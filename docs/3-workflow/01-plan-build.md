# Plan vs Build: планирование и выполнение

> 💡 **Коротко**: Plan Agent только читает и анализирует, Build Agent читает и выполняет. Переключение — <kbd>Tab</kbd>.

## 📝 Конспект урока

Ключевые идеи урока в сжатом виде:

<img src="/images/3-workflow/plan-build-notes.mini.jpeg"
     alt="Шпаргалка урока: Plan vs Build"
     data-zoom-src="/images/3-workflow/plan-build-notes.jpeg" />

<details>
<summary>📝 Текстовая версия шпаргалки</summary>

1. Plan Agent — только чтение, спрашивает разрешение перед изменениями кода.
2. Build Agent — чтение, запись и выполнение, все инструменты доступны.
3. Primary-агенты переключаются клавишей Tab (Plan ↔ Build); суб-агент вызывается через @.
4. Права: edit/bash — ask в Plan, allow в Build; read — allow в обоих.
5. Plan — для анализа структуры, планирования, код-ревью, изучения чужого кода.
6. Build — новые фичи, фикс багов, рефакторинг, создание и изменение файлов.
7. Рекомендуемый workflow: сначала Plan для анализа → потом Build для выполнения.
8. Ловушки: AI не меняет файл — вы в Plan, переключитесь в Build; нежелательные правки — /undo; Plan перестал спрашивать — переключение сбрасывает права.

</details>

## Основная идея

### Что такое Plan и Build

Plan и Build — два встроенных в OpenCode **Primary Agents** (главных помощника).

- **Primary Agent**: главный помощник, с которым вы общаетесь напрямую, переключение — <kbd>Tab</kbd>
- **Subagent**: экспертный помощник, которого вызывает Primary Agent, упоминание через `@` (подробности — [3.2 Знакомство с Agent](./02-agents))

В OpenCode по умолчанию два Primary Agents:

| Agent | Тип | Описание |
|-------|------|------|
| **Build** | Primary | Помощник по умолчанию, доступны все инструменты, подходит для разработки |
| **Plan** | Primary | Ограниченный помощник, спрашивает разрешения, подходит для анализа и планирования |

### Система разрешений

Plan Agent защищает ваш код механизмом **изоляции разрешений** — ему запрещено редактировать исходный код, разрешено только править файлы планов:

| Разрешение | Plan Agent | Build Agent |
|------|-----------|------------|
| `edit` (запись/изменение файлов) | **deny** (исходники запрещены, разрешены только файлы планов) | allow |
| `bash` (выполнение команд) | allow | allow |
| `read`, `grep`, `glob` и др. | allow | allow |

> ⚠️ **Обратите внимание**: Plan Agent может редактировать файлы планов `.opencode/plans/*.md`, но не исходный код проекта.

### Когда использовать Plan

- Разобрать структуру кода, но **ничего не менять**
- Попросить AI спланировать и спроектировать
- Ревью кода
- Разобраться в незнакомой кодовой базе

### Когда использовать Build

- Попросить AI написать новую функцию
- Попросить AI исправить баг
- Попросить AI отрефакторить код
- Попросить AI создать/изменить файлы

### Шпаргалка по выбору режима

| Ваша задача | Рекомендуемый режим | Почему |
|---------|---------|------|
| Новая функция | Build | Сразу к делу, высокая скорость |
| Простой баг | Build | Масштаб последствий понятен |
| Рефакторинг ядра | Сначала Plan, потом Build | Сначала оценить влияние, потом действовать |
| Изучение новой кодовой базы | Plan | Безопасное исследование без случайных правок |
| Влияние изменений неясно | Plan | Сначала анализ, потом решение |
| Быстрый прототип | Build | Скорость итераций важнее |
| Командная задача | Сначала Plan, потом Build | План можно проверить, выполнение — отследить |
| Ревью кода | Plan | Только чтение и анализ, без изменений |

**Простое правило**: не уверены → сначала Plan; уверены → сразу Build

## Доступные инструменты
<AdInArticle />

Plan Agent может читать, искать и выполнять shell-команды, но по умолчанию не правит исходники; Build Agent доступны все инструменты:

### Инструменты чтения (доступны и Plan, и Build)

| Инструмент | Описание |
|------|------|
| `read` | Чтение содержимого файлов |
| `grep` | Поиск по содержимому файлов |
| `glob` | Поиск файлов по шаблону |
| `list` | Список содержимого каталога |
| `webfetch` | Получение содержимого веб-страниц |

### Инструменты записи (по умолчанию только Build)

| Инструмент | Описание |
|------|------|
| `write` | Создание новых файлов |
| `edit` | Изменение существующих файлов |

### Инструменты выполнения (доступны и Plan, и Build)

| Инструмент | Описание |
|------|------|
| `bash` | Выполнение shell-команд; разрешение конкретных команд всё равно регулируется правилами |

## Настройка (необязательно)

Конфигурации по умолчанию хватает для повседневной работы. Если нужно настроить поведение Agent, это делается в `opencode.jsonc`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "agent": {
    // Настройка Build Agent
    "build": {
      "mode": "primary",
      "model": "anthropic/claude-opus-4-5-thinking",
      "temperature": 0.3,
      "permission": {
        "edit": "allow",
        "bash": "allow"
      }
    },
    // Настройка Plan Agent
    "plan": {
      "mode": "primary",
      "model": "anthropic/claude-opus-4-5-thinking",
      "temperature": 0.1,
      "permission": {
        "edit": {
          "*": "deny",                    // Запретить правку всего исходного кода
          ".opencode/plans/*.md": "allow" // Разрешить только файлы планов
        },
        "bash": "allow"
      }
    }
  }
}
```

**Описание параметров**:

- `model`: используемая модель, формат `provider/model-id`
- `temperature`: число, управляющее случайностью; реальный диапазон задают модель и провайдер, обычно чем ниже значение, тем сосредоточеннее ответы
- `permission.edit`: права на редактирование файлов
  - `"allow"`: разрешить
  - `"deny"`: запретить
  - Можно задавать правила для путей, например `{ "*": "deny", ".opencode/plans/*.md": "allow" }`
- `permission.bash`: права на выполнение команд (`allow`/`deny`)

> 💡 **Подсказка**: конфиг поддерживает формат JSONC — можно добавлять `//`-комментарии.

## Повторите за мной

### Шаг 1: проверьте текущий Agent

**Зачем**
Сначала посмотрите, какой Agent используется прямо сейчас.

Справа в строке состояния отображается `Plan` или `Build`.

### Шаг 2: переключитесь на Plan Agent

**Зачем**
Готовимся к анализу только для чтения.

Нажимайте <kbd>Tab</kbd>, пока в строке состояния не появится `Plan`.

### Шаг 3: проанализируйте код через Plan Agent

**Зачем**
Попробуйте анализ только для чтения — AI не изменит ни одного файла.

Введите:

```
@src/main.ts разбери структуру этого файла, перечисли все функции и их назначение
```

**Вы должны увидеть**: AI прочитает файл инструментом `read` и разберёт структуру. Plan Agent запрещено править исходники, поэтому файл останется нетронутым.

### Шаг 4: переключитесь на Build Agent

**Зачем**
Готовимся дать AI править код.

Нажмите <kbd>Tab</kbd> — в строке состояния появится `Build`.

### Шаг 5: отрефакторите код через Build Agent

**Зачем**
Попробуйте режим чтения и записи — AI реально изменит файл.

Введите:

```
Добавь в @src/main.ts подробные JSDoc-комментарии
```

**Вы должны увидеть**: AI изменит файл инструментом `edit` и добавит комментарии. Изменения можно проверить и принять.

### Шаг 6: отмените изменения (необязательно)

**Зачем**
Если результат не понравился — откатите.

```
/undo
```

`/undo` возвращает к предыдущему сообщению пользователя и откатывает связанные с ним файловые патчи; если откатили лишнего, `/redo` восстановит сессию и файлы. Восстановление файлов зависит от снапшотов: `snapshot: false` отключает только undo/redo для файлов, но не undo/redo сообщений сессии.

## Приём: пусть AI отслеживает прогресс

Для сложных задач прямо попросите AI вести прогресс через TODO:

| Что вы говорите | Что сделает AI |
|---------|------------|
| «Веди прогресс через TODO» | Создаст список задач и будет обновлять статусы |
| «Выполняй по шагам» | Сам разобьёт задачу и отметит выполнение |
| «Какой сейчас прогресс?» | Сообщит выполненное / в работе / ожидающее |

**Пример диалога**:

```
Вы: Отрефактори модуль аутентификации пользователей, веди прогресс через TODO

AI: Хорошо, сначала создам список задач:
    ✅ 1. Разобрать существующую структуру кода
    🔄 2. Спроектировать новый процесс аутентификации
    ⏳ 3. Переписать логику аутентификации
    ⏳ 4. Обновить тест-кейсы
    ⏳ 5. Проверить функциональность

    Начинаю с первого пункта...

Вы: Какой прогресс?

AI: Сейчас посмотрю...
    ✅ 1. Разобрать существующую структуру кода (готово)
    ✅ 2. Спроектировать новый процесс аутентификации (готово)
    🔄 3. Переписать логику аутентификации (в работе, примерно 5 минут)
    ⏳ 4. Обновить тест-кейсы
    ⏳ 5. Проверить функциональность
```

**Когда использовать приём**:

- В задаче больше 3 шагов
- Вы можете отойти и захотите узнать прогресс по возвращении
- Хотите, чтобы AI действовал системно и ничего не пропускал

> 💡 **Как это работает**: AI ведёт и читает список дел инструментом `todowrite`. Вам не нужно вникать в детали — достаточно сказать в промпте «веди через TODO».

## Типичные проблемы

| Симптом | Причина | Решение |
|-----|-----|-----|
| Хотели, чтобы AI правил файл, но он не правит | Вероятно, активен Plan Agent — ему запрещено править исходники | Переключитесь на Build через Tab |
| AI изменил файл, который не должен был | Активен Build Agent с правами `allow` | Откатите через `/undo`, в следующий раз сначала проанализируйте через Plan |
| Plan Agent не правит исходники | Так задумано: Plan по умолчанию правит только проектные или глобальные файлы планов | Переключитесь на Build для изменений |

## Продвинутые возможности (достаточно знать)

### temperature: управление случайностью

Plan Agent обычно использует низкий `temperature` (например, 0.1) — ответы сосредоточеннее и определённее; Build Agent — средний (например, 0.3), баланс между точностью и креативностью.

### steps: лимит автоитераций

Целым положительным числом задаётся максимальное число автоитераций Agent. По достижении лимита Agent вместо действий выводит финальный текстовый ответ. Одна итерация может включать несколько вызовов инструментов, так что это не строгий лимит числа вызовов.

```jsonc
{
  "agent": {
    "plan": {
      "steps": 5  // Максимум 5 автоитераций
    }
  }
}
```

### Свои горячие клавиши

По умолчанию Agent переключается через <kbd>Tab</kbd>, но в отдельном `tui.jsonc` можно поменять привязку `agent_cycle`:

```jsonc title="tui.jsonc"
{
  "$schema": "https://opencode.ai/tui.json",
  "keybinds": {
    "agent_cycle": "tab",           // Следующий Agent (по умолчанию)
    "agent_cycle_reverse": "shift+tab"  // Предыдущий Agent (по умолчанию)
  }
}
```

Начиная с v1.17.0 поля `theme`, `keybinds` и старое поле `tui` больше не живут в главном `opencode.json`/`opencode.jsonc`. При старте TUI переносит эти старые поля по каталогам конфигурации: если целевой `tui.json` уже существует — пропускает; после успешной записи backup'ит главный конфиг и удаляет из него старые поля. Отдельный конфиг TUI продолжает загружаться по уровням «глобальный — пользовательский — проектный — `.opencode`», можно также напрямую использовать `tui.jsonc`.

### plan_exit: запрос Plan Agent на начало выполнения

::: warning ⚠️ Экспериментальная функция
`plan_exit` пока **экспериментален** и требует одновременного выполнения условий:

1. Включён экспериментальный режим: `OPENCODE_EXPERIMENTAL=true` или `OPENCODE_EXPERIMENTAL_PLAN_MODE=true`
2. Используется CLI-клиент: OpenCode запущен в терминале (не Web/IDE-интеграция)

В будущих версиях функцию могут открыть официально — тогда урок обновится.
:::

Для входа в Plan Agent нажмите <kbd>Tab</kbd> вручную (или свою клавишу переключения Agent). В целевой версии нет инструмента `plan_enter`. Когда Plan Agent закончит планирование, он может вызвать `plan_exit` с запросом возврата в Build:

| Инструмент | Действие | Доступен |
|------|------|-----------|
| `plan_exit` | Выйти из Plan и вернуться в Build | Доступен Plan Agent |

**Рабочий процесс**:

```
Вы: [переключаетесь на Plan Agent через Tab]
    → AI анализирует код в режиме Plan
    → Создаёт файл плана .opencode/plans/xxx.md

Вы: План выглядит хорошо, приступай к реализации

AI: [вызывает инструмент plan_exit]
    → Всплывает подтверждение: переключиться в режим Build?
    → Вы выбираете Yes
    → AI выполняет изменения в режиме Build
```

**В режиме Plan AI по умолчанию правит только проектные или глобальные файлы планов** и не трогает исходники. Так «планирование» безопасно отделено от «выполнения».

### Где хранятся файлы планов

В режиме Plan созданные AI файлы планов сохраняются сюда:

| Уровень | Путь | Описание |
|------|------|------|
| Проектный | `.opencode/plans/<created>-<slug>.md` | В каталоге проекта, следует за проектом |
| Глобальный | `<Global.Path.data>/plans/<created>-<slug>.md` | В глобальном каталоге данных OpenCode, общий для проектов |

> `created` — 13-значная метка времени в миллисекундах, `slug` — URL-дружественный формат заголовка плана. Например: `1736854321000-refactor-auth.md`. Обычный каталог данных в Linux — `~/.local/share/opencode`, но реальный путь зависит от платформы и переменных XDG; точный путь `data` покажет `opencode debug paths`.

::: tip Как определяется место хранения
- **В проекте есть Git (или другой VCS)** → сохраняется на уровне проекта, в `.opencode/plans/`
- **В проекте нет VCS** → сохраняется в `<Global.Path.data>/plans/`
:::

Просмотр файлов планов:

```bash
# Проектные планы
cat .opencode/plans/*.md

# Глобальный каталог данных; допишите plans/ к пути data из вывода
opencode debug paths
```

> 💡 В эти детали углубитесь на продвинутом уровне, сейчас достаточно знать о них.
