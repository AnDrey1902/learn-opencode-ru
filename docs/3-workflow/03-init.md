## Основная идея
<AdInArticle />

### Зачем нужна инициализация

Без инициализации в каждом диалоге приходится рассказывать AI:
- что это за проект
- какой технологический стек
- какой стиль кода
- какие особые нормы

После инициализации всё это лежит в файле `AGENTS.md`, и AI читает его автоматически.

### Где лежит файл правил

OpenCode ищет файлы правил в таком порядке:

| Расположение | Область действия |
|-----|---------|
| `корень-проекта/AGENTS.md` | Текущий проект |
| `корень-проекта/CLAUDE.md` | Совместимость с Claude Code |
| `~/.config/opencode/AGENTS.md` | Глобально (все проекты) |
| `~/.claude/CLAUDE.md` | Глобально (совместимость с Claude Code) |
| `$OPENCODE_CONFIG_DIR/AGENTS.md` | Глобально (каталог через переменную окружения) |

::: tip 💡 Как работает поиск
OpenCode идёт от текущего каталога вверх до корня рабочего каталога (worktree) — используется первый найденный файл правил. Глобальные правила объединяются с проектными.
:::

## Повторите за мной

### Шаг 1: перейдите в каталог проекта

**Зачем**
Инициализация в корне проекта — созданные правила будут именно для него.

```bash
cd ~/your-project
opencode
```

### Шаг 2: выполните инициализацию

**Зачем**
Пусть AI проанализирует проект и создаст файл правил.

Введите:

```
/init
```

**Вы должны увидеть**: AI начнёт разбирать структуру проекта, стек и стиль кода

#### Продвинутое использование

> Горячей клавиши по умолчанию нет, вводите `/init` вручную

**Запуск с параметрами**:

```
/init обрати особое внимание на типобезопасность TypeScript и обработку ошибок
```

Команда `/init`:
- сканирует файлы и структуру каталогов проекта
- определяет команды сборки, тестов и линта
- анализирует стиль кода и соглашения об именах
- если находит правила Cursor (`.cursor/rules/`, `.cursorrules`) или Copilot (`.github/copilot-instructions.md`) — автоматически объединяет их
- если `AGENTS.md` уже существует — улучшает его, а не перезаписывает
- генерирует файл правил примерно на 150 строк — сжато и по делу

### Шаг 3: проверьте созданные правила

**Зачем**
Созданные AI правила могут быть неточными — их проверяет человек.

AI создаст файл `AGENTS.md` примерно такого содержания:

```markdown
# SST v3 Monorepo Project

This is an SST v3 monorepo with TypeScript. The project uses bun workspaces for package management.

## Project Structure

- `packages/` - Contains all workspace packages (functions, core, web, etc.)
- `infra/` - Infrastructure definitions split by service (storage.ts, api.ts, web.ts)
- `sst.config.ts` - Main SST configuration with dynamic imports

## Code Standards

- Use TypeScript with strict mode enabled
- Shared code goes in `packages/core/` with proper exports configuration
- Functions go in `packages/functions/`
- Infrastructure should be split into logical files in `infra/`

## Monorepo Conventions

- Import shared modules using workspace names: `@my-app/core/example`
```

Проверьте, всё ли верно. Полный пример AGENTS.md — в официальной документации: https://github.com/anomalyco/opencode/blob/dev/packages/web/src/content/docs/rules.mdx

### Продвинутое: больше правил через opencode.json

Помимо `AGENTS.md` в конфигурации можно указать дополнительные файлы правил:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "instructions": [
    "CONTRIBUTING.md",
    "docs/guidelines.md",
    "packages/*/AGENTS.md"
  ]
}
```

**Возможности `instructions`**:

- **Относительные пути**: поиск от каталога проекта к корню рабочего каталога, glob-шаблоны поддерживаются
- **Glob-шаблоны**: например, `packages/*/AGENTS.md` покрывает несколько файлов
- **Абсолютные пути**: прямой полный путь
- **URL**: загрузка удалённых правил по `https://` или `http://` (тайм-аут 5 секунд)
- **Домашний каталог**: пути с `~/` раскрываются автоматически

Пример:

```json title="opencode.json"
{
  "instructions": [
    "~/team-rules/typescript.md",
    "https://example.com/company-coding-standards.md",
    "docs/**/*.md"
  ]
}
```

Все файлы из `instructions` объединяются с `AGENTS.md`.

### Шаг 4: поправьте правила (при необходимости)

**Зачем**
Добавить нормы, которых AI не заметил, или исправить ошибки.

Откройте `AGENTS.md` в редакторе и допишите своё:

```markdown
## Additional Rules
- Always use Russian comments
- Prefer async/await over callbacks
- Error messages should be user-friendly
```

### Шаг 5: проверьте, что правила работают

**Зачем**
Убедиться, что AI правда читает ваши правила.

Введите:

```
Какой технологический стек используется в этом проекте?
```

**Вы должны увидеть**: ответ AI должен совпадать с тем, что записано в AGENTS.md

## Загрузка и объединение файлов правил

### Порядок загрузки

OpenCode загружает правила так:

1. **Правила проекта**: от текущего каталога вверх до корня рабочего каталога ищутся `AGENTS.md` или `CLAUDE.md`
2. **Глобальные правила**: загружаются `~/.config/opencode/AGENTS.md` или `~/.claude/CLAUDE.md`
3. **Пользовательский каталог конфигурации**: если задана переменная `OPENCODE_CONFIG_DIR` — `AGENTS.md` из него
4. **Правила из конфигурации**: все файлы из `instructions` в `opencode.json`

::: tip 💡 Тайм-аут URL
`instructions` умеет грузить файлы правил по удалённым URL, но с ограничением в 5 секунд.
:::

### Механизм объединения

Все найденные файлы правил объединяются и вместе отдаются AI. Это значит, что:

- общие нормы можно держать в правилах уровня проекта
- личные предпочтения — в глобальных правилах
- в `instructions` — ссылаться на общие командные стандарты
- правила не перезаписывают друг друга — действуют все сразу

## Командная работа

### Коммитьте AGENTS.md в Git

::: tip 💡 Командная работа
Коммитьте проектный `AGENTS.md` в систему контроля версий, чтобы вся команда пользовалась одинаковыми нормами проекта.
:::

### Обработка монорепозиториев

Для монорепозиториев рекомендуется через `instructions` единообразно подгружать правила всех подпроектов:

```json title="opencode.json"
{
  "instructions": ["packages/*/AGENTS.md"]
}
```

Так у каждого подпроекта свои правила, но загружаются они централизованно.

## Продвинутый приём: ссылки на внешние файлы в AGENTS.md

Хотя OpenCode не раскрывает ссылки на файлы автоматически, в `AGENTS.md` можно явно велеть AI читать внешние файлы:

```markdown title="AGENTS.md"
# Правила проекта

## Ссылки на внешние файлы

Когда встречаешь ссылку на файл (например, `@docs/xxx.md`), подгружай её инструментом Read по мере необходимости:
- Не грузи все ссылки заранее, только лениво и по потребности
- Подгруженное содержимое — обязательные к соблюдению инструкции
- При необходимости раскрывай ссылки рекурсивно

## Технические нормы

Стиль TypeScript: @docs/typescript-guidelines.md
Паттерны React-компонентов: @docs/react-patterns.md
Дизайн REST API: @docs/api-standards.md
Стратегия тестов: @test/testing-guidelines.md
```

Такой подход даёт:
- модульные переиспользуемые файлы правил
- общие правила между проектами через симлинки или Git submodule
- лаконичный `AGENTS.md` со ссылками на подробные гайды
- загрузку нужных правил только по потребности

## Типичные проблемы

| Симптом | Причина | Решение |
|-----|-----|-----|
| AI не соблюдает правила | Запустились не в каталоге проекта | Убедитесь, что AGENTS.md лежит в текущем каталоге |
| Содержимое правил неверное | AI ошибся при анализе | Отредактируйте AGENTS.md вручную |
| Хотите глобальные правила | Подходят для каждого проекта | Положите в `~/.config/opencode/AGENTS.md` или `~/.claude/CLAUDE.md` |
| Правила не применились | Ошибка в пути конфигурации | Проверьте пути `instructions` в `opencode.json` |
| Общие правила для нескольких проектов | Копировать файл неудобно | Используйте `instructions` или симлинки |
