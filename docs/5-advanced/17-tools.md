# Встроенные инструменты

## Конспект урока

Инструменты позволяют LLM выполнять действия в вашей кодовой базе. В OpenCode встроен набор инструментов, а расширить их можно через [свои инструменты](13-custom-tools.md) или [MCP-серверы](07a-mcp-basics.md).

По умолчанию все инструменты включены и работают без разрешений. Но поведением прав можно управлять через конфигурацию [прав](05-permissions.md).

---

## Условная активация

Отдельные инструменты включаются лишь при особых условиях:

| Инструмент | Условие активации |
|------|---------|
| `websearch` | Хостед-модель OpenCode Zen или заданный `OPENCODE_ENABLE_EXA=true` |
| `codesearch` | Хостед-модель OpenCode Zen или заданный `OPENCODE_ENABLE_EXA=true` |
| `batch` | Настроенный `experimental.batch_tool: true` |
| `lsp` | Включённый флаг `OPENCODE_EXPERIMENTAL_LSP_TOOL` |
| `plan_enter` / `plan_exit` | Режим CLI + флаг экспериментального режима планирования |

::: tip Как включить
Настройте в `opencode.json`:

```json
{
  "experimental": {
    "batch_tool": true
  }
}
```

Или задайте переменные окружения:

```bash
export OPENCODE_ENABLE_EXA=true
export OPENCODE_EXPERIMENTAL_LSP_TOOL=1
```
:::

---

## Конфигурация

Инструменты настраиваются глобально или для отдельных агентов. Настройки агентов перекрывают глобальные.

По умолчанию все инструменты включены (`true`). Чтобы отключить инструмент — задайте `false`.

### Глобальная настройка

Глобально отключайте или включайте инструменты опцией tools:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "tools": {
    "write": false,
    "bash": false,
    "webfetch": true
  }
}
```

### Настройка для отдельных агентов

В определении агента опцией tools перекрывайте глобальные настройки:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "tools": {
    "write": true,
    "bash": true
  },
  "agent": {
    "plan": {
      "tools": {
        "write": false,
        "bash": false
      }
    }
  }
}
```

## Список встроенных инструментов

### bash

Выполнение shell-команд в окружении проекта.

```json
{
  "tools": {
    "bash": true
  }
}
```

Позволяет LLM выполнять терминальные команды вроде npm install и git status.

::: details Параметры вызова для AI

| Параметр | Тип | Обязат. | Описание |
|------|------|------|------|
| `command` | string | ✅ | Команда для выполнения |
| `description` | string | ✅ | Описание команды (5–10 слов) |
| `workdir` | string | ❌ | Рабочий каталог, по умолчанию корень проекта |
| `timeout` | number | ❌ | Тайм-аут (миллисекунды), по умолчанию 120000 (2 минуты) |

**Механизмы безопасности**:
- Разбор синтаксиса команд через tree-sitter-bash
- Детект команд `cd`, `rm`, `cp`, `mv`, `mkdir`, `touch`, `chmod`, `chown`, `cat` и др.
- При затрагивании каталогов вне проекта запрашивается подтверждение права `external_directory`
- Вывод больше 2000 строк или 50KB обрезается автоматически, полный вывод сохраняется в файл

:::

### edit

Изменение существующих файлов точной заменой строк.

```json
{
  "tools": {
    "edit": true
  }
}
```

::: details Параметры вызова для AI

| Параметр | Тип | Обязат. | Описание |
|------|------|------|------|
| `filePath` | string | ✅ | Абсолютный путь к файлу |
| `oldString` | string | ✅ | Исходный заменяемый текст |
| `newString` | string | ✅ | Текст замены (обязан отличаться от oldString) |
| `replaceAll` | boolean | ❌ | Заменить ли все совпадения (по умолчанию false) |

**Умное сопоставление**: у edit 9 уровней стратегий сопоставления (SimpleReplacer → LineTrimmedReplacer → BlockAnchorReplacer → WhitespaceNormalizedReplacer → IndentationFlexibleReplacer → EscapeNormalizedReplacer → TrimmedBoundaryReplacer → ContextAwareReplacer → MultiOccurrenceReplacer) — от строгих к мягким по очереди.

**Предусловие**: сначала прочитайте файл через read, иначе будет ошибка.

**Проверка после записи**: автоматически запускается LSP-диагностика с отчётом о синтаксических ошибках и ошибках типов.

:::

### write

Создание новых файлов или перезапись существующих.

```json
{
  "tools": {
    "write": true
  }
}
```

::: details Параметры вызова для AI

| Параметр | Тип | Обязат. | Описание |
|------|------|------|------|
| `filePath` | string | ✅ | Абсолютный путь к файлу (обязательно абсолютный) |
| `content` | string | ✅ | Записываемое содержимое |

**Предусловие**: существующий файл сначала прочитайте через read, иначе будет ошибка.

**Проверка после записи**: автоматически запускается LSP-диагностика с отчётом об ошибках текущего и затронутых файлов (максимум 5 файлов).

**Предпросмотр diff**: перед записью создаётся diff и запрашивается подтверждение правами.

:::

### read

Чтение содержимого файлов и каталогов кодовой базы.

```json
{
  "tools": {
    "read": true
  }
}
```

::: details Параметры вызова для AI

| Параметр | Тип | Обязат. | Описание |
|------|------|------|------|
| `filePath` | string | ✅ | Абсолютный путь к файлу или каталогу |
| `offset` | number | ❌ | С какой строки или записи читать (**нумерация с 1**) |
| `limit` | number | ❌ | Сколько строк или записей максимум (по умолчанию 2000) |

**Лимиты чтения файлов**:
- По умолчанию читаются 2000 строк (`DEFAULT_READ_LIMIT`)
- Строки длиннее 2000 символов обрезаются (`MAX_LINE_LENGTH`)
- Общий лимит вывода 50KB (`MAX_BYTES`)

**Чтение каталогов** (v1.1.60+):
- Чтение каталога возвращает список записей, подкаталоги с `/` на конце
- Записи сортируются по алфавиту
- Поддерживаются пагинация `offset` и `limit` (как при чтении файлов, нумерация с 1)

**Пример вывода чтения каталога**:

```xml
<path>/Users/xxx/project/src</path>
<type>directory</type>
<entries>
components/
utils/
index.ts
(3 entries)
</entries>
```

**Особые файлы**: поддерживается чтение картинок (PNG, JPG, GIF, кроме SVG) и PDF — конвертируются в base64-вложения. Двоичные файлы (.zip, .exe и т. д.) вызывают ошибку.

**Умное исправление**: несуществующий файл — поиск похожих имён в том же каталоге с подсказкой.

:::

### grep

Поиск по содержимому файлов регулярными выражениями.

```json
{
  "tools": {
    "grep": true
  }
}
```

::: details Параметры вызова для AI

| Параметр | Тип | Обязат. | Описание |
|------|------|------|------|
| `pattern` | string | ✅ | Шаблон регулярного выражения |
| `path` | string | ❌ | Путь поиска, по умолчанию текущий каталог |
| `include` | string | ❌ | Фильтр файлов, например `"*.ts"` |

**Лимиты результатов**:
- Максимум 100 совпадений, остальное обрезается
- Строки длиннее 2000 символов обрезаются

:::

### glob

Поиск файлов по шаблонам совпадения.

```json
{
  "tools": {
    "glob": true
  }
}
```

::: details Синтаксис шаблонов glob

| Шаблон | Описание | Пример |
|------|------|------|
| `*` | Любые символы (кроме `/`) | `*.ts` |
| `**` | Любая глубина каталогов | `src/**/*.ts` |
| `?` | Ровно один символ | `file?.ts` |
| `[abc]` | Указанные символы | `file[123].ts` |
| `{a,b}` | Несколько шаблонов | `*.{ts,tsx}` |

**Лимит результатов**: максимум 100 файлов, остальное обрезается.

:::

### question

Позволяет AI задавать вам вопросы по ходу задач.

```json
{
  "tools": {
    "question": true
  }
}
```

Инструмент позволяет AI:

- собирать ваши предпочтения и требования
- прояснять туманные инструкции
- получать решения о выборе реализации
- предлагать несколько направлений на выбор

Каждый вопрос включает заголовок, текст вопроса и список вариантов. Можно выбирать из вариантов или вводить свой ответ. При нескольких вопросах между ними можно перемещаться до отправки.

**Сценарии использования**:

```
Вы: отрефактори этот модуль

AI: Вижу несколько способов рефакторинга. Какой вам ближе?
    ○ Выделить в отдельные функции
    ○ Разбить на несколько классов
    ○ Структуру не трогать, только улучшить имена
    [Ввести свой ответ]
```

**Обратите внимание**: инструменты `todowrite` и `todoread` в подагентах по умолчанию отключены, а инструмент `question` по умолчанию включён.

### webfetch

Получение содержимого веб-страниц: HTML, Markdown, чистый текст и картинки.

```json
{
  "tools": {
    "webfetch": true
  }
}
```

::: details Параметры вызова для AI

| Параметр | Тип | Обязат. | Описание |
|------|------|------|------|
| `url` | string | ✅ | Забираемый URL (строго с http:// или https:// в начале) |
| `format` | string | ❌ | Формат ответа: `markdown` (по умолчанию), `text`, `html` |
| `timeout` | number | ❌ | Тайм-аут в секундах (максимум 120 секунд, по умолчанию 30 секунд) |

**Поддержка картинок** (v1.1.62+):
- URL картинок (image/*) автоматически возвращаются base64-вложением
- SVG (image/svg+xml) и FastBidSheet (image/vnd.fastbidsheet) не поддерживаются

**Конвертация HTML**:
- `format: "markdown"` — HTML автоматически в Markdown
- `format: "text"` — чистый текст, теги script/style вырезаются
- `format: "html"` — исходный HTML как есть

**Лимит**: ограничение размера ответа 5MB.

:::

### websearch (экспериментальный)

```json
{
  "tools": {
    "websearch": true
  }
}
```

> Нужна переменная окружения OPENCODE_ENABLE_EXA=true или хостед-модель OpenCode Zen.

### codesearch (экспериментальный)

Поиск по кодовым базам и онлайн-ресурсам: релевантные API, библиотеки, документация.

```json
{
  "tools": {
    "codesearch": true
  }
}
```

> Нужна переменная окружения OPENCODE_ENABLE_EXA=true или хостед-модель OpenCode Zen.

::: details Параметры вызова для AI

| Параметр | Тип | По умолчанию | Описание |
|------|------|--------|------|
| `query` | string | Обязательный | Поисковый запрос, например `"React useState hook examples"` |
| `tokensNum` | number | 2000+ | Число возвращаемых токенов (1000–2000+) |

**Рекомендации по выбору tokensNum**:

| Значение | Сценарии |
|-----|---------|
| 1000–2000 | Точные запросы, нужны короткие примеры |
| 2000+ | Обычные запросы (по умолчанию) |
| 10000–20000 | Нужна полная документация |
| 30000–2000+ | Нужны исчерпывающие справочные материалы |

**Прочие лимиты**: тайм-аут запроса 30 секунд.

:::

### batch (экспериментальный)

Параллельное выполнение нескольких вызовов инструментов — меньше ожидания. Когда AI читает несколько файлов, выполняет несколько поисковых команд и прочих независимых операций, batch выполняет всё разом — в 2–5 раз быстрее поштучного выполнения.

**Как включить**:

```json
{
  "experimental": {
    "batch_tool": true
  }
}
```

::: details Параметры вызова для AI

**Структура параметров**:

```typescript
{
  tool_calls: [
    { tool: "имя-инструмента", parameters: { /* параметры */ } },
    { tool: "имя-инструмента", parameters: { /* параметры */ } },
    // ... максимум 25 штук
  ]
}
```

**Пример реального вызова**:

```json
[
  {"tool": "read", "parameters": {"filePath": "src/index.ts", "limit": 350}},
  {"tool": "grep", "parameters": {"pattern": "Session\\.updatePart", "include": "src/**/*.ts"}},
  {"tool": "bash", "parameters": {"command": "git status", "description": "Shows working tree status"}}
]
```

**Формат возврата**:

```json
{
  "title": "Batch execution (3/3 successful)",
  "output": "All 3 tools executed successfully.\n\nKeep using the batch tool for optimal performance in your next response!",
  "metadata": {
    "totalCalls": 3,
    "successful": 3,
    "failed": 0,
    "tools": ["read", "grep", "bash"],
    "details": [
      {"tool": "read", "success": true},
      {"tool": "grep", "success": true},
      {"tool": "bash", "success": true}
    ]
  }
}
```

:::

**Подходящие сценарии для batch**:

| Сценарий | Описание |
|------|------|
| Чтение нескольких файлов за раз | Сразу package.json, tsconfig.json, .eslintrc.json |
| Комбинации grep + glob + read | Сначала поиск, потом чтение, независимые части — параллельно |
| Несколько bash-команд | Одновременно git status, npm test и т. д. |
| Правки в нескольких местах | Одновременные правки разных мест нескольких файлов |

**Неподходящие сценарии для batch**:

| Сценарий | Причина |
|------|------|
| Зависимые друг от друга операции | Например, сначала создать файл, потом прочитать — порядок не гарантируется |
| Последовательные операции с состоянием | Например, сначала git add, потом git commit |

**Лимиты**:

| Пункт | Значение | Описание |
|--------|-----|------|
| Максимум вызовов | 25 | Лишние вызовы отбрасываются с ошибкой |
| Запрет вложенности | batch | Вызывать batch внутри batch нельзя |
| Внешние инструменты | Не поддерживаются | MCP-инструменты через batch не выполняются — вызывайте отдельно |
| Частичные ошибки | Не мешают остальным | Ошибка одного вызова не прерывает параллельные |

## Внутренняя реализация

Инструменты grep, glob и list внутри используют ripgrep. По умолчанию ripgrep уважает шаблоны .gitignore — файлы и каталоги из .gitignore исключаются из поиска и списков.

### Шаблоны игнора

Чтобы включить обычно игнорируемые файлы, создайте в корне проекта файл .ignore:

```text
!node_modules/
!dist/
!build/
```

## Приёмы использования поисковых инструментов

Эти приёмы помогут писать точные промпты, чтобы AI эффективнее находил целевой код.

### Чем различаются три поисковых инструмента

| Сценарий | Какой инструмент возьмёт AI |
|------|---------------|
| Найти примеры использования некого API | codesearch (онлайн-поиск документации и примеров) |
| Искать конкретную строку в локальном коде | grep (совпадения regex по содержимому файлов) |
| Найти файл по имени | glob (совпадение шаблонов с путями файлов) |

### Комбинированное использование

Частые комбинированные стратегии AI:

1. **Сначала glob находит файлы, потом grep ищет содержимое**
   ```
   Вы: найди во всех TypeScript-файлах места определения interface User
   AI: сначала glob ищет *.ts-файлы, затем grep ищет "interface User"
   ```
2. **codesearch ищет примеры, grep — локальную реализацию**
   ```
   Вы: хочу понять, как правильно чистить useEffect в React, и проверить, верно ли у нас в проекте
   AI: сначала codesearch смотрит документацию, затем grep ищет useEffect локально
   ```

### Про лимиты результатов

У инструментов **grep** и **glob** лимит 100 записей. Если AI говорит «результаты обрезаны», можно:

- попросить AI конкретизировать условия поиска
- указать меньший диапазон каталогов
- использовать более точные регулярные выражения

У **codesearch** лимита записей нет, но есть лимит 30 секунд на тайм-аут.
