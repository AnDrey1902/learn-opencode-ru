## Дизайн интерфейсов инструментов (ACI)

> «Проектированию человеко-машинных интерфейсов (HCI) уделяют столько усилий — столько же вкладывайте в проектирование интерфейсов "агент-компьютер" (ACI)». — Anthropic

ACI (Agent-Computer Interface) — интерфейс взаимодействия Agent с инструментами. Хороший дизайн — Agent эффективно выполняет задачи; плохой — Agent часто ошибается.

### Главные принципы

#### 1. Оставляйте модели место для мышления

Не проектируйте форматы, загоняющие LLM «в угол».

```markdown
<!-- ❌ Плохо: сначала нужно знать число строк -->
Выведите:
- Строки 1–5: импорты
- Строки 6–20: определения функций
- ...

<!-- ✅ Хорошо: описание естественным языком -->
Организуйте код по структуре:
1. Импорты
2. Определение констант
3. Определение функций
4. Главная логика
```

#### 2. Формат ближе к естественному языку

Модель легче генерирует форматы, которых навидалась в интернете.

```markdown
<!-- ❌ Плохо: нужно точное JSON-экранирование -->
Формат вывода:{"code": "function foo() {\n  return \"bar\";\n}"}

<!-- ✅ Хорошо: Markdown-блоки кода (модель видела их бессчётно) -->
Формат вывода:
```javascript
function foo() {
  return "bar";
}
```
```

#### 3. Описания — как отличные docstring

Описание инструмента должно включать:
- **Что делает**: назначение инструмента
- **Пример использования**: типовое применение
- **Граничные случаи**: когда не применять
- **Формат ввода**: требования к параметрам

### Практический опыт Anthropic

> «Создавая SWE-bench Agent, мы потратили на оптимизацию инструментов больше времени, чем на оптимизацию общего промпта».

Они заметили: модели ошибаются с относительными путями (когда Agent уходит из корня). Решение: требовать **абсолютные пути** — модели выполняют идеально.

**Вывод**: если Agent часто ошибается на неком инструменте — проблема, возможно, в дизайне инструмента, а не в промпте.

## Инженерия промптов

<AdInArticle />

### Структура системного промпта

Хороший промпт Agent включает:

```markdown
---
description: Короткое описание (влияет на автовыбор)
mode: subagent
temperature: 0.2
---

# Определение роли
Кто вы и в чём сильны.

# Рабочий процесс
1. Что делать первым
2. Что делать вторым
3. ...

# Ограничения
- Чего не делать
- Когда останавливаться

# Формат вывода
- Как организовать вывод
- Какие разделы включить

# Самопроверка (необязательно)
Перед завершением задайте себе несколько вопросов.
```

### Полный пример

```markdown
---
description: Эксперт по аудиту безопасности, фокус на уязвимостях OWASP Top 10
mode: subagent
temperature: 0.1
steps: 30
permission:
  edit: deny
---

# Роль

Вы — эксперт по аудиту безопасности, находите уязвимости в веб-приложениях.

Главное обнаружить:
- SQL-инъекции
- XSS (межсайтовый скриптинг)
- CSRF (межсайтовая подделка запросов)
- Проблемы аутентификации и авторизации
- Утечки чувствительных данных
- Уязвимости зависимостей

### Механизм рефлексии

Добавление шагов самопроверки в промпт повышает точность Agent.

```markdown
# Самопроверка перед завершением

Перед отправкой результата спросите себя:
1. Полностью ли я понял задачу пользователя?
2. Полно ли моё решение?
3. Не упущены ли граничные случаи?
4. Будь я пользователем — устроил бы меня такой результат?
```

## Сквозные параметры (Additional Options)

Неизвестные поля конфигурации Agent **пробрасываются провайдеру**. Так доступны специфичные для провайдера параметры.

> Источник: `packages/core/src/v1/config/agent.ts:62-66` (normalize складывает неизвестные поля в options), `packages/opencode/src/agent/agent.ts:292` (слияние options)

### Пример конфигурации

```jsonc
{
  "agent": {
    "deep-thinker": {
      "description": "Глубокое мышление для сложных задач",
      "model": "openai/o1",
      "reasoningEffort": "high",     // Специфичный параметр OpenAI
      "textVerbosity": "low"          // Специфичный параметр OpenAI
    },
    "quick-helper": {
      "description": "Быстрые ответы для простых задач",
      "model": "anthropic/claude-haiku-4-5",
      "temperature": 0.3
    }
  }
}
```

### Частые сквозные параметры

| Параметр | Провайдер | Описание |
|------|----------|------|
| `reasoningEffort` | OpenAI серии o | `high` / `medium` / `low` |
| `textVerbosity` | OpenAI | Детализация вывода |
| `top_k` | Anthropic | Параметр сэмплирования |
| `max_tokens` | Большинство провайдеров | Максимум выходных токенов |

> Какие параметры поддерживаются — смотрите в документации соответствующего провайдера.

## Приёмы продвинутой настройки

### Agent во вложенных подкаталогах

Agent раскладываются по подкаталогам:

```
.opencode/agent/
├── review/
│   ├── security.md       → имя: review/security
│   └── performance.md    → имя: review/performance
├── docs/
│   └── api.md            → имя: docs/api
└── translator.md         → имя: translator
```

::: tip 💡 Как вызываются
- **Без поля name**: система сама использует полный путь как имя Agent, например `review/security`, вызов — `@review/security`
- **С полем name**: перекрывает автоимя, например `name: security` вызывается как `@security`

**Рекомендация**: у Agent во вложенных каталогах не задавайте поле `name` во frontmatter — пусть система сама создаёт имена с путём.
:::

Способы вызова:

```
@review/security проведи аудит этого кода
```

> Источник: `packages/opencode/src/config/agent.ts:22-29`

### Wildcard-контроль инструментов MCP

Отключить все инструменты некого MCP-сервера:

```jsonc
{
  "agent": {
    "safe-agent": {
      "permission": {
        "mymcp_*": "deny",           // Отключить все инструменты mymcp
        "postgres_query": "ask"       // Запросы к базе — с подтверждением
      }
    }
  }
}
```

> Источник: `agents.mdx:366-379`

### Настройка параметра steps

```yaml
---
steps: 50  # Максимум шагов итераций
---
```

| Настройка | Поведение |
|------|------|
| Не задано | Без лимита, пока модель сама не остановится |
| Задано число | По достижении лимита — принудительная сводка и остановка |

**Рекомендации**:
- Простые задачи: 10–20 шагов
- Средние задачи: 30–50 шагов
- Сложные задачи: 50–100 шагов
- Без лимита: когда нужно довести до конца во что бы то ни стало

### Свой цвет color

```yaml
---
color: "#FF5733"  # hex-цвет
---
```

Различайте Agent в интерфейсе — видно, какой сейчас работает.

### Скрытие Agent через hidden

```yaml
---
hidden: true  # Скрыть из @-меню
---
```

Когда подходит:
- Внутренние инструментальные Agent, прямой вызов не нужен
- Вызываются только через Task tool другими Agent
- Системные Agent

> Источник: `packages/core/src/v1/config/agent.ts:27-29`

### Переопределение имени через name

```yaml
---
name: my-custom-name  # Перекрыть имя файла
description: ...
---
```

По умолчанию имя Agent — имя файла (без .md). Полем `name` перекрывается.

> Источник: `agent.ts:290`

## Приёмы отладки Agent

### 1. Смотреть реальные диалоги

Данные сессий OpenCode лежат в каталоге `.opencode/data/`.

```bash
# Свежие сессии
ls -la .opencode/data/sessions/

# Сообщения конкретной сессии
cat .opencode/data/sessions/<session-id>/messages.json
```

### 2. Упрощать для тестов

При аномальном поведении Agent:

1. Создайте **минимальную** версию промпта
2. Постепенно добавляйте сложность
3. Найдите ломающий фрагмент

```markdown
<!-- Минимальная версия -->
---
description: Тестовый Agent
mode: subagent
---

Ты — тестовый помощник. Отвечай на вопросы пользователя.
```

### 3. Проверять конфигурацию прав

Проблемы прав — самый частый источник проблем.

```bash
# Текущая конфигурация (включая смерженные права)
opencode config
```

Проверьте:
- верный ли порядок правил (`*` — первым)
- нет ли конфликтующих правил
- не перекрывают ли правила уровня Agent ожидаемые глобальные

### 4. Проверять возможности модели

Возможности моделей сильно различаются.

| Тип задач | Рекомендуемые модели |
|---------|---------|
| Сложные рассуждения | Claude Opus, GPT-4, o1 |
| Генерация кода | Claude Sonnet, GPT-4 |
| Простые задачи | Claude Haiku, GPT-4o-mini |

Плохая работа Agent — попробуйте более сильную модель.

### 5. Отладка лимитом steps

Задайте маленький `steps` и понаблюдайте за первыми шагами Agent:

```yaml
---
steps: 5  # Остановиться после 5 шагов
---
```

## Подборка граблей расширения

| Симптом | Причина | Решение |
|-----|-----|-----|
| Agent игнорирует инструкции | Промпт длинный или туманный | Выжмите главные правила, используйте структуру |
| Agent зацикливает вызовы subagent | Нет условия остановки | Задайте лимит steps или запретите task |
| Сквозные параметры не действуют | Провайдер не поддерживает | Сверьтесь с документацией провайдера |
| Agent из вложенного каталога не находится | Неверный формат пути или перекрыт name | Разделитель `/`: `folder/agent`; проверьте, не задано ли поле `name` во frontmatter |
| Права MCP-инструментов недействительны | Не совпал wildcard | Убедитесь, что префикс имён инструментов совпадает |
| temperature не действует | Модель не поддерживает или `capabilities.temperature = false` | Смотрите документацию модели: отдельные reasoning-модели (вроде Codex) temperature не поддерживают |
| description не работает | Содержимое слишком общее | Конкретно опишите, **когда** использовать этот Agent |
| Автовыбор не того Agent | Похожие description | Разведите описания Agent с явными различиями |
| Скрытый Agent всё равно виден | mode не subagent | hidden действует только на subagent |
| Лимит steps достигнут, задача не готова | Лимит мал | Увеличьте steps или улучшите промпт |

## Примеры продвинутого использования

### Робот автоматического ревью кода

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "agent": {
    "pr-reviewer": {
      "description": "Робот ревью PR: автоматически проверяет изменения кода",
      "mode": "primary",
      "model": "anthropic/claude-opus-4-5-thinking",
      "steps": 100,
      "temperature": 0.1,
      "prompt": "{file:./prompts/pr-reviewer.md}",
      "permission": {
        "edit": "deny",
        "bash": {
          "*": "deny",
          "git log*": "allow",
          "git diff*": "allow",
          "git show*": "allow",
          "npm test": "allow"
        },
        "task": {
          "*": "deny",
          "security-auditor": "allow",
          "performance-checker": "allow",
          "style-checker": "allow"
        }
      }
    }
  }
}
```

### Командная работа нескольких моделей

```jsonc
{
  "agent": {
    "planner": {
      "description": "Планировщик: разбирает требования, составляет план",
      "mode": "primary",
      "model": "anthropic/claude-opus-4-5-thinking",
      "temperature": 0.2,
      "steps": 20
    },
    "executor": {
      "description": "Исполнитель: пишет конкретный код",
      "mode": "primary",
      "model": "anthropic/claude-sonnet-4-20250514",
      "temperature": 0.3,
      "steps": 100
    },
    "reviewer": {
      "description": "Ревьюер: проверяет качество кода",
      "mode": "subagent",
      "model": "anthropic/claude-haiku-4-5",
      "temperature": 0.1,
      "permission": {
        "edit": "deny"
      }
    }
  }
}
```

Как пользоваться:
1. Tab на planner — составить план
2. Tab на executor — реализовать
3. `@reviewer` — вызвать проверку
