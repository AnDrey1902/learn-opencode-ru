## Режимы прав

| Режим | Описание |
|-----|------|
| `allow` | Разрешить выполнение без вопросов |
| `ask` | Каждый раз спрашивать подтверждение пользователя |
| `deny` | Запретить выполнение |

---

## Границы режима автоподтверждения

Стандартный TUI и неинтерактивный `run` открыто предоставляют `--auto`:

```bash
# Стандартный TUI
opencode --auto

# Неинтерактивные задачи
opencode run --auto "Прогони тесты и почини упавшее"
```

Он автоматически подтверждает только те запросы прав, которые попали бы в процесс `ask`, и **не перекрывает явные правила `deny`**. Например, при настроенном `"rm *": "deny"` совпадающие команды удаления отклоняются даже с `--auto`.

Целевая версия принимает скрытый `--yolo` как алиас совместимости и отображает его на то же поведение автоподтверждения, что и `--auto`; новые команды и скрипты должны использовать открытый параметр `--auto`. Флаг работает в стандартном TUI и `opencode run`, вход `opencode --mini` его не пробрасывает.

> **Исходники (v1.18.22)**: [`tui.ts:108-121`](https://github.com/anomalyco/opencode/blob/v1.18.22/packages/opencode/src/cli/cmd/tui.ts#L108-L121),[`tui.ts:287-295`](https://github.com/anomalyco/opencode/blob/v1.18.22/packages/opencode/src/cli/cmd/tui.ts#L287-L295),[`run.ts:242-274`](https://github.com/anomalyco/opencode/blob/v1.18.22/packages/opencode/src/cli/cmd/run.ts#L242-L274)

## Глобальная настройка прав

В `opencode.json` используйте `permission` (обратите внимание — в **единственном числе**):

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "*": "ask",          // По умолчанию все действия с подтверждением
    "bash": "allow",     // Bash-команды пропускать автоматически
    "edit": "deny"       // Правку файлов запретить
  }
}
```

Настройка всех прав разом:

```jsonc
{
  "permission": "allow"  // Все действия пропускать автоматически
}
```

## Точечные правила (синтаксис объектов)

Разные действия для разных входных данных инструментов:

```jsonc
{
  "permission": {
    "bash": {
      "*": "ask",                    // По умолчанию с подтверждением
      "git *": "allow",              // git-команды пропускать
      "npm *": "allow",              // npm-команды пропускать
      "rm *": "deny"                 // Команды rm запретить
    },
    "edit": {
      "*": "deny",                   // Правка по умолчанию запрещена
      "packages/web/src/content/docs/*.mdx": "allow"  // Только документацию можно
    }
  }
}
```

**Приоритет правил**: сопоставление шаблонов вычисляется по порядку, **действует последнее совпавшее правило**.

Частый приём: wildcard-правило `"*"` — первым, более конкретные — после него.

---

## Wildcard-шаблоны

- `*` покрывает ноль и более любых символов
- `?` покрывает ровно один символ
- Остальные символы match'атся буквально

### Права с поддержкой точечных правил

Эти права настраиваются объектным синтаксисом под разные шаблоны:

| Право | Описание | Что сопоставляется |
|------|------|---------|
| `read` | Чтение файлов | Пути файлов |
| `edit` | Права изменения файлов (покрывают edit, write и patch) | Пути файлов |
| `glob` | Поиск файлов по wildcard | glob-шаблоны |
| `grep` | Поиск по содержимому | Шаблоны регулярных выражений |
| `list` | Список файлов каталога | Пути каталогов |
| `bash` | Запуск shell-команд | Разобранные префиксы команд |
| `task` | Запуск под-агентов | Имена под-агентов |
| `skill` | Загрузка навыков | Имена навыков |
| `lsp` | LSP-запросы | Поддерживает точечное сопоставление |
| `external_directory` | Доступ к путям вне проекта | Пути каталогов |

> 📝 Примечание: в целевой версии нет инструмента `multiedit`; создание, правка и патчи файлов едино управляются правом `edit`.

### Права только с простым синтаксисом

Эти права задаются только как `allow`/`ask`/`deny`, объектный синтаксис не поддерживается:

| Право | Описание |
|------|------|
| `todowrite` | Обновление списка дел |
| `webfetch` | Получение содержимого URL (URL передаётся в рантайме для always-подтверждений) |
| `websearch` | Поиск в вебе (запрос передаётся в рантайме для always-подтверждений) |
| `doom_loop` | Срабатывает при троекратном повторе одного вызова инструмента |

> ⚠️ Обратите внимание: в целевой версии нет реализации инструмента `plan_enter`; одноимённый ключ прав не создаёт вызываемого действия. Экспериментальный инструмент `plan_exit` существует и вычисляется по обычным правилам прав, пользовательские правила перекрывают встроенные значения по умолчанию.

> **Источник**: `opencode/packages/opencode/src/config/config.ts:621-652`

## Значения по умолчанию

- Большинство прав по умолчанию `"allow"`
- `doom_loop` и `external_directory` по умолчанию `"ask"`
- Файлы `.env` по умолчанию спрашивают (`ask`), а не отклоняют напрямую:

```jsonc
{
  "permission": {
    "read": {
      "*": "allow",
      "*.env": "ask",
      "*.env.*": "ask",
      "*.env.example": "allow"  // Файлы-примеры читать можно
    }
  }
}
```

## Матрица прав Agent

В OpenCode четыре главных встроенных Agent с разными правами по умолчанию:

| Инструмент/право | build | plan | general | explore |
|----------|-------|------|---------|---------|
| Чтение файлов | ✅ | ✅ | ✅ | ✅ |
| Правка файлов | ✅ | ❌ (разрешены только проектные и глобальные файлы планов) | ✅ | ❌ |
| Shell-команды | ✅ | ✅ | ✅ | ✅ |
| Веб-поиск и чтение | ✅ | ✅ | ✅ | ✅ |
| Поиск по коду | ✅ | ✅ | ✅ | ✅ |
| Ведение TODO | ✅ | ✅ | ❌ | ❌ |
| Инструмент вопросов | ✅ | ✅ | ❌ | ❌ |
| `plan_exit` | ❌ | ✅ | ❌ | ❌ |
| Доступ к внешним каталогам | ⚠️ (по умолчанию ask) | ⚠️ (по умолчанию ask; плюс разрешён глобальный каталог plans) | ⚠️ (по умолчанию ask) | ⚠️ (по умолчанию ask; наследует общий белый список) |

::: details 📝 Примечание: пояснение права внешних каталогов
Доступ всех Agent к внешним каталогам по умолчанию требует подтверждения пользователя (ask) плюс наследование общих белых списков (каталоги временных усечений, временные каталоги, каталоги Skill и Reference и т. д.). У отдельных Agent есть исключения:
- **build**: по умолчанию ask
- **plan**: по умолчанию ask, плюс разрешён `plans/*` в глобальном каталоге данных; проектный `.opencode/plans/*.md` — в белом списке edit, а не исключение внешних каталогов
- **general**: по умолчанию ask
- **explore**: по умолчанию ask, наследует белые списки усечённого вывода, временных каталогов, каталогов Skill и Reference
:::

::: details 📝 Примечание: подробности по Agent

### Build Agent (по умолчанию)
- **Режим**: `primary`
- **Права**: разрешено всё
- **Назначение**: Agent разработки по умолчанию, доступны все инструменты

### Plan Agent
- **Режим**: `primary`
- **Права**: правка по умолчанию запрещена, разрешены только проектные и глобальные файлы планов
- **Назначение**: планирование только для чтения, код не меняет — этап анализа сосредоточен на мышлении

### General Agent
- **Режим**: `subagent`
- **Права**: по умолчанию запрещены `todowrite` и `question`
- **Назначение**: общие исследования, многошаговые задачи

### Explore Agent
- **Режим**: `subagent`
- **Права**: по умолчанию запрещены все инструменты (`"*": "deny"`), разрешены только чтение, поиск и shell для исследования
- **Назначение**: быстрый разведывательный поиск по коду

:::

> **Источник**: `opencode/packages/opencode/src/agent/agent.ts:92-155`

## Особые правила режима Plan

Когда AI пытается обратиться к файлам **вне рабочего каталога проекта**, срабатывает проверка права `external_directory`.

### Сценарии срабатывания

Эти инструменты срабатывают при путях вне проекта:

| Инструмент | Условие срабатывания |
|------|---------|
| `read` | Чтение файла вне проекта |
| `edit` | Правка файла вне проекта |
| `write` | Запись файла вне проекта |
| `patch` | Патч файла вне проекта |
| `bash` | Команда затрагивает пути вне проекта (например, `cd ..`, `rm /tmp/file`) |

### Логика детекта

Принадлежность файла проекту OpenCode определяет относительным путём:

```typescript
// Источник: opencode/packages/opencode/src/util/filesystem.ts:25-27
export function contains(parent: string, child: string) {
  return !relative(parent, child).startsWith("..")
}
```

Относительный путь с `..` в начале — файл вне каталога проекта.

### Поведение по умолчанию

```jsonc
{
  "permission": {
    "external_directory": "ask"  // По умолчанию: спрашивать подтверждение для внешних путей вне белого списка
  }
}
```

### Частая настройка: разрешить доступ к внешним папкам

Чтобы OpenCode обращался к внешним папкам **без подтверждений каждый раз**, добавьте конфигурацию:

```jsonc
// opencode.json
{
  "permission": {
    "external_directory": "allow"
  }
}
```

Одна из самых частых настроек, особенно подходит, когда:
- нужен частый доступ к каталогам конфигурации вроде `~/.config/`
- проект зависит от файлов других каталогов
- монорепозиторий, а OpenCode стартуете в подкаталоге

### Точечное управление (по путям)

`external_directory` поддерживает объектный синтаксис по путям:

```jsonc
{
  "permission": {
    "external_directory": {
      "*": "ask",                    // По умолчанию с подтверждением
      "/tmp/*": "allow",             // Каталог /tmp разрешён
      "/home/user/shared/*": "allow", // Общий каталог разрешён
      "/etc/*": "deny"               // Системная конфигурация запрещена
    }
  }
}
```

### Сводка способов настройки

| Способ | Место конфигурации | Пример |
|------|---------|------|
| Глобальная настройка | `~/.config/opencode/opencode.json` | `"external_directory": "allow"` |
| Настройка проекта | `корень-проекта/opencode.json` | `"external_directory": "allow"` |
| Переменная окружения | `OPENCODE_PERMISSION` | `export OPENCODE_PERMISSION='{"external_directory": "allow"}'` |
| Уровень Agent | `agent.xxx.permission` | Пример ниже |

### Настройка уровня Agent

```jsonc
{
  "agent": {
    "file-manager": {
      "description": "Agent управления файлами с доступом к внешним каталогам",
      "permission": {
        "external_directory": "allow"
      }
    },
    "safe-agent": {
      "description": "Безопасный Agent без доступа к внешним каталогам",
      "permission": {
        "external_directory": "deny"
      }
    }
  }
}
```

## Как сопоставляются Bash-команды

OpenCode разбирает Bash-команды в **читаемые префиксы команд** и сопоставляет. Правила разбора опираются на "arity" команд (число параметров).

### Примеры разбора

| Входная команда | Разобранный шаблон сопоставления |
|---------|----------------|
| `git checkout main` | `git checkout` |
| `npm install` | `npm install` |
| `npm run dev` | `npm run dev` |
| `docker compose up` | `docker compose up` |
| `rm -rf node_modules` | `rm` |

### Частые Arity команд

| Префикс команды | Arity | Описание |
|---------|-------|------|
| `git` | 2 | Совпадает с `git <подкоманда>` |
| `npm` | 2 | Совпадает с `npm <подкоманда>` |
| `npm run` | 3 | Совпадает с `npm run <имя-скрипта>` |
| `docker` | 2 | Совпадает с `docker <подкоманда>` |
| `docker compose` | 3 | Совпадает с `docker compose <подкоманда>` |
| `rm` | 1 | Совпадает только с `rm` |

> **Источник**: `opencode/packages/opencode/src/permission/arity.ts`

### Практический пример конфигурации

```jsonc
{
  "permission": {
    "bash": {
      "*": "ask",
      "git status": "allow",
      "git diff": "allow",
      "git log*": "allow",
      "npm run*": "allow",
      "rm*": "deny"           // Запретить все операции удаления
    }
  }
}
```

## Поведение Ask

Когда OpenCode просит подтверждения, предлагаются три варианта:

| Вариант | Поведение |
|------|------|
| `once` | Подтвердить только этот запрос |
| `always` | Подтверждать будущие запросы по **предложенному шаблону** (текущая сессия) |
| `reject` | Отклонить запрос |

### Как работает `always`

При выборе `always` OpenCode подтверждает последующие запросы по **предложенному инструментом безопасному шаблону**.

Например, при подтверждении `git status --porcelain` предложенным шаблоном может быть `git status*` — и все последующие команды `git status` пропускаются автоматически.

### Обратная связь при отклонении

При отклонении пользователем можно:
- **Отклонить напрямую**: AI получит «пользователь отклонил этот вызов инструмента» и попробует другие способы
- **С отзывом**: можно сказать AI, почему отклонено, и направить его в другую сторону

## Права уровня Agent

Права переопределяются для отдельных агентов, правила агентов **приоритетнее** глобальной конфигурации:

```jsonc
{
  "permission": {
    "bash": {
      "*": "ask",
      "git status": "allow"
    }
  },
  "agent": {
    "deploy": {
      "permission": {
        "bash": {
          "*": "ask",
          "git status": "allow",
          "git push": "allow"     // Только agent deploy может делать push
        }
      }
    }
  }
}
```

### Конфигурация Markdown Agent

Права в Markdown-агенте:

```markdown
---
description: Ревью кода только для чтения
mode: subagent
permission:
  edit: deny
  bash: ask
  webfetch: deny
---

Только анализируй код и предлагай изменения, ничего не выполняй.
```

> **Обратите внимание**: права Agent **сливаются** с глобальными правами, правила Agent приоритетнее.

## Миграция устаревшей конфигурации

С v1.1.1 старая конфигурация `tools` устарела, переходите на `permission`:

```jsonc
// ❌ Старый синтаксис (устарел, но обратно совместим)
{
  "tools": {
    "bash": true,
    "edit": false
  }
}

// ✅ Новый синтаксис
{
  "permission": {
    "bash": "allow",
    "edit": "deny"
  }
}
```

> Старая конфигурация по-прежнему работает, OpenCode автоматически конвертирует в новый формат.

## Лучшие практики безопасности

### 1. Защита чувствительных файлов

```jsonc
{
  "permission": {
    "read": {
      "*": "allow",
      "*.env": "deny",
      "*.env.*": "deny",
      "*.key": "deny",
      "*.pem": "deny",
      "credentials/*": "deny"
    }
  }
}
```

::: tip Защита файлов .env
OpenCode по умолчанию защищает все файлы `.env` и `.env.*`, но разрешает прямой доступ к `.env.example` (примеры не содержат чувствительных данных).
:::

### 2. Ограничение опасных команд

```jsonc
{
  "permission": {
    "bash": {
      "*": "ask",
      "git *": "allow",
      "npm *": "allow",
      "rm -rf *": "deny",
      "sudo *": "ask",
      "chmod *": "ask"
    }
  }
}
```

### 3. Конфигурация корпоративного окружения

Строгие права в глобальном конфиге `~/.config/opencode/opencode.json`:

```jsonc
{
  "permission": {
    "external_directory": "deny",
    "bash": "ask",
    "websearch": "deny",
    "webfetch": "deny"
  }
}
```

### 4. Конфигурация окружения разработки

Мягкие права в проектном `.opencode/opencode.json`:

```jsonc
{
  "permission": {
    "read": {
      "*": "allow"
    },
    "edit": {
      "src/*": "allow",
      "test/*": "allow",
      "*.md": "allow"
    },
    "external_directory": "allow"
  }
}
```

## Диагностика проблем с правами

### Проблема: действие неожиданно отклонено

1. Проверьте, не режим ли Plan (в режиме Plan правка исходников запрещена)
2. Проверьте конфигурацию прав в `opencode.json`
3. Проверьте, не сработал ли матчинг шаблонов файлов (правила чувствительных файлов вроде .env)

### Проблема: частые окна подтверждений

1. Используйте «всегда разрешать» для сокращения повторов
2. Добавьте правила `allow` для перекрытия умолчаний
3. Матчьте класс действий wildcard-шаблонами

### Проблема: конфигурация прав не действует

1. Проверьте корректность JSON-синтаксиса
2. Убедитесь в пути конфига (проект vs глобальный)
3. Убедитесь, что используете `permission` (единственное число), а не `permissions` (множественное)
4. Перезапустите OpenCode для применения

---

## Типичные проблемы

| Симптом | Причина | Решение |
|-----|-----|-----|
| Конфигурация прав не действует | Использовали `permissions` (множественное число) | Используйте `permission` (единственное число) |
| Команда неожиданно перехвачена | Проблема порядка правил | **Действует последнее совпавшее правило**, `*` — первым |
| Не читается .env | По умолчанию отклонено | Явно добавьте правило allow |
| `todowrite: {...}` ругается | Поддерживается только простой синтаксис | Замените на `todowrite: "allow"` |
| `git push` сопоставился как `git` | Не настроена полная команда | Настройте `"git push": "allow"` |
| Права Agent не действуют | Неверный уровень вложенности | Убедитесь, что внутри `agent.имя.permission` |
| Доступ к внешним файлам всегда спрашивает | `external_directory` по умолчанию `ask` | Задайте `"external_directory": "allow"` |
| Хотите запретить отдельные внешние пути | Нужен точечный контроль | Настройте по путям объектным синтаксисом |
