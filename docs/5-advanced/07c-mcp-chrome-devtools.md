# 5.7c Практика Chrome DevTools MCP

> 💡 **Коротко**: пусть AI напрямую подключается к вашему браузеру Chrome — отлаживает страницы, анализирует производительность и управляет DOM.

---

## Что вы сможете после урока

- Настроить MCP-сервер Chrome DevTools
- Подключить AI к используемой сессии браузера
- Выделять элементы и запросы в DevTools для анализа AI
- Не перелогиниваться — отлаживать уже залогиненные страницы

---

## С какими трудностями вы столкнулись

- Хотите, чтобы AI помог с отладкой страницы, но приходится пересылать скриншоты и копировать код
- Проблемы залогиненных страниц AI недоступны (нужен повторный вход)
- Нашли проблему в DevTools — вручную копируете данные AI для объяснений
- Хотя Chrome уже открыт, MCP ругается, что `chrome-beta` не найден

## Что такое Chrome DevTools MCP

Chrome DevTools MCP — официальный браузерный MCP от Google. Итог в трёх пунктах:

1. **Напрямую забирает ваш текущий Chrome**
2. **Переиспользует ваше залогиненное состояние**
3. **Отдаёт AI видимую DevTools информацию**

### Чем отличается от традиционной автоматизации браузеров

| Критерий | Chrome DevTools MCP | Puppeteer, Playwright и Selenium |
|------|------|------|
| Состояние входа | Прямое переиспользование текущего браузера | Обычно самим вести cookie и токены |
| Инстанс браузера | Подключение к уже открытому Chrome | Часто новый инстанс |
| Позиционирование элементов | `uid` (дерево доступности) | CSS и XPath |
| Взгляд на отладку | Больше «понимать семантику страницы» | Больше «искать узлы DOM» |

::: info Что за `uid`?
Здесь `uid` — временный идентификатор в снепшоте страницы из дерева доступности, а не CSS-селектор.

Плюс в независимости от имён классов страницы. Минус прямой: **после обновления страницы uid может поменяться — хардкодить нельзя.**
:::

```
┌─────────────────────────────────────────────────────────────┐
│                    Chrome DevTools MCP                       │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│   Ваш браузер ◄──────────► MCP-сервер ◄──────────► OpenCode  │
│   (залогинен)               (локально)          (AI-агент)    │
│                                                              │
│   ✓ Без повторного входа                                     │
│   ✓ Доступ к текущей сессии                                  │
│   ✓ Функции DevTools                                         │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

### Типичные сценарии

| Сценарий | Традиционно | Через MCP |
|------|---------|---------|
| Отладка залогиненных страниц | Скриншоты + копирование кода | AI напрямую в браузере |
| Анализ сетевых запросов | Ручное копирование данных запросов | AI читает панель Network |
| Проверка структуры DOM | Копирование HTML-кода | AI напрямую работает с панелью элементов |
| Анализ производительности | Выгрузка отчёта для AI | AI напрямую читает данные производительности |

## Настройка MCP-сервера

Пропишите прямо в глобальный файл `~/.config/opencode/opencode.json`:

### Способ 1: правка конфига вручную

Отредактируйте `~/.config/opencode/opencode.json` или `.opencode/opencode.json` в каталоге проекта:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "chrome-devtools": {
      "type": "local",
      "command": ["npx", "-y", "chrome-devtools-mcp@latest", "--autoConnect", "--channel=stable"],
      "enabled": true
    }
  }
}
```

**Описание параметров**:

| Параметр | Описание |
|------|------|
| `--autoConnect` | Автоподключение к текущему активному инстансу Chrome |
| `--channel=stable` | Явно стабильный Chrome — без путаницы версий |

Если ближе интерактивная настройка, можно и так:

```bash
opencode mcp add
```



Не нужно специально писать `use chrome-devtools`. Общайтесь с OpenCode по-человечески — MCP он вызовет сам, когда надо.

**При первом подключении** Chrome покажет диалог разрешений:

```
┌─────────────────────────────────────────────────────────────┐
│  Chrome                                                     │
│                                                             │
│  "chrome-devtools-mcp" wants to start a remote debugging   │
│  session with Chrome.                                       │
│                                                             │
│  [Allow]  [Block]                                          │
└─────────────────────────────────────────────────────────────┘
```

После успешного подключения сверху в Chrome появится:

```
┌─────────────────────────────────────────────────────────────┐
│  Chrome is being controlled by automated test software.     │
└─────────────────────────────────────────────────────────────┘
```

::: tip Если после правки конфига не заработало
Сначала выйдите из OpenCode и откройте заново. Часто дело в неостановившемся старом MCP-процессе.
:::

## Что этот MCP реально умеет

Не считайте его просто «браузером для AI». Его настоящая сила — в трёх классах.

### Прямые действия на странице

- Открывать страницы, переключать вкладки, вперёд-назад, обновлять
- Скриншоты, снепшоты страниц, клики, ввод, клавиши
- Загрузка файлов, обработка попапов, перетаскивание элементов

Самая наглядная автоматизация: что раньше кликали руками — теперь кликает AI.

### Прямое чтение отладочной информации

- Смотреть ошибки консоли
- Смотреть сетевые запросы и ответы
- Смотреть структуру страницы и дерево доступности
- Прогонять аудит Lighthouse
- Прогонять трассировку производительности, разбирать LCP, INP и CLS
- Делать снепшоты памяти

Эти способности лучше всего для отладки фронтенда. Раньше вы делали скриншоты, копировали ошибки и выгружали HAR. Теперь AI смотрит живьём на месте.

### Прямое переиспользование состояния входа текущего браузера

- Без отдельной передачи cookie
- Без повторного входа
- Без отдельного ведения токенов и сессий
- Что видно в браузере — с тем AI в основном и работает дальше

В этом его главная сила. Во многих веб-задачах сложность не в «нажатии кнопок», а в том, чтобы «сначала войти и получить реальное состояние страницы».

Раньше для такого приходилось:

- вручную таскать cookie
- разбираться с протуханием входа
- проходить двухфакторку и антифрод
- придумывать, как передать данные страницы AI

Теперь логика перевёрнута: **вы входите как обычно, а AI продолжает работу прямо в вашем браузере.**

### В чём настоящее преимущество перед традиционной автоматизацией браузеров

- Традиционная автоматизация часто открывает новый браузер и заново ведёт вход
- Chrome DevTools MCP подключается прямо к вашей текущей сессии
- Традиционные инструменты ближе к скриптам и селекторам
- Этот MCP лучше подходит AI: смотреть на страницу, судить и действовать дальше

Одним предложением: традиционная автоматизация больше похожа на «вы скриптом командуете браузером», а Chrome DevTools MCP — на «AI напрямую забирает уже открытый у вас браузер».

### Самые практичные сценарии

- **Отладка залогиненных страниц**: админки, консоли, страницы подписок, залогиненные рабочие места
- **Разбор проблем страниц**: смотреть Network, Console, Elements, Performance
- **Контентная работа**: постинг, разбор таймлайнов, сбор информации, Markdown-сводки
- **Формы и админские действия**: повторяющиеся заполнения, пакетный ввод, загрузка вложений
- **Патрулирование страниц**: скриншоты, аудиты производительности, регрессионные проверки
- **Страница как узел процесса**: сначала спросить AI на странице, потом продолжить автооперации

### Ещё шаг вверх: из него собираются полные процессы

Сильнее всего не отдельные действия, а связки:

1. Открыть страницу
2. Прочитать состояние страницы
3. Решить следующий шаг
4. Нажать или ввести
5. Снова прочитать результат
6. Продолжить действия или выдать отчёт

Так что это не просто «автоматизация браузера», а скорее движок веб-процессов с визуальным контекстом.

### Реально прогнанные здесь кейсы

| Кейс | Фактический результат | Использованные способности |
|------|------|------|
| Подключение текущего Chrome | Успешно перечислены 28 вкладок | `list_pages` |
| Чтение текущей страницы | Успешно получен снепшот страницы | `take_snapshot` |
| Пост в X | Успешно опубликован тестовый пост | Навигация, клики, ввод |
| Разбор таймлайна X | Собраны 14 записей в `x_timeline.md` | Навигация, ожидание, снепшот, запись файлов |
| Спросить Grok и подписаться | Grok порекомендовал AI-специалистов, далее подписки | Многошаговые действия на страницах |

### Запомните эти 4 вывода

| Симптом | Что реально делать |
|------|-------------|
| Ругается, что `chrome-beta` не найден | Не пишите beta в конфиг, пользуйтесь стабильным Chrome |
| Пользователь говорит «Chrome уже открыт» | Сначала убедитесь, что открыт Chrome той же версии |
| После правки конфига старая ошибка | В первую очередь подозревайте незавершённый старый MCP-процесс — перезапустите OpenCode |
| `list_pages` прошёл | Добейте `take_snapshot` или скриншотом — убедитесь в реальном соединении |

::: warning Про активное ограничение скорости в автооперациях
AI по умолчанию не работает «в человеческом темпе». Действия вроде постов, лайков, подписок, пакетных кликов и пакетного заполнения форм при слишком быстром подряд выполнении легко триггерят антифрод платформ.

Рекомендуем прямо писать в промпте:

```text
Работай помедленнее, в человеческом ритме. Между шагами пауза 2–3 секунды, без частых кликов подряд.
```

Для более чувствительных платформ — ещё консервативнее:

```text
Действуй максимально по-человечески: после изменений страницы сначала жди, потом продолжай; после каждого клика пауза 3–5 секунд.
```
:::

## Частые инструменты: примеры

Инструментов у Chrome DevTools MCP много — для начала хватит этого высокочастотного набора:

| Инструмент | Функция |
|------|------|
| `list_pages` | Список всех открытых вкладок |
| `select_page` | Выбор вкладки |
| `navigate_page` | Переход по URL, вперёд, назад, обновление |
| `take_snapshot` | Снепшот страницы (дерево доступности) |
| `take_screenshot` | Скриншот страницы или элемента |
| `click` | Клик по элементу |
| `fill` | Заполнение формы |
| `type_text` | Ввод текста |
| `press_key` | Нажатия клавиш |
| `hover` | Наведение на элемент |
| `evaluate_script` | Выполнение JavaScript |
| `list_network_requests` | Список сетевых запросов |
| `get_network_request` | Детали запроса |
| `list_console_messages` | Список сообщений консоли |
| `lighthouse_audit` | Аудит Lighthouse |
| `performance_start_trace` | Старт трассировки производительности |
| `performance_stop_trace` | Стоп трассировки производительности |

Для более полных процессов стоит знать и этот набор:

| Инструмент | Когда нужен |
|------|------|
| `new_page` | Новая вкладка для поиска, входа, тестов переходов |
| `close_page` | Вкладок много — закрыть лишние и сузить процесс |
| `wait_for` | Ждать загрузки страницы, появления кнопки, готовности результатов |
| `drag` | Зоны перетаскивания, сортировки, слайдеры |
| `fill_form` | Сразу несколько полей формы — экономнее поштучных `fill` |
| `handle_dialog` | Обработка попапов `alert`, `confirm`, `prompt` |
| `upload_file` | Загрузка картинок, PDF и вложений на странице |
| `emulate` | Эмуляция мобилок, слабой сети, геопозиции, светлой и тёмной темы |
| `get_console_message` | Полное содержимое сообщения об ошибке консоли |
| `performance_analyze_insight` | Трейс производительности уже снят — копнуть конкретный инсайт глубже |
| `take_memory_snapshot` | Подозрение на утечку памяти страницы — снять снепшот кучи |

Их удобно понимать как 3 класса:

- **Управление процессом**: `new_page`, `close_page`, `wait_for`
- **Сложные взаимодействия**: `drag`, `fill_form`, `handle_dialog`, `upload_file`
- **Глубокая диагностика**: `emulate`, `get_console_message`, `performance_analyze_insight`, `take_memory_snapshot`

::: details Почему у инструментов префикс `chrome-devtools_`?
OpenCode регистрирует MCP-инструменты в виде «имя-сервера + подчёркивание + имя-инструмента».

Поэтому при имени сервера `chrome-devtools` итоговые инструменты выглядят как `chrome-devtools_list_pages`, `chrome-devtools_take_snapshot`. Так избегают коллизий имён инструментов разных MCP-серверов.

В `v1.18.22` восстановлен и продолжает использоваться этот старый формат. Коротко мелькавший в разработке вариант `mcp__chrome-devtools__list_pages` — не текущее именование целевой версии, не правьте по нему правила прав и промпты.
:::

## Другие способы запуска

Кроме `--autoConnect` у Chrome DevTools MCP есть другие способы подключения:

### Способ 1: изолированный пользовательский профиль

Конфиг MCP с выделенным профилем Chrome (чистое окружение):

```jsonc
{
  "mcp": {
    "chrome-devtools": {
      "type": "local",
      "command": ["npx", "-y", "chrome-devtools-mcp@latest"]
    }
  }
}
```

Так стартует новый инстанс Chrome с временным профилем.

### Способ 2: подключение к порту удалённой отладки

Сначала закройте текущий Chrome и запустите удалённую отладку отдельным профилем. Так безопаснее и лучше соответствует нынешним требованиям Chrome:

```bash
# macOS
/Applications/Google\ Chrome.app/Contents/MacOS/Google\ Chrome --remote-debugging-port=9222 --user-data-dir=/tmp/chrome-profile

# Linux
google-chrome --remote-debugging-port=9222 --user-data-dir=/tmp/chrome-profile

# Windows
"C:\Program Files\Google\Chrome\Application\chrome.exe" --remote-debugging-port=9222 --user-data-dir=%TEMP%\chrome-profile
```

Затем настройте подключение MCP:

```jsonc
{
  "mcp": {
    "chrome-devtools": {
      "type": "local",
      "command": ["npx", "-y", "chrome-devtools-mcp@latest", "--browser-url=http://127.0.0.1:9222"]
    }
  }
}
```

## Типичные проблемы

| Симптом | Причина | Решение |
|-----|-----|-----|
| Не находит DevToolsActivePort для chrome-beta | Инструмент ошибочно подключился к каталогу beta-конфига | Явно добавьте `--channel=stable` |
| После правки конфига продолжает искать beta | Старый MCP-процесс в OpenCode не вышел | Перезапустите OpenCode и попробуйте снова |
| Тайм-аут подключения | Не включена удалённая отладка | Откройте `chrome://inspect/#remote-debugging` и включите |
| Диалог разрешений не появляется | Версия Chrome не поддерживается | Обновитесь до Chrome 144+, лучше до свежего стабильного |
| Сразу обрывается после подключения | Параллельно другой отладочный клиент | Закройте другие подключения DevTools |
| Медленная загрузка npx | Проблемы сети | Через прокси или предустановите `npm i -g chrome-devtools-mcp` |
| Операции на странице слишком быстрые, триггерят антифрод | AI кликает и вводит подряд слишком быстро | В промпте явно требуйте «паузы 2–5 секунд, действия как у человека» |

## Замечания о безопасности

::: warning Запрос авторизации
При каждом запросе MCP на подключение Chrome показывает диалог авторизации. Только после вашего «Разрешить» AI получает доступ к браузеру.

Во время отладочной сессии сверху в Chrome висит баннер «Chrome управляется ПО для автотестов».
:::

1. **Разрешайте только доверенные MCP** — не подтверждайте запросы подключений из неизвестных источников
2. **Отключайтесь после отладки** — закройте OpenCode или перезапустите браузер
3. **Осторожнее с чувствительными действиями** — AI видит все ваши залогиненные сайты
