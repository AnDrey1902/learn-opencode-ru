# 5.1a Основы конфигурации

> Через файл конфигурации opencode.json управляйте главным поведением OpenCode.

## 📝 Конспект урока

Ключевые идеи урока в сжатом виде:

<img src="/images/5-advanced/config-basics-notes.mini.jpeg" alt="Шпаргалка урока: основы конфигурации" data-zoom-src="/images/5-advanced/config-basics-notes.jpeg" />

<details>
<summary>📝 Текстовая версия шпаргалки</summary>

1. Иерархия приоритетов: переменные окружения > проект > глобально.
2. Настройки сливаются (merge), а НЕ перезаписываются.
3. `model` — основная модель (`provider/model`), `small_model` — дешёвая для простых задач.
4. `provider` — в ЕДИНСТВЕННОМ числе (не providers!) с полями `apiKey`, `baseURL`, `timeout`.
5. Подстановки: `{env:VARIABLE}` — переменная окружения, `{file:path}` — содержимое файла.
6. Ловушки: `providers` → надо `provider`; `variables empty` → проверить env.

</details>

## Где лежит конфигурация

Главная конфигурация OpenCode грузится по порядку, приоритет снизу вверх (позже загруженное перекрывает ранее загруженное):

| Приоритет | Место | Описание |
|-------|-----|------|
| 1 (низший) | Удалённый `.well-known/opencode` | Удалённая org-конфигурация по умолчанию (забирается механизмом Auth) |
| 2 | `~/.config/opencode/opencode.json(c)` | Глобальная пользовательская конфигурация |
| 3 | Переменная окружения `OPENCODE_CONFIG` | Путь к своему файлу конфигурации |
| 4 | `./opencode.json(c)` | Конфигурация проекта, обнаружение вверх от места открытия |
| 5 | `./.opencode/opencode.json(c)` | Конфигурация каталога `.opencode` проекта |
| 6 | Переменная окружения `OPENCODE_CONFIG_CONTENT` | Инлайн-содержимое конфигурации (строка JSON) |
| 7 (высший) | Управляемый каталог конфигурации | Корпоративный деплой, управляет администратор |

> Файлы конфигурации **сливаются**, а не перекрываются. Позже загруженное перекрывает конфликтующие ключи, а неконфликтующие настройки сохраняются.

::: details Управляемый каталог конфигурации (корпоративный деплой)
В корпоративном окружении администратор кладёт конфигурацию в системный каталог с наивысшим приоритетом — перекрывает все пользовательские и проектные конфигурации:

| Платформа | Путь |
|------|------|
| macOS | `/Library/Application Support/opencode` |
| Windows | `%ProgramData%\opencode` |
| Linux | `/etc/opencode` |

Обычным пользователям это, как правило, не нужно — достаточно знать.

:::

### Структура каталогов конфигурации

```
~/.config/opencode/
├── opencode.json       # Глобальная конфигурация
├── tui.json            # Глобальная TUI-конфигурация
├── AGENTS.md           # Глобальные правила
├── agent/              # Глобальные Agent
├── command/            # Глобальные команды
└── plugin/             # Глобальные плагины

Каталог проекта/
├── opencode.json       # Конфигурация проекта (приоритет 4)
├── tui.json            # TUI-конфигурация проекта
├── AGENTS.md           # Правила проекта
└── .opencode/
    ├── opencode.json   # Конфигурация проекта (приоритет 5, рекомендуется)
    ├── tui.json        # TUI-конфигурация проекта
    ├── agent/          # Agent проекта
    ├── command/        # Команды проекта
    └── plugin/         # Плагины проекта
```

## Формат конфигурации

Поддерживаются JSON и JSONC (JSON с комментариями):

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  // Это комментарий, формат JSONC поддерживает
  "model": "anthropic/claude-opus-4-5-thinking"
}
```

> Имя главного конфига — `opencode.json` либо `opencode.jsonc`. Обнаружение конфигурации V2 распознаёт только эти два имени; старый глобальный `~/.config/opencode/config.json` дочитывается загрузчиком совместимости. Без глобальной конфигурации текущий загрузчик по умолчанию создаёт `opencode.jsonc`. Неизвестные ключи верхнего уровня игнорируются, а не роняют с ошибкой.

## Конфигурация моделей
<AdInArticle />

### Главная и малая модели

```json
{
  "$schema": "https://opencode.ai/config.json",
  "model": "anthropic/claude-opus-4-5-thinking",
  "small_model": "anthropic/claude-haiku-4-5"
}
```

| Поле | Описание |
|-----|------|
| `model` | Главная модель (формат: provider/model) |
| `small_model` | Малая модель для простых задач (вроде генерации заголовков) |

> `small_model` задаёт дешёвую модель для лёгких задач. Без настройки OpenCode попробует дешёвую модель провайдера, иначе откатится к главной модели.

### Agent по умолчанию

```json
{
  "default_agent": "build"
}
```

Задаёт primary agent по умолчанию (обязательно primary-режим). Варианты:
- `"build"` — по умолчанию, доступны все инструменты
- `"plan"` — правка исходников запрещена, разрешена запись только проектных и глобальных файлов планов
- Или имя вашего собственного primary agent

## Конфигурация провайдеров

### Базовая конфигурация

```json
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "anthropic": {
      "options": {
        "apiKey": "{env:ANTHROPIC_API_KEY}",
        "baseURL": "https://api.anthropic.com",
        "timeout": 600000,
        "setCacheKey": true
      }
    }
  }
}
```

> Обратите внимание: ключ конфигурации — `provider` (единственное число), а не `providers`.

### Описание полей options

| Поле | Тип | Описание |
|-----|------|------|
| `apiKey` | string | API-ключ |
| `baseURL` | string | Свой адрес API (часто для прокси) |
| `timeout` | number \| false | Тайм-аут запросов (миллисекунды), по умолчанию 300000, `false` отключает |
| `setCacheKey` | boolean | Включить ключ кэширования промптов (по умолчанию false) |

### Особые настройки Amazon Bedrock

Amazon Bedrock поддерживает AWS-специфичную конфигурацию:

```json
{
  "provider": {
    "amazon-bedrock": {
      "options": {
        "region": "us-east-1",
        "profile": "my-aws-profile",
        "endpoint": "https://bedrock-runtime.us-east-1.vpce-xxxxx.amazonaws.com"
      }
    }
  }
}
```

| Поле | Описание |
|-----|------|
| `region` | Регион AWS (по умолчанию из переменной окружения `AWS_REGION` или `us-east-1`) |
| `profile` | Имя AWS-профиля (из `~/.aws/credentials`) |
| `endpoint` | Свой URL эндпоинта (для VPC-эндпоинтов) |

### Чёрные и белые списки провайдеров

Управление загружаемыми провайдерами:

```json
{
  "disabled_providers": ["openai", "gemini"],
  "enabled_providers": ["anthropic"]
}
```

| Поле | Описание |
|-----|------|
| `disabled_providers` | Список отключённых провайдеров — не грузятся даже с API-ключом |
| `enabled_providers` | Только эти провайдеры включены, остальные игнорируются |

> `disabled_providers` приоритетнее `enabled_providers`. Попадание в оба списка — отключение.

## Конфигурация тем

Темы относятся к TUI-конфигурации — пишите в отдельный `tui.json` или `tui.jsonc`, а не в главный `opencode.json`:

```jsonc
{
  "$schema": "https://opencode.ai/tui.json",
  "theme": "tokyonight"
}
```

> Обратите внимание: `theme` — ключ корня `tui.json`, а не `tui.theme`. Главный загрузчик конфигурации игнорирует `theme`, `keybinds` и `tui`.

### Автомиграция старой конфигурации

При старте TUI OpenCode попытается перенести `theme`, `keybinds` и `tui` из старых `opencode.json` / `opencode.jsonc` в `tui.json` того же каталога:

1. Если в каталоге уже есть целевой `tui.json` — каталог пропускается, файлы не трогаются. Одинокий `tui.jsonc` пропуск не вызывает, мигратор всё равно создаст `tui.json`.
2. Мигратор распознаёт строку `theme` и объект `keybinds`; старые `tui` со скоростью прокрутки, ускорением прокрутки и стилем Diff декодируются сразу по соответствующим схемам, недействительные значения в целевой файл не пишутся. Созданный `tui.json` при загрузке проходит полную валидацию схемы.
3. Сначала успешно пишется `tui.json`, затем для исходного файла создаётся разовый бэкап `<исходный-файл>.tui-migration.bak`; существующий бэкап переиспользуется без перезаписи.
4. Лишь после успеха бэкапа из исходной главной конфигурации удаляются `theme`, `keybinds` и `tui`. Миграция не транзакционна: если новый `tui.json` записан, а запись бэкапа или перезапись исходника упали — новый файл не откатывается, а старые поля могут остаться; следующий старт из-за существующего `tui.json` пропустит каталог и автоматически не повторит.

Проверка миграции охватывает глобальную главную конфигурацию, обнаруженные вверх от текущего каталога проектные главные конфигурации, главные конфигурации каталога конфигурации, а также файл, указанный `OPENCODE_CONFIG`. После миграции TUI-конфигурация сливается в порядке: глобальный `tui.json(c)` → файл из `OPENCODE_TUI_CONFIG` → обычные проектные `tui.json(c)` → `.opencode/tui.json(c)` → `OPENCODE_CONFIG_DIR`, позже загруженное приоритетнее. В одном каталоге сначала грузится `.json`, затем `.jsonc`. Обычные проектные файлы применяются от корневой стороны к текущему каталогу, поэтому чем ближе к текущему — тем приоритетнее; несколько каталогов `.opencode` сливаются от текущей стороны к корневой, поэтому при конфликте одноимённых полей побеждает более корневой, загруженный позже. `OPENCODE_CONFIG_DIR` грузится последним.

> Основания в исходниках: [фильтрация старых TUI-полей главной конфигурацией](https://github.com/anomalyco/opencode/blob/v1.18.22/packages/opencode/src/config/config.ts#L53-L61),[правила миграции и бэкапов](https://github.com/anomalyco/opencode/blob/v1.18.22/packages/opencode/src/config/tui-migrate.ts#L24-L67) и [уровни загрузки отдельной конфигурации](https://github.com/anomalyco/opencode/blob/v1.18.22/packages/opencode/src/config/tui.ts#L171-L209).

## Автообновления

```json
{
  "autoupdate": true
}
```

| Значение | Описание |
|-----|------|
| `true` | При старте автоматически скачивать обновления (по умолчанию) |
| `false` | Автообновления отключены |
| `"notify"` | Только уведомлять о новых версиях, не обновлять автоматически |

## Подстановки переменных

Значения в конфигурации задаются динамически переменными:

### Переменные окружения

Ссылки на переменные окружения через `{env:ИМЯ_ПЕРЕМЕННОЙ}`:

```json
{
  "model": "{env:OPENCODE_MODEL}",
  "provider": {
    "anthropic": {
      "options": {
        "apiKey": "{env:ANTHROPIC_API_KEY}"
      }
    }
  }
}
```

> Несуществующие переменные окружения заменяются пустой строкой.

### Содержимое файлов

Ссылки на содержимое файлов через `{file:путь}`:

```json
{
  "provider": {
    "openai": {
      "options": {
        "apiKey": "{file:~/.secrets/openai-key}"
      }
    }
  }
}
```

Пути файлов поддерживают:
- Пути относительно файла конфигурации
- Абсолютные пути с `/` в начале
- Пути домашнего каталога с `~` в начале

Подстановки переменных подходят для:
- Защиты чувствительных данных (API-ключи — отдельными файлами)
- Конфигураций под окружения (разные переменные для разработки и production)
- Общих фрагментов конфигурации

## Полный пример базовой конфигурации

```jsonc
{
  "$schema": "https://opencode.ai/config.json",

  // Модели
  "model": "anthropic/claude-opus-4-5-thinking",
  "small_model": "anthropic/claude-haiku-4-5",
  "default_agent": "build",

  // Провайдер
  "provider": {
    "anthropic": {
      "options": {
        "apiKey": "{env:ANTHROPIC_API_KEY}",
        "timeout": 600000
      }
    }
  },

  // Управление провайдерами
  "disabled_providers": ["gemini"],

  // Пользователь
  "username": "разработчик",

  // Автообновления
  "autoupdate": true
}
```

Сопутствующий `tui.jsonc`:

```jsonc
{
  "$schema": "https://opencode.ai/tui.json",
  "theme": "catppuccin"
}
```

## Типичные проблемы

| Симптом | Причина | Решение |
|-----|-----|-----|
| Конфигурация не действует | Проблема приоритетов | Конфигурация уровня проекта приоритетнее глобальной |
| Подстановка переменных не работает | Переменной окружения нет | Убедитесь, что переменная окружения задана |
| Ошибка разбора JSON | Ошибка формата | Используйте формат JSONC или проверьте синтаксис |
| Использовали `providers` | Ошибка в имени ключа | Должно быть `provider` (единственное число) |
| Провайдер не грузится | В списке disabled | Проверьте `disabled_providers` |
| Настройка темы не действует | `theme` записан в главную конфигурацию | Перенесите в `tui.json` / `tui.jsonc` того же уровня |
