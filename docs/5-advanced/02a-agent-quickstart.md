## Что такое Agent

### Определение Anthropic

По определению Anthropic из «Building Effective Agents»:

| Тип | Описание | Особенности |
|------|------|------|
| **Workflow** | LLM и инструменты оркеструются предопределённым кодом | Шаги фиксированы, предсказуемы |
| **Agent** | LLM сама направляет свой процесс и использование инструментов | Свои решения, гибкие реакции |

### Agent в OpenCode

Agent OpenCode — это **настраиваемый образ AI**, в котором определяете:

- **Личность**: кто он и в чём силён
- **Способности**: какие инструменты доступны
- **Поведение**: как выполняет задачи, какие ограничения

### Зачем нужны свои Agent

| Сценарий | Без Agent | С Agent |
|------|-----------|---------|
| Ревью кода | Каждый раз говорить «ты эксперт по ревью кода...» | Сразу `@reviewer` |
| Написание документации | Каждый раз говорить «в стиле техдоков...» | Сразу `@docs-writer` |
| Аудит безопасности | Каждый раз говорить «проверь уязвимости...» | Сразу `@security-auditor` |

---

## Типы Agent

В OpenCode два типа Agent:

| Тип | Описание | Способ вызова |
|------|------|----------|
| **Primary** | Главный Agent, объект вашего прямого общения | Переключение через Tab |
| **Subagent** | Под-агент, вызываемый главным Agent для профильных задач | `@имя-агента` или автовызов |
| **All** | Смешанный режим: работает и главным, и вызываемым | Tab или @-вызов |

### Как они сотрудничают

```
Пользователь ←→ Primary Agent (build/plan)
                    ↓
            Task Tool (создаёт независимую сессию)
                    ↓
            Subagent (explore/general/ваш собственный Agent)
                    ↓
            Возврат результата в Primary
```

### Механика под-агентов (важно)

Понимание механики под-агентов критично для проектирования эффективных Agent:

1. **Изоляция сессий (без исторической памяти)**
   Под-агент работает в **новой независимой сессии**. Это значит:
   - **Не видит историю диалога с главным Agent**: не знает, о чём вы говорили с главным Agent раньше.
   - **В контексте только промпт**: весь его мир — описание задачи (промпт), переданное ему.
   - **Контекст нужен полный**: при вызове в промпт пишется вся информация для задачи.

2. **Двойная личность режима All**
   Когда у Agent `mode: "all"`:
   - **Переключён через Tab**: он главный Agent с полной исторической памятью.
   - **Вызван через @**: он под-агент в изоляции сессий и истории вызывающего не видит.

## Разбор встроенных Agent

<AdInArticle />

### Видимые пользователю Agent

| Имя | Режим | Права по умолчанию | Описание |
|------|------|---------|------|
| `build` | primary | Разрешено всё | Agent разработки по умолчанию, доступны все инструменты |
| `plan` | primary | edit: deny (разрешены только `.opencode/plans/*.md` и глобальный каталог plans) | Планирование только для чтения, код не меняет |
| `general` | subagent | todowrite: deny | Общие исследования, многошаговые задачи |
| `explore` | subagent | Разрешены только grep/glob/list/bash/read/webfetch/websearch | Быстрое исследование кода |

> **О глубине исследования Explore Agent**: при вызове Explore задаётся глубина исследования. AI определяет сам по описанию задачи, глубину можно указать и явно в промпте:
> - **quick**: базовый поиск, быстрое позиционирование целевых файлов
> - **medium**: среднее исследование, баланс скорости и охвата
> - **very thorough**: полный разбор, поиск по нескольким местам и соглашениям об именах
>
> Источник: `agent.ts:213`

> **О Plan Agent**: это не «правка с подтверждением», а **запрет правки по умолчанию** (`edit: deny`), писать разрешено только в `.opencode/plans/*.md` (на уровне проекта) и `plans/*.md` в глобальном каталоге данных. Команды bash по умолчанию разрешены (наследуется глобальное `*: allow`). Так этап планирования сосредоточен на мышлении и не отвлекается на правки кода.
>
> Источник: `agent.ts:171-175`

### Скрытые встроенные Agent

Этими Agent вы напрямую не пользуетесь, но знание о них помогает понять систему:

## Создание первого Agent (способом Markdown)

### Базовая структура

```markdown
---
description: Коротко опишите, что делает этот Agent
mode: subagent
---

Здесь системный промпт (System Prompt).

Расскажите Agent, кто он, в чём силён и как работает.
```

### Полный пример: Agent автора документации

Создайте файл `.opencode/agent/docs-writer.md`:

```markdown
---
description: |
  Эксперт по технической документации: API-документация, README, руководства пользователя.
  Сценарии: новая документация проекта, обновление существующей, объяснение функций кода.
  Неприменимо: ревью кода, исправление багов, реализация функций.
mode: subagent
temperature: 0.3
---

# Роль

Вы — эксперт по технической документации: сложные концепции объясняете просто и понятно. Вашу документацию хвалят как «прочитал — и пользуешься».

# Нормы документации

- Формат Markdown
- Примеры кода обязаны запускаться
- Описание входа и выхода
- Русский язык в приоритете, профессиональные термины — на английском

# Структура документации

1. Обзор (что это — одним предложением)
2. Быстрый старт (за 30 секунд запускается)
3. Подробный API (полное описание параметров)
4. Примеры кода (покрывают частые сценарии)
5. Частые вопросы (предугадываем недоумения пользователей)

# Принципы работы

- Сначала поймите код, потом пишите документацию
- Непонятные места проверяйте
- Держите единый стиль

# Ограничения

- ✅ Код быстрого старта обязан копипаститься и запускаться
- ✅ Описание параметров — с типами и значениями по умолчанию
- ❌ Не предполагайте фоновых знаний пользователя
```

### Права в Markdown

Права задаются прямо во Frontmatter (синтаксис YAML):

```markdown
---
description: Agent аудита кода только для чтения
mode: subagent
permission:
  edit: deny            # Правка запрещена
  bash:
    "*": deny           # Все команды запрещены
    "git log*": allow   # Разрешён только просмотр лога
  task:
    "*": deny           # Вызовы других Agent запрещены
---
```

### Шпаргалка всех полей конфигурации

| Поле | Тип | Описание |
|-----|------|------|
| `description` | string | **Рекомендуется заполнить**. Описание Agent влияет на решения автовыбора главным Agent |
| `mode` | enum | `subagent` \| `primary` \| `all`. По умолчанию `all` |
| `model` | string | Формат `provider/model`. Без заполнения наследуется текущая модель главного Agent |
| `variant` | string | Вариант модели по умолчанию (вроде thinking). Действует лишь когда у agent задан свой `model`; без model бессмысленно |
| `prompt` | string | Системный промпт (только для JSON-конфигурации, в Markdown — тело) |
| `temperature` | number | 0–1, управляет случайностью ответов |
| `top_p` | number | 0–1, параметр ядерной выборки |
| `steps` | number | Максимум шагов итераций, защита от зацикливания |
| `hidden` | boolean | `true` прячет из @-автодополнения |
| `color` | string | Hex `#RRGGBB` или имя цвета темы (`primary`/`secondary`/`accent`/`success`/`warning`/`error`/`info`) для различения в интерфейсе |
| `permission` | object | Объект конфигурации прав |
| `disable` | boolean | Отключён ли этот Agent |
| `options` | object | Контейнер сквозных параметров для нечастых параметров Provider |
| *Остальные поля* | any | Неизвестные поля автоматически **пробрасываются** провайдеру (вроде `reasoningEffort`) |

> `maxSteps` deprecated, используйте `steps`.

### Значения temperature по умолчанию (важно)

У разных моделей разные температуры по умолчанию:

| Модель | Temperature по умолчанию | Пояснение |
|------|-----------------|------|
| Claude | undefined | Используется API-умолчание |
| GPT | undefined | Используется API-умолчание |
| Gemini | 1.0 | Фиксированное значение |
| Qwen | 0.55 | Фиксированное значение |
| GLM-4.6/4.7 | 1.0 | Фиксированное значение |
| MiniMax-M2 | 1.0 | Фиксированное значение |
| Kimi-K2 | 0.6 или 1.0 | Версии thinking/k2./k2p — 1.0, остальные — 0.6 |

**Приоритет**:
```
agent.temperature (ваша настройка) > умолчание модели > undefined
```

**Примечания**:
- Действует лишь для моделей с `capabilities.temperature = true`
- Отдельные reasoning-модели (вроде Codex) temperature не поддерживают
- При недействительности сверьтесь с документацией модели

## Как работает системный промпт (важно)

Когда вы задаёте Agent prompt — как он сочетается с поведением OpenCode по умолчанию?

### Порядок сборки промпта

При каждой отправке запроса системный промпт собирается в порядке:

```
┌─────────────────────────────────────────────────────────────┐
│  1. Промпт Agent ИЛИ промпт Provider по умолчанию (выбор)    │
│     ├─ Есть prompt → используется ваш                        │
│     └─ Нет prompt → модельный по умолчанию (вроде anthropic.txt) │
├─────────────────────────────────────────────────────────────┤
│  2. Информация об окружении + файлы инструкций (всегда)      │
│     Рабочий каталог, статус git, платформа, дата             │
│     Файлы глобальных правил AGENTS.md, CLAUDE.md и т. д.     │
└─────────────────────────────────────────────────────────────┘
```

**Главное**:
1. Промпт Agent и промпт Provider по умолчанию — **выбор одного из двух**, не сложение
2. Информация об окружении и файлы инструкций **добавляются всегда**, есть ли у Agent prompt или нет

### Промпты встроенных Agent

| Agent | Свой prompt? | Фактически используемый промпт |
|-------|--------------|-----------------|
| `build` | ❌ Нет | Provider по умолчанию |
| `plan` | ❌ Нет | Provider по умолчанию |
| `general` | ❌ Нет | Provider по умолчанию |
| `explore` | ✅ Есть | Специальный промпт (эксперт поиска файлов) |
| `title` | ✅ Есть | Специальный промпт (генерация заголовков сессий) |
| `summary` | ✅ Есть | Специальный промпт (генерация сводок сессий) |
| `compaction` | ✅ Есть | Специальный промпт (сжатие контекста) |

### Как выглядят промпты Provider по умолчанию?

Разные модели используют разные шаблоны промптов по умолчанию:

| Модель | Файл промпта | Особенности стиля |
|------|-----------|---------|
| Claude | `anthropic.txt` | Акцент на TodoWrite, спец-инструменты, сжатый вывод |
| GPT-5 | `codex_header.txt` | Специально для OpenAI Codex |
| GPT / O1 / O3 | `beast.txt` | Акцент на постоянных итерациях, сетевых исследованиях, самостоятельном решении |
| Gemini | `gemini.txt` | Адаптация под особенности Gemini |
| Trinity | `trinity.txt` | Специально для моделей Trinity |
| Остальные (Qwen и др.)| `qwen.txt` | Как Anthropic, но без TodoWrite |

> **Пояснение**: не совпавшие ни с одной выше модели используют `qwen.txt` (`PROMPT_ANTHROPIC_WITHOUT_TODO`).

::: details Смотреть пример: начало anthropic.txt
```text
You are OpenCode, the best coding agent on the planet.

You are an interactive CLI tool that helps users with software engineering tasks.
Use the instructions below and the tools available to you to assist the user.

# Tone and style
- Only use emojis if the user explicitly requests it
- Your responses should be short and concise
- Output text to communicate with the user

# Task Management
You have access to the TodoWrite tools to help you manage and plan tasks.
Use these tools VERY frequently...
```
:::

::: details Смотреть пример: начало beast.txt
```text
You are opencode, an agent - please keep going until the user's query
is completely resolved, before ending your turn and yielding back to the user.

You MUST iterate and keep going until the problem is solved.

THE PROBLEM CAN NOT BE SOLVED WITHOUT EXTENSIVE INTERNET RESEARCH.
You must use the webfetch tool to recursively gather all information...
```
:::

### Что это значит для собственных Agent?

**Резюме одной фразой**: тело md-файла Agent и есть написанный вами системный промпт, OpenCode не подмешивает перед ним других промптов. Он **заменяет** умолчания `anthropic.txt` или `beast.txt`, а **после него** дописываются информация об окружении и файлы инструкций.

**Сценарий 1: у вашего Agent есть prompt**

```markdown
---
description: Эксперт по ревью кода
mode: subagent
---

Вы — эксперт по ревью кода, фокус на безопасности и производительности...
```

Реально модели отправляется:
```
Вы — эксперт по ревью кода, фокус на безопасности и производительности...    ← ваш промпт (вместо умолчания)
You are powered by the model named...     ← информация об окружении
Working directory: /path/to/project       ← информация об окружении
...                                       ← содержимое AGENTS.md (если есть)
```

**Сценарий 2: у вашего Agent нет prompt**

```markdown
---
description: Универсальный помощник
mode: subagent
---
(тело пустое)
```

Реально модели отправляется:
```
You are OpenCode, the best coding agent... ← Provider по умолчанию
You are powered by the model named...       ← информация об окружении
Working directory: /path/to/project         ← информация об окружении
...                                         ← содержимое AGENTS.md (если есть)
```

> **Источники**: `session/llm.ts:67-80`,`session/system.ts:19-27`

## Создание первого Agent (способом JSON)

Настройка в `opencode.json`. Эквивалентно способу Markdown, подходит для простых Agent или перекрывающих настроек.

### Правила слияния конфигурации

Markdown и JSON можно смешивать. Если одноимённый Agent есть в обоих местах, правила такие:

1. **Приоритет JSON-конфигурации выше**: поля `opencode.json` перекрывают одноимённые поля `.md`.
2. **Сценарий**: длинные промпты обычно держат в `.md` (длинный текст удобнее), а в `opencode.json` тонко подкручивают параметры (временное отключение, смена модели).

### Пример JSON-конфигурации

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "agent": {
    "code-reviewer": {
      "description": "Эксперт по ревью кода: безопасность, производительность, поддерживаемость. Для ревью PR и проверки здоровья кода.",
      "mode": "subagent",
      "model": "anthropic/claude-sonnet-4-20250514",
      "temperature": 0.2,
      "steps": 30,
      "color": "#4CAF50",
      "prompt": "Вы — эксперт по ревью кода.\n\n## Что проверять\n- Уязвимости безопасности (SQL-инъекции, XSS, захардкоженные ключи)\n- Проблемы производительности (сложность по времени, утечки ресурсов)\n- Стиль кода (именования, структура, читаемость)\n- Поддерживаемость (связность, покрытие тестами)\n\n## Формат вывода\n- 🔴 Серьёзные проблемы (чинить обязательно, с рисками и планом исправления)\n- 🟡 Рекомендации (желательно исправить, с причинами)\n- 🟢 Плюсы (что сохранить)\n\n## Ограничения\n- ✅ Проблемы конкретно до строк\n- ✅ К каждой проблеме — рекомендация\n- ❌ Без критики без предложений"
    }
  }
}
```

### Использование внешних файлов промптов

Длинный промпт выносите во внешний файл:

```jsonc
{
  "agent": {
    "code-reviewer": {
      "description": "Эксперт по ревью кода",
      "mode": "subagent",
      "prompt": "{file:./prompts/code-reviewer.txt}"
    }
  }
}
```

> Путь считается от каталога конфигурационного файла.

## Использование Agent

### Переключение Primary Agent

Клавишей **Tab** переключайтесь между primary agent (вроде build ↔ plan).

Также работает сочетание `<Leader>+a` для списка Agent.

### Вызов Subagent

**Способ 1: ручное упоминание @**

```
@docs-writer напиши мне README
```

**Способ 2: автовызов**

Главный Agent сам выбирает подходящий subagent по описанию задачи и полю `description` subagent.

> Именно поэтому поле `description` важно — оно решает, когда Agent автовыбирается.

### Навигация сессий

Когда subagent создаёт дочернюю сессию:

| Горячие клавиши | Действие |
|--------|------|
| `<Leader>+→` | Вперёд (родитель → ребёнок1 → ребёнок2 → родитель) |
| `<Leader>+←` | Назад |
| `<Leader>+↑` | Вернуться к родительской сессии |

## Agent по умолчанию при старте

Какой primary agent используется при старте OpenCode:

```jsonc
{
  "default_agent": "plan"  // По умолчанию использовать plan agent
}
```

> Без настройки по умолчанию — `build`.
>
> Источник: `config.ts:817-821`

## Типичные проблемы

| Симптом | Причина | Решение |
|-----|-----|-----|
| Agent не появился | Неверное место файла | Убедитесь, что в каталоге `agent/`, а не `agents/` |
| Agent игнорирует инструкции | Промпт длинный или туманный | Выжмите главные правила, структурируйте |
| Неверный mode | Использовали `plan` или `build` | Должно быть `primary` / `subagent` / `all` |
| Ошибка обязательности description | Проблема версии | Формально необязательно, но заполнять рекомендуем |
| maxSteps не действует | Устарело | Используйте `steps` |
| Неверный формат color | Недопустимое значение | Используйте `#RRGGBB` или имена цветов темы (`primary`/`accent` и т. д.) |
| Имя Agent из вложенного каталога | Не знаете, как вызывать | Без `name` имя включает путь: `folder/agent-name`; с `name` — перекрывает имя по умолчанию |
