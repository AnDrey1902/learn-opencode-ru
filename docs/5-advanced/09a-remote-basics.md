# 5.9a Основы удалённого режима

> 💡 **Коротко**: OpenCode поддерживает headless-режим сервера с доступом через веб-интерфейс или удалённый терминал.

## 📝 Конспект урока

Ключевые идеи урока в сжатом виде:

<img src="/images/5-advanced/remote-basics-notes.mini.jpeg" alt="Шпаргалка урока: основы удалённого режима" data-zoom-src="/images/5-advanced/remote-basics-notes.jpeg" />

<details>
<summary>📝 Текстовая версия шпаргалки</summary>

1. Архитектура: HTTP-сервер (OpenAPI 3.1) + TUI-клиент; плюсы — мульти-клиенты, удалённый доступ, скрипты.
2. Три режима: `opencode` (TUI), `opencode serve` (API-сервер), `opencode web` (браузер).
3. Сервер: `opencode serve --port 4096 --hostname 0.0.0.0`; порт по умолчанию 4096.
4. Конфиг: server.port, server.hostname, server.mdns, server.cors.
5. Веб: `opencode web` → автооткрытие браузера; доступ localhost:4096.
6. Удалёнка: attach → подключение; `run --attach` → скрипты.
7. Прокси: HTTPS_PROXY, HTTP_PROXY, NO_PROXY (обязательно localhost,127.0.0.1).
8. Самоподписанные серты: NODE_EXTRA_CA_CERTS.
9. Ловушки: CORS → `--cors`, конфликт портов → `--port`, NO_PROXY обязателен, mDNS → hostname 0.0.0.0.

</details>

## Архитектура и принципы

При запуске `opencode` фактически стартуют два компонента:

1. **Сервер**: HTTP-сервис с REST API по спецификации OpenAPI 3.1
2. **TUI**: терминальный пользовательский интерфейс, общающийся с сервером как клиент

Плюсы такой архитектуры:
- Несколько клиентов сразу (TUI, Web, плагины IDE)
- Программное взаимодействие с OpenCode
- Удалённый доступ

```

     │   TUI   │    │   Web   │    │   IDE   │
     └─────────┘    └─────────┘    └─────────┘
```

## Три режима запуска

| Команда | Назначение | Интерфейс |
|------|------|------|
| `opencode` | Повседневная работа | TUI (автостарт локального сервера) |
| `opencode serve` | Headless-сервис | Нет (чистый API-сервис) |
| `opencode web` | Веб-доступ | Интерфейс браузера |

## Запуск headless-сервера
<AdInArticle />

### Базовая команда

```bash
opencode serve [--port <number>] [--hostname <string>] [--cors <origin>]
```

### Опции командной строки

| Параметр | Описание | По умолчанию |
|------|------|--------|
| `--port` | Порт прослушивания | `4096` |
| `--hostname` | Имя хоста прослушивания | `127.0.0.1` |
| `--mdns` | Включить обнаружение сервисов mDNS | `false` |
| `--cors` | Дополнительные разрешённые CORS-источники | `[]` |

> Источник: `opencode/packages/opencode/src/cli/network.ts:4-26`

### Примеры

```bash
# Старт с умолчаниями (порт 4096 или случайный)
opencode serve

# Указать порт и адрес для доступа по локальной сети
opencode serve --port 4096 --hostname 0.0.0.0

# Несколько разрешённых CORS-источников
opencode serve --cors http://localhost:5173 --cors https://app.example.com

# Включить обнаружение mDNS (hostname автоматически станет 0.0.0.0)
opencode serve --mdns
```

После старта выводится:

```
opencode server listening on http://0.0.0.0:4096
```

## Способ через файл конфигурации

Помимо параметров командной строки параметры сервера задаются конфигом:

```jsonc
// opencode.json
{
  "server": {
    "port": 4096,           // Порт прослушивания
    "hostname": "0.0.0.0",  // Адрес прослушивания
    "mdns": true,           // Включить mDNS
    "cors": [               // Белый список CORS
      "http://localhost:5173",
      "https://my-app.example.com"
    ]
  }
}
```

> Источник: `opencode/packages/opencode/src/config/config.ts:701-711`

**Правила приоритета**: параметры командной строки > файл конфигурации > значения по умолчанию

## Запуск веб-интерфейса

```bash
opencode web
```

Стартует HTTP-сервер и автоматически открывает браузер с веб-интерфейсом.

### Опции

Те же, что у команды `serve`:

| Параметр | Описание |
|------|------|
| `--port` | Порт прослушивания |
| `--hostname` | Имя хоста прослушивания |
| `--mdns` | Включить обнаружение mDNS |
| `--cors` | Дополнительные разрешённые CORS-источники |

### Доступ по локальной сети

При hostname `0.0.0.0` показываются все доступные адреса доступа:

```bash
opencode web --hostname 0.0.0.0 --port 4096
```

Вывод:

```
  Local access:      http://localhost:4096
  Network access:    http://192.168.1.100:4096
```

> Источник: `opencode/packages/opencode/src/cli/cmd/web.ts:41-68`

## Удалённое подключение

### Команда attach

TUI подключается к уже запущенному серверу OpenCode:

```bash
# Терминал 1: стартует бэкенд-сервер
opencode web --port 4096 --hostname 0.0.0.0

# Терминал 2: подключается с другой машины
opencode attach http://192.168.1.100:4096
```

### Опции attach

| Параметр | Коротко | Описание |
|------|------|------|
| `--dir` | | Рабочий каталог для старта TUI |
| `--session` | `-s` | ID продолжаемой сессии |

> Источник: `opencode/packages/opencode/src/cli/cmd/tui/attach.ts:4-31`

### Команда run --attach

Команда `run` тоже умеет подключаться к работающему серверу — удобно для автоматизации:

```bash
# Терминал 1: стартует headless-сервер
opencode serve

# Терминал 2: выполняет команду через attach (без холодного старта MCP)
opencode run --attach http://localhost:4096 "Объясни замыкания в JavaScript"
```

Плюс в том, что каждый запуск не поднимает MCP-серверы заново — отклик намного быстрее.

> Источник: `opencode/packages/web/src/content/docs/cli.mdx:325-333`

## Обнаружение сервисов mDNS

При включённом mDNS устройства локальной сети обращаются к серверу по `.local`-домену:

```bash
opencode web --mdns
```

Вывод:

```
  Local access:      http://localhost:4096
  Network access:    http://192.168.1.100:4096
  mDNS:              opencode.local
```

**Примечания**:
- mDNS действует лишь при не-loopback hostname
- Реально публикуемое mDNS-имя имеет вид `opencode-{port}`
- Сеть обязана поддерживать mDNS (большинство домашних и офисных сетей поддерживают)

> Источник: `opencode/packages/opencode/src/server/server.ts:2853-2862`

## Настройка сетевого прокси

OpenCode поддерживает стандартные переменные окружения прокси:

```bash
# HTTPS-прокси (рекомендуется)
export HTTPS_PROXY=https://proxy.example.com:8080

# HTTP-прокси
export HTTP_PROXY=http://proxy.example.com:8080

# Адреса в обход прокси (локальные адреса обязательны)
export NO_PROXY=localhost,127.0.0.1
```

> ⚠️ **Важно**: общение TUI с локальным сервером обязано идти мимо прокси, иначе соединение упадёт.

### Аутентификация прокси

Если прокси требует аутентификацию — credentials в URL:

```bash
export HTTPS_PROXY=http://username:password@proxy.example.com:8080
```

> ⚠️ Не хардкодьте пароли в скриптах — пользуйтесь переменными окружения или безопасными хранилищами credentials.

> Источник: `opencode/packages/web/src/content/docs/network.mdx:10-45`

## Свои сертификаты

В корпоративных окружениях с самоподписанным CA-сертификатом настройте доверие Node.js:

```bash
export NODE_EXTRA_CA_CERTS=/path/to/ca-cert.pem
```

Действует и на подключения через прокси, и на прямые обращения к API.

> Источник: `opencode/packages/web/src/content/docs/network.mdx:49-57`

## Вход в документацию API

Сервер публикует спецификацию OpenAPI 3.1 — смотрите в браузере:

```
http://<hostname>:<port>/doc
```

Например: `http://localhost:4096/doc`

Пригодится для:
- просмотра всех доступных API
- генерации клиентского кода
- исследований в инструментах Swagger

Полный справочник API — в разделе [5.9b Справочник API](./09b-remote-api).

## Типичные проблемы

| Симптом | Причина | Решение |
|-----|-----|-----|
| Удалёнка не коннектится | Блокирует файрвол | Откройте нужный порт (например, 4096) |
| Ошибка CORS | Не настроен источник | Добавьте `--cors <your-origin>` или в конфиг |
| Конфликт портов | Порт по умолчанию занят | Укажите другой порт через `--port` |
| Локальное подключение падает | Прокси перехватывает локальные запросы | Задайте `NO_PROXY=localhost,127.0.0.1` |
| mDNS не работает | hostname — loopback-адрес | Используйте `--hostname 0.0.0.0` |
| Ошибка HTTPS-сертификата | Корпоративный самоподписанный сертификат | Задайте `NODE_EXTRA_CA_CERTS` |
