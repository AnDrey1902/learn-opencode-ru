## Начало пилота

<AdInArticle />

OpenCode — опенсорс и не хранит код или данные контекста, команда может сразу начинать пилот.

### Обработка данных

**OpenCode не хранит ваш код и данные контекста.** Вся обработка идёт локально либо прямыми API-вызовами к выбранному вами AI-провайдеру.

Значит, с доверенным провайдером или внутренним AI-шлюзом OpenCode можно использовать безопасно.

### Отключение функции шаринга

Единственное, за чем стоит следить, — опциональная функция `/share`. Если пользователь включает шаринг, данные диалога отправляются на хостинг opencode.ai.

**Для корпоративного пилота рекомендуем отключить:**

```jsonc
// opencode.json
{
  "$schema": "https://opencode.ai/config.json",
  "share": "disabled"
}
```

Опции конфигурации `share`:

| Значение | Описание |
|---|-----|
| `"manual"` | Ручной шаринг (по умолчанию) |
| `"auto"` | Автошаринг новых сессий |
| `"disabled"` | Полное отключение шаринга |

> **Источник**: config.ts:790-795

### Владение кодом

**Весь созданный OpenCode код принадлежит вам.** Никаких лицензионных ограничений и claims на владение.

## Production-деплой

После пилота посетите [сайт OpenCode](https://opencode.ai) для обсуждения цен и плана внедрения.

### Централизованная конфигурация

Корпоративная версия задаёт единую централизованную конфигурацию на всю организацию.

Централизованная конфигурация умеет:

- интегрироваться с SSO-провайдером организации
- гарантировать, что все пользователи ходят только во внутренний AI-шлюз

### Интеграция SSO

Через централизованную конфигурацию OpenCode интегрируется с SSO-провайдером организации для аутентификации.

Так OpenCode получает credentials внутреннего AI-шлюза через существующую систему управления доступом.

### Внутренний AI-шлюз

Централизованная конфигурация также заставляет OpenCode использовать только внутренний AI-шлюз.

Можно отключить всех остальных AI-провайдеров, чтобы все запросы шли только через одобренную организацией инфраструктуру.

### Собственный хостинг

> ⚠️ **Функция в дорожной карте**

Хотя для гарантии невыхода данных из организации рекомендуем отключать страницу шаринга, корпоративная версия поможет самостоятельно хостить страницу шаринга на вашей инфраструктуре.

По необходимости посетите [сайт OpenCode](https://opencode.ai) для связи.

## Конфигурация корпоративного окружения

### Конфиг enterprise.url

Единственный собственный параметр корпоративной версии:

```jsonc
// opencode.json
{
  "$schema": "https://opencode.ai/config.json",
  "enterprise": {
    "url": "https://your-company.opencode.internal"
  }
}
```

Этот URL используется корпоративными функциями вроде сервиса шаринга.

> **Источник**: config.ts:922-926

### Приватный NPM-реестр

OpenCode нативно поддерживает файлы `.npmrc` через Bun для работы с приватными npm-реестрами.

Если организация использует JFrog Artifactory, Nexus и подобные приватные реестры, убедитесь, что разработчики прошли аутентификацию до запуска OpenCode.

**Вход в приватный реестр:**

```bash
npm login --registry=https://your-company.jfrog.io/api/npm/npm-virtual/
```

Это создаст credentials в `~/.npmrc`, и OpenCode подхватит их автоматически.

**Ручная настройка `.npmrc`:**

```bash
# ~/.npmrc
registry=https://your-company.jfrog.io/api/npm/npm-virtual/
//your-company.jfrog.io/api/npm/npm-virtual/:_authToken=${NPM_AUTH_TOKEN}
```

> ⚠️ **Важно**: сначала вход разработчиков в приватный реестр, потом запуск OpenCode.

<summary>Что такое корпоративная версия OpenCode?</summary>

</details>

<details>
<summary>Как начать пользоваться корпоративной версией?</summary>

## Типичные проблемы

| Симптом | Причина | Решение |
|-----|-----|-----|
| В пилоте шаринг всё ещё доступен | По умолчанию `"manual"` | Задайте `"share": "disabled"` в `opencode.json` |
| Установка npm-пакетов падает | Нет входа в приватный реестр | Сначала выполните вход командой `npm login` |
| Не найти параметры корпоративной версии | Конфигурацией управляет централизованная конфигурация | Запросите конфигурацию у администратора предприятия |
