# Сводка экспериментальных функций

> Экспериментальные функции OpenCode активно разрабатываются и могут измениться в любой момент. Страница сводит все доступные экспериментальные функции и способы их включения.

---

## Что такое экспериментальные функции?

Экспериментальные функции — новые возможности, разрабатываемые командой OpenCode и отдаваемые пользователям заранее для опыта и обратной связи до официального релиза.

**Особенности**:
- Функции могут быть недоделаны
- API может измениться в любой момент
- Отдельным функциям нужны дополнительные зависимости

**Принципы включения**:
- Включайте по необходимости, всё сразу не нужно
- При проблемах сначала отключите
- Следите за журналом изменений

---

## Быстрое включение

### Способ 1: включить всё одним махом

```bash
# macOS и Linux: добавьте в ~/.zshrc или ~/.bashrc
export OPENCODE_EXPERIMENTAL=true

# Затем перезагрузите
source ~/.zshrc
```

### Способ 2: включать точечно отдельные функции

```bash
# Включайте только нужные функции
export OPENCODE_EXPERIMENTAL_LSP_TOOL=true
export OPENCODE_EXPERIMENTAL_PLAN_MODE=true
export OPENCODE_EXPERIMENTAL_CODE_MODE=true
export OPENCODE_EXPERIMENTAL_BACKGROUND_SUBAGENTS=true
```

## Список экспериментальных функций

### 🌐 Веб-поиск

| Переменная | Описание | Связанный урок |
|------|------|---------|
| `OPENCODE_ENABLE_EXA` | Включить инструмент websearch, чтобы AI искал в интернете | [5.23 Поиск и чтение веба](../5-advanced/23-web-search) |

**Как включить**:
```bash
export OPENCODE_ENABLE_EXA=true
```

**Сценарии использования**:
- Запросы свежих технических документов и использования API
- Поиск решений по текстам ошибок
- Изучение свежих версий библиотек

При хостед-моделях OpenCode Zen веб-поиск уже включён автоматически, настраивать не нужно.
:::

### 🔧 Усиление LSP

| Переменная | Описание | Связанный урок |
|------|------|---------|
| `OPENCODE_EXPERIMENTAL_LSP_TOOL` | Включить инструмент LSP (переходы к определениям, поиск ссылок и др.) | [5.19 Кодовый интеллект LSP](../5-advanced/19-lsp) |
| `OPENCODE_EXPERIMENTAL_LSP_TY` | Включить экспериментальный Python-сервер ty (вместо pyright) | [5.19 Кодовый интеллект LSP](../5-advanced/19-lsp) |

**Как включить**:
```bash
export OPENCODE_EXPERIMENTAL_LSP_TOOL=true
export OPENCODE_EXPERIMENTAL_LSP_TY=true
```

**Сценарии использования**:
- Пусть AI выполняет операции «перейти к определению» и «найти все ссылки»
- В Python-проектах — более быстрая проверка типов

### 📋 Усиление процессов

| Переменная | Описание | Связанный урок |
|------|------|---------|
| `OPENCODE_EXPERIMENTAL_PLAN_MODE` | Открыть в CLI экспериментальный инструмент `plan_exit` | [3.1 Планирование и сборка](../3-workflow/01-plan-build) |

**Как включить**:
```bash
export OPENCODE_EXPERIMENTAL_PLAN_MODE=true
```

**Сценарии использования**:
- Крупные задачи рефакторинга: сначала AI исследует и планирует, проверяете — затем выполняется
- Не уверены в лучшем решении: сначала планируете несколько вариантов, выбираете — затем действуете
- Нужна ручная проверка: файлы планов сохраняются, ими делятся и их итерируют

> Agent Build и Plan существуют независимо от переменной — переключать Agent можно вручную всегда. Переменная лишь управляет попаданием `plan_exit` в список инструментов CLI.

**Новые инструменты**:
- `plan_exit`: Plan Agent завершил план — спрашивает, переключаться ли в Build

В целевой версии нет инструмента `plan_enter`. Вход в Plan Agent — клавишей <kbd>Tab</kbd> или настроенной клавишей переключения Agent.

### Режим MCP Code

| Переменная | Описание | Связанный урок |
|------|------|---------|
| `OPENCODE_EXPERIMENTAL_CODE_MODE` | Включить ограниченный оркестрирующий инструмент MCP `execute` | [5.7b MCP: продвинутый уровень](../5-advanced/07b-mcp-advanced) |

**Как включить**:
```bash
export OPENCODE_EXPERIMENTAL_CODE_MODE=true
```

`execute` появляется, только если флаг включён И хотя бы один MCP-инструмент видим в правах текущего Agent и сессии. Он выполняет код ограниченного интерпретатора и видит только каталогизированные видимые MCP-инструменты; shell им не заменить, каждый вызов MCP всё равно проходит проверку прав исходного инструмента.

Источник: [флаги рантайма](https://github.com/anomalyco/opencode/blob/v1.18.22/packages/opencode/src/effect/runtime-flags.ts#L48),[условия видимости `execute`](https://github.com/anomalyco/opencode/blob/v1.18.22/packages/opencode/src/tool/registry.ts#L280-L308),[ограниченная среда выполнения](https://github.com/anomalyco/opencode/blob/v1.18.22/packages/opencode/src/tool/code-mode.ts#L239-L274).

### Фоновые под-агенты

| Переменная | Описание |
|------|------|
| `OPENCODE_EXPERIMENTAL_BACKGROUND_SUBAGENTS` | Разрешить `task` с `background: true` и увод работающих синхронных под-агентов в фон |

**Как включить**:
```bash
export OPENCODE_EXPERIMENTAL_BACKGROUND_SUBAGENTS=true
```

Флаг управляет лишь фоновыми способностями. Могут ли под-агенты запускать под-агентов — решает корневой `subagent_depth`, по умолчанию `1`: главный Agent запускает один уровень под-агентов, а под-агент дальше под-агентов не запускает:

```jsonc
{
  "subagent_depth": 2
}
```

Перед повышением глубины убедитесь в границах прав и стоимости задач; при достижении лимита `task` упадёт сразу с ошибкой, а не тихо деградирует.

Источники: [флаг фонового эксперимента](https://github.com/anomalyco/opencode/blob/v1.18.22/packages/opencode/src/effect/runtime-flags.ts#L43),[фоновые проверки и лимит глубины](https://github.com/anomalyco/opencode/blob/v1.18.22/packages/opencode/src/tool/task.ts#L96-L115),[Schema `subagent_depth`](https://github.com/anomalyco/opencode/blob/v1.18.22/packages/core/src/v1/config/config.ts#L84-L86).

### 🗂️ Управление рабочими областями

| Переменная | Описание |
|------|------|
| `OPENCODE_EXPERIMENTAL_WORKSPACES` | Включить поддержку рабочих областей (Workspaces) в TUI |

**Как включить**:
```bash
export OPENCODE_EXPERIMENTAL_WORKSPACES=1
```

**Сценарии использования**:
- Параллельная разработка нескольких проектов и репозиториев
- Переключение веток через Git Worktree
- Изоляция контекстов разных задач

**Действия в TUI**:
- Введите `/workspaces` для списка рабочих областей
- Или нажмите `Ctrl+P` для палитры команд → введите "workspace"
- Рабочие области создаются, переключаются и удаляются

**Поддерживаемые сейчас типы рабочих областей**:
| Тип | Описание |
|------|------|
| `worktree` | Git Worktree (разные ветки одного репозитория) |

### ⏱️ Тайм-ауты и лимиты

| Переменная | Тип | Описание |
|------|------|------|
| `OPENCODE_EXPERIMENTAL_BASH_DEFAULT_TIMEOUT_MS` | number | Тайм-аут Bash-команд по умолчанию (миллисекунды) |
| `OPENCODE_EXPERIMENTAL_OUTPUT_TOKEN_MAX` | number | Максимум выходных токенов ответов LLM |

**Пример**:
```bash
# Тайм-аут bash — 2 минуты
export OPENCODE_EXPERIMENTAL_BASH_DEFAULT_TIMEOUT_MS=120000

# Лимит вывода LLM — 8192 токена
export OPENCODE_EXPERIMENTAL_OUTPUT_TOKEN_MAX=8192
```

## Конфигурация experimental в opencode.json

Помимо переменных окружения в `opencode.json` есть поле `experimental` для другого класса экспериментальных функций:

```json
{
  "experimental": {
    "batch_tool": true,           // Включить инструмент пакетных операций
    "openTelemetry": true,        // Включить трассировку OpenTelemetry
    "disable_paste_summary": true, // Отключить автосуммирование при вставке больших кусков текста
    "continue_loop_on_deny": true, // Продолжать мышление при отказе в инструменте
    "primary_tools": ["tool1"],   // Инструменты только для Primary Agent
    "mcp_timeout": 30000          // Тайм-аут запросов MCP (миллисекунды)
  }
}
```

| Поле | Описание |
|------|------|
| `batch_tool` | Включить пакетный инструмент для операций за раз |
| `openTelemetry` | Включить OpenTelemetry для мониторинга производительности и трассировки связей |
| `disable_paste_summary` | При вставке больших кусков текста не создавать автосуммирование |
| `continue_loop_on_deny` | При отказе пользователя в вызове инструмента Agent продолжает думать, а не прерывается |
| `primary_tools` | Список инструментов только для Primary Agent |
| `mcp_timeout` | Глобальный тайм-аут запросов MCP (миллисекунды) |

## Полный пример конфигурации

Ниже пример «всеохватной» экспериментальной конфигурации — копируйте по необходимости:

```bash
# ═══════════════════════════════════════════════════════════════
# Конфигурация экспериментальных функций OpenCode
# Добавьте в ~/.zshrc или ~/.bashrc, затем source
# ═══════════════════════════════════════════════════════════════

# Одним махом все экспериментальные функции (отдельные флаги ниже входят автоматически)
# export OPENCODE_EXPERIMENTAL=true

# ───────────────────────────────────────────────────────────────
# Веб-поиск (нужен Exa API, либо авто включено на Zen-моделях)
# ───────────────────────────────────────────────────────────────
export OPENCODE_ENABLE_EXA=true           # Включить инструмент websearch

# ───────────────────────────────────────────────────────────────
# LSP (протокол языковых серверов): усиление
# ───────────────────────────────────────────────────────────────
export OPENCODE_EXPERIMENTAL_LSP_TOOL=true  # Включить инструмент LSP
export OPENCODE_EXPERIMENTAL_LSP_TY=true    # Включить экспериментальный Python-сервер ty

# ───────────────────────────────────────────────────────────────
# Интерфейс и взаимодействие
# ───────────────────────────────────────────────────────────────
export OPENCODE_EXPERIMENTAL_MARKDOWN=true         # Экспериментальный рендер Markdown
export OPENCODE_EXPERIMENTAL_ICON_DISCOVERY=true   # Автообнаружение иконок проектов

# ───────────────────────────────────────────────────────────────
# Усиление процессов
# ───────────────────────────────────────────────────────────────
export OPENCODE_EXPERIMENTAL_PLAN_MODE=true  # Открыть инструмент plan_exit в CLI
export OPENCODE_EXPERIMENTAL_CODE_MODE=true  # Включить ограниченный оркестрирующий MCP-инструмент
export OPENCODE_EXPERIMENTAL_BACKGROUND_SUBAGENTS=true  # Включить фоновых под-агентов

# ───────────────────────────────────────────────────────────────
# Управление рабочими областями
# ───────────────────────────────────────────────────────────────
export OPENCODE_EXPERIMENTAL_WORKSPACES=1    # Включить поддержку рабочих областей TUI

# ───────────────────────────────────────────────────────────────
# Производительность и форматирование
# ───────────────────────────────────────────────────────────────
export OPENCODE_EXPERIMENTAL_OXFMT=true      # Включить форматтер oxfmt

# ───────────────────────────────────────────────────────────────
# Тайм-ауты и лимиты (необязательно)
# ───────────────────────────────────────────────────────────────
# export OPENCODE_EXPERIMENTAL_BASH_DEFAULT_TIMEOUT_MS=120000
# export OPENCODE_EXPERIMENTAL_OUTPUT_TOKEN_MAX=8192
```

## Частые вопросы

### Включил, но эффекта нет?

1. **Убедитесь, что конфигурация перезагружена**:
   ```bash
   source ~/.zshrc  # или source ~/.bashrc
   ```

2. **Убедитесь, что OpenCode перезапущен**: переменные окружения читаются при старте процесса

3. **Проверьте, что переменная задана**:
   ```bash
   env | grep OPENCODE
   ```

### Работает нестабильно?

Экспериментальные функции могут глючить:
- Смотрите [журнал изменений](../changelog/), что изменилось
- При проблемах сначала отключите функцию
- Сообщайте в [GitHub Issues](https://github.com/anomalyco/opencode/issues)

### Как отключить отдельную функцию?

Без общего флага `OPENCODE_EXPERIMENTAL` достаточно убрать или закомментировать нужную переменную. При `OPENCODE_EXPERIMENTAL=true` незаданные точечные переменные откатываются к общему флагу — тогда явно задайте `false` или выключите общий флаг:
```bash
export OPENCODE_EXPERIMENTAL_PLAN_MODE=false
# или уберите/выключите OPENCODE_EXPERIMENTAL=true
```
