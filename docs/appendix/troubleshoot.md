## Логи и места хранения

### Файлы логов

| Платформа | Путь |
|------|------|
| macOS/Linux | `~/.local/share/opencode/log/` |
| Windows | `%USERPROFILE%\.local\share\opencode\log\` |

Файлы логов именуются метками времени (вроде `2025-01-09T123456.log`), хранятся последние 10 штук.

```bash
# Свежий лог
ls -lt ~/.local/share/opencode/log/ | head

# Включить debug-лог
opencode --log-level DEBUG

# Печатать логи в терминал
opencode --print-logs
```

### Места хранения

| Тип данных | Путь |
|----------|------|
| Файлы конфигурации | `~/.config/opencode/opencode.json` |
| Credentials аутентификации | `~/.local/share/opencode/auth.json` |
| Логи | `~/.local/share/opencode/log/` |
| Данные проектов | `~/.local/share/opencode/storage/` |
| Кэш | `~/.cache/opencode/` |

## Проблемы старта

### Не стартует, команда не найдена

**Симптомы**:
```
zsh: command not found: opencode
```

**Шаги диагностики**:

```bash
# 1. Проверьте установку
which opencode
npm list -g opencode-ai

# 2. Проверьте PATH
echo $PATH | tr ':' '\n' | grep -E "(npm|bin)"
```

**Решения**:

```bash
# Переустановка
npm install -g opencode-ai

# Ручное добавление в PATH
echo 'export PATH="$HOME/.npm-global/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
```

---

### Падение при старте, белый экран

**Симптомы**: сразу после старта выход или пустой экран

**Шаги диагностики**:

```bash
# 1. Смотрим лог ошибок
opencode --print-logs 2>&1 | head -50

# 2. Чистим кэш и пробуем снова
rm -rf ~/.cache/opencode
opencode

# 3. Сбрасываем конфигурацию
mv ~/.config/opencode/opencode.json ~/.config/opencode/opencode.json.bak
opencode
```

**Частые причины**:
- Ошибка синтаксиса в конфиге
- Несовместимый терминал
- Битый кэш

---

### ProviderInitError

**Симптомы**:
```
ProviderInitError: Failed to initialize provider
```

**Шаги диагностики**:

```bash
# 1. Проверяем конфигурацию провайдера
opencode auth list

# 2. Чистим хранилище и пробуем снова
rm -rf ~/.local/share/opencode
```

**Решения**:

1. Убедитесь в верной настройке по [гиду провайдеров](./providers)
2. Настройтесь заново через `/connect`

### Ошибка аутентификации GitHub Copilot

**Симптомы**:
```
Error: 403 Forbidden
Please reauthenticate with the copilot provider to ensure
your credentials work properly with OpenCode.
```

**Причина**: OAuth-токен GitHub Copilot протух или недействителен.

**Решение**:

```bash
# Повторная аутентификация GitHub Copilot
opencode auth login
# Выберите провайдера github-copilot и пройдите OAuth-процесс
```

При GitHub Enterprise:

```bash
# Укажите Enterprise URL в конфигурации
{
  "provider": {
    "github-copilot": {
      "options": {
        "enterpriseUrl": "https://github.your-company.com"
      }
    }
  }
}
```

## Проблемы моделей

### AI_APICallError

**Симптомы**:
```
AI_APICallError: API call failed
```

**Шаги диагностики**:

```bash
# 1. Проверяем сеть
curl -I https://api.anthropic.com

# 2. Чистим кэш пакетов провайдера
rm -rf ~/.cache/opencode

# 3. Перезапускаем opencode
```

**Частые причины**:
- Проблемы сети
- Недействительный API-ключ
- Устаревшая версия пакета провайдера

---

### ProviderModelNotFoundError

**Симптомы**:
```
ProviderModelNotFoundError: Model not found
```

**Причина**: неверный формат ссылки на модель

**Верный формат**: `<providerId>/<modelId>`

**Примеры**:
- `anthropic/claude-sonnet-4-20250514`
- `openai/gpt-4o`
- `deepseek/deepseek-chat`

**Решение**:

```bash
# Посмотреть доступные модели
opencode models
```

---

### Пустые ответы модели

**Симптомы**: AI не отвечает или ответ пуст

**Возможные причины**:
1. Слишком длинный контекст обрезан
2. Сработал фильтр контента
3. Перегрузка модели

**Решения**:

```
# Сжать контекст
/compact

# Новая сессия
/new

# Сменить модель
/models
```

## Механизм ретраев API

При временных ошибках вроде `Too Many Requests` и `Provider is overloaded` OpenCode ретраит сам — вручную делать ничего не нужно.

### Стратегия ретраев

| Параметр | Значение | Описание |
|------|-----|------|
| Начальная задержка | 2 секунды | Время ожидания первого ретрая |
| Коэффициент роста | 2x | Каждый ретрай удваивает задержку |
| Максимум задержки (без заголовков ответа) | 30 секунд | Верхний предел, когда провайдер не вернул заголовок `Retry-After` |
| Максимум задержки (с заголовками ответа) | По заголовкам ответа | При заголовках `Retry-After` ждём по указанному провайдером времени |

::: details Расчёт задержек ретраев (когда провайдер не вернул заголовки ответа)
```
Первый ретрай: 2 секунды
Второй:   4 секунды
Третий:   8 секунд
Четвёртый:  16 секунд
Пятый:  30 секунд (достигнут предел, дальше не растёт)
```

Если провайдер вернул заголовки `Retry-After` или `Retry-After-Ms`, OpenCode ждёт по указанному провайдером времени без лимита 30 секунд.
:::

### Какие ошибки ретраятся автоматически

| Ошибка | Ретрай | Описание |
|------|---------|------|
| `Too Many Requests` (429) | ✅ Автоматически | Лимит частоты |
| `Provider is overloaded` (503) | ✅ Автоматически | Перегрузка сервиса |
| `Rate Limited` | ✅ Автоматически | Ограничение частоты |
| Переполнение контекста | ❌ Нет | Нужно сжатие или новая сессия |
| Ошибка аутентификации (401) | ❌ Нет | Нужно чинить API-ключ |
| Исчерпан бесплатный лимит | ❌ Нет | Подскажем ссылку пополнения |

::: tip
Видите, что OpenCode ждёт ретрай, — не спешите закрывать. Обычно через паузу проходит. При частых срабатываниях смените модель.
:::

## Обрезка вывода

При слишком длинном выводе инструментов OpenCode обрезает автоматически, чтобы не забивать контекст.

### Правила обрезки

| Лимит | Значение по умолчанию | Описание |
|------|--------|------|
| Максимум строк | 2 000 строк | Превышение обрезается |
| Максимум байт | 50 KB | Превышение обрезается |
| Полный вывод сохраняется | 7 дней | Обрезанные полные файлы авточистятся |

### Что вы увидите после обрезки

```
...2000+ lines truncated...

The tool call succeeded but the output was truncated.
Full output saved to: /path/to/tool-output/tool_xxx
Use Grep to search the full content or Read with offset/limit
to view specific sections.
```

Обратите внимание: обрезка не влияет на результат операции — подрезается только показ. Полное содержимое сохраняется локально в файлах.

### Как работать с обрезанным выводом

1. **Пусть AI ищет через Grep**: скажите AI «в обрезанном выводе найди xxx»
2. **Пусть AI читает частями**: AI сам возьмёт параметры `offset` и `limit` инструмента Read для постраничного просмотра
3. **Делегируйте под-агенту**: при правах на Task AI предложит отдать explore agent — так экономнее контекст

::: tip
Обрезка — нормальное поведение, а не ошибка. В большинстве случаев AI сам разбирает обрезанный вывод, вмешиваться не нужно.
:::

## Отказы в правах

### Симптомы

Действие отклонено с выводом:
```
The user rejected permission to use this specific tool call.
```

### Правила прав по умолчанию

У разных действий OpenCode разные права по умолчанию:

| Действие | Право по умолчанию | Описание |
|------|---------|------|
| Чтение обычных файлов | ✅ Разрешено | Большинство файлов читаются напрямую |
| Чтение файлов `.env` | ⚠️ С подтверждением | Защита чувствительных конфигов (API-ключи и т. д.) |
| Чтение файлов `.env.*` | ⚠️ С подтверждением | Вроде `.env.local`, `.env.production` |
| Чтение `.env.example` | ✅ Разрешено | В файлах-примерах секретов нет |
| Доступ к каталогам вне проекта | ⚠️ С подтверждением | Защита от выхода за пределы |
| Правка файлов (режим Build) | ✅ Разрешено | В режиме Build писать можно |
| Правка файлов (режим Plan) | ❌ Отклонено | В режиме Plan правка обычных файлов запрещена (кроме файлов планов) |
| Выполнение Bash-команд | ✅ Разрешено | По умолчанию разрешено |

### Решения

**Разовое разрешение**: в запросе права нажмите `y`

**Разрешать всегда**: нажмите `a` — в этой сессии однотипные действия больше не спрашивают

**Изменить конфигурацию**: задайте политику прав в `opencode.json`

```json
{
  "permission": {
    "read": "allow",
    "edit": "allow",
    "bash": "ask"
  }
}
```

Отдельным шаблонам файлов:

```json
{
  "permission": {
    "read": {
      "*": "allow",
      "*.env": "allow"
    }
  }
}
```

## Проблемы сети

### Тайм-ауты подключений

**Симптомы**:
```
ETIMEDOUT / ECONNREFUSED / ECONNRESET
```

**Шаги диагностики**:

```bash
# 1. Базовая сеть
ping api.anthropic.com

# 2. HTTPS
curl -v https://api.anthropic.com

# 3. Через прокси
curl -x http://127.0.0.1:7890 https://api.anthropic.com
```

**Решения**:

```bash
# Настроить прокси
export HTTP_PROXY=http://127.0.0.1:7890
export HTTPS_PROXY=http://127.0.0.1:7890

# Или доступные напрямую модели
/connect  # Выберите Z.AI
```

---

### Ошибки SSL и TLS

**Симптомы**:
```
UNABLE_TO_VERIFY_LEAF_SIGNATURE
CERT_HAS_EXPIRED
```

**Решения**:

```bash
# Корпоративный сертификат
export NODE_EXTRA_CA_CERTS=/path/to/cert.pem

# Временно отключить проверку (не для production)
export NODE_TLS_REJECT_UNAUTHORIZED=0
```

## Проблемы файловых операций

### Не удаётся записать файл

**Симптомы**: AI говорит, что изменил файл, но фактически ничего не поменялось

**Шаги диагностики**:

```bash
# 1. Права на файл
ls -la path/to/file

# 2. Настройки прав OpenCode
cat ~/.config/opencode/opencode.json | jq .permission
```

**Решения**:
- Убедитесь, что файл записываемый
- Проверьте настройку прав `allow` или `ask`
- В запросе права нажмите `y`

---

### Не работает откат Git

**Симптомы**: `/undo` без эффекта

**Шаги диагностики**:

```bash
# Убедитесь, что это Git-репозиторий
git status
```

**Решения**:
- Работайте в Git-репозитории
- Убедитесь в наличии откатываемых изменений

## Специфика Linux

### Не работает буфер обмена

**Симптомы**: не копируется и не вставляется

**Решения**:

```bash
# X11
sudo apt install xclip
# или
sudo apt install xsel

# Wayland
sudo apt install wl-clipboard
```

---

### Не хватает прав на установку npm (EACCES)

**Симптомы**:
```
EACCES: permission denied
```

**Решения**:

```bash
# Починить права npm
mkdir ~/.npm-global
npm config set prefix '~/.npm-global'
echo 'export PATH=~/.npm-global/bin:$PATH' >> ~/.bashrc
source ~/.bashrc

# Переустановить
npm install -g opencode-ai
```

## Быстрый чек-лист диагностики

При проблемах идите по списку по порядку:

- [ ] **Проверьте версию**: `opencode --version` — точно свежая?
- [ ] **Проверьте конфигурацию**: синтаксис `opencode.json` верный? (проверьте формат JSON через `jq .`)
- [ ] **Проверьте аутентификацию**: `opencode auth list` — API-ключ действителен? OAuth не протух?
- [ ] **Проверьте квоты**: хватает ли баланса счёта? Нет ли лимитов частоты?
- [ ] **Проверьте сеть**: доступен ли API провайдера? (проверьте через `curl`)
- [ ] **Проверьте права**: хватает ли прав доступа к файлам и каталогам?
- [ ] **Смотрите логи**: включите debug-режим для подробных логов

```bash
# Быстрая тройка диагностики
opencode --version
opencode auth list
opencode --log-level DEBUG --print-logs
```

## Шпаргалка кодов ошибок

### HTTP-ошибки провайдеров

| Код ошибки | Смысл | Возможные причины | Авторетрай |
|--------|------|---------|-------------|
| 400 | Неверный формат запроса | Недействительные параметры, нет обязательных полей | ❌ |
| 401 | Ошибка аутентификации | Недействительный или просроченный API-ключ | ❌ |
| 403 | Недостаточно прав | Нет прав на эту модель | ❌ |
| 404 | Ресурс не существует | Неверное имя модели или снята с обслуживания | ⚠️ OpenAI иногда ложно срабатывает |
| 413 | Слишком большое тело запроса | Переполнение контекста (Cerebras/Mistral) | ❌ |
| 429 | Слишком много запросов | Сработал лимит частоты или квоты | ✅ |
| 2000+ | Ошибки сервера | Внутренние ошибки провайдера | ✅ |
| 503 | Сервис недоступен | Обслуживание или перегрузка провайдера | ✅ |

### Внутренние ошибки OpenCode

| Тип ошибки | Смысл | Решение |
|---------|------|---------|
| `ContextOverflowError` | Переполнение контекста | Сожмите через `/compact` или создайте сессию через `/new` |
| `AI_APICallError` | Ошибка вызова API | Проверьте сеть и аутентификацию |
| `ProviderInitError` | Ошибка инициализации провайдера | Проверьте конфигурацию и аутентификацию |
| `ProviderModelNotFoundError` | Модель не существует | Проверьте формат имени модели `provider/model` |
| `RejectedError` | Пользователь отклонил право | Разрешите кнопкой `y` в запросе права |
| `DeniedError` | Действие отклонено правилами конфигурации | Проверьте конфигурацию `permission` в `opencode.json` |

### Шаблоны ошибок переполнения контекста у провайдеров

У разных провайдеров свои тексты ошибок переполнения контекста — OpenCode распознаёт едино:

| Провайдер | Шаблон текста ошибки |
|--------|-------------|
| Anthropic | `prompt is too long` |
| OpenAI | `exceeds the context window` |
| Google Gemini | `input token count exceeds the maximum` |
| DeepSeek | `maximum context length is X tokens` |
| OpenRouter | `maximum context length is X tokens` |
| Groq | `reduce the length of the messages` |
| Amazon Bedrock | `input is too long for requested model` |
| xAI (Grok) | `maximum prompt length is X` |
| GitHub Copilot | `exceeds the limit of X` |
| llama.cpp | `exceeds the available context size` |
| LM Studio | `greater than the context length` |
| Cerebras/Mistral | `400 (no body)` / `413 (no body)` |
| MiniMax | `context window exceeds limit` |
| Moonshot/Kimi | `exceeded model token limit` |
| Общий fallback | `context length exceeded` |

При этих ошибках сожмите контекст через `/compact` или создайте сессию через `/new`.
