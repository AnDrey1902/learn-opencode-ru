# A9 Авторская станция

> 💡 **Коротко**: создайте собственных авторских Agent, Skill и быстрые команды — зафиксируйте свой контентный конвейер.

## 📝 Конспект урока

Ключевые идеи урока в сжатом виде:

<img src="/images/4-scenarios/writer-workstation-notes.mini.jpeg"
     alt="Шпаргалка урока: A9 Авторская станция"
     data-zoom-src="/images/4-scenarios/writer-workstation-notes.jpeg" />

<details>
<summary>📝 Текстовая версия шпаргалки</summary>

1. Три столпа: Agent (AI-личность) + Skill (сложные инструкции) + команды (быстрые).
2. Agent писателя: каталог `.opencode/agent/`, файл = имя агента, frontmatter с mode (не agent): name, description.
3. Пример: `name: novelist`, `mode: subagent`, `temperature: 0.8`.
4. Skill: структура `skill/<название>/SKILL.md`, имена строчными (цифры, дефисы, 1–64 символа).
5. Быстрые команды: каталог `.opencode/command/`, `$ARGUMENTS` для параметров, `subtask: true` для подзадач.
6. Права: allow (грузится сразу), deny (скрыт), ask (запрос перед загрузкой).
7. Проверка: перезапуск OpenCode, Tab для переключения, проверка команд.
8. Ошибки: Agent не работает — неверный путь; ошибка frontmatter — неверные поля; Skill не найден — структура каталога; ошибка команды — синтаксис аргументов.

</details>

## Почему OpenCode, а не веб-версия AI?

| Возможность | Веб-версия AI | OpenCode |
|-----|----------|----------|
| Свои Agent | ❌ Только общий AI | ✅ Собственные образы, работают всегда |
| Быстрые команды | ❌ Каждый раз вводите заново | ✅ `/блог` — полный процесс одной командой |
| Переиспользование Skill | ❌ | ✅ Сложные инструкции — в Skill, вызов в любой момент |
| Фиксация процесса | ❌ | ✅ Процесс, стиль и шаблоны сохраняются навсегда |
| Совместное использование | ❌ | ✅ Конфиги версионируются, команда переиспользует |

**В этом высшая ценность OpenCode** — не просто пользоваться AI, а построить собственную AI-станцию.

## Основная идея

### Три элемента писательской станции

| Элемент | Роль | Пример |
|-----|------|------|
| Agent | Собственный образ AI | Agent-романист, Agent-сценарист |
| Skill | Упаковка сложных инструкций | Навыки дизайна персонажей, генерации сюжета |
| Команды | Быстрый запуск | /персонаж, /сцена, /редактура |

---

## Частые поля Agent

Поля, настраиваемые во frontmatter:

| Поле | Тип | Описание | Пример |
|-----|------|------|-------|
| `name` | строка (обязательно) | Имя Agent, имя файла и есть имя |
| `description` | строка | Описание функций Agent (показывается в меню) |
| `mode` | `"primary"` или `"subagent"` | Главный agent переключается через Tab, под-агент вызывается через @ |
| `temperature` | число (0.0–1.0) | Управляет случайностью: 0.0–0.2 — точность, 0.3–0.5 — баланс, 0.6–1.0 — креатив |
| `model` | строка | Переопределить модель по умолчанию, формат: `provider/model-id` |
| `permission` | объект | Тонкий контроль прав, например `{ "edit": "ask" }` |
| `hidden` | булево | Скрыть под-агента (не показывать в @-автодополнении) |
| `color` | hex-цвет | Свой цвет отображения Agent, например `#FF5733` |
| `steps` | положительное целое | Максимум итераций, защита от бесконечных циклов |
| `disable` | булево | `true` отключает agent |
| `options` | объект | Дополнительные опции модели для провайдера, например `reasoningEffort` у OpenAI |
| `disable` | булево | Отключить этот Agent |

> 💡 Все неперечисленные поля передаются провайдеру напрямую как опции модели (например, `reasoningEffort` у OpenAI)

## Повторите за мной

### Шаг 1: создайте писательский Agent

**Зачем**
Собственный Agent понимает ваш стиль и предпочтения.

```bash
mkdir -p ~/.config/opencode/agent
```

Создайте файл конфигурации Agent. Обратите внимание:

- **Имя файла и есть имя Agent**, например `novelist.md`
- Во frontmatter используйте поле `mode` (а не `agent`)

```bash
opencode
```

```
Создай писательский Agent и сохрани в ~/.config/opencode/agent/novelist.md со следующим содержанием:

---
name: novelist
description: Профессиональный помощник автора романов: придумывает сюжеты, проектирует персонажей, шлифует текст
mode: subagent
temperature: 0.8
---

# Agent-романист

Ты — опытный наставник по созданию романов, мастер:
- дизайна структуры историй (трёхактная структура, путь героя)
- создания персонажей (характер, мотивация, арки)
- развития сюжета (конфликты, повороты, кульминации)
- шлифовки текста (ритм, атмосфера, диалоги)

## Принципы работы
1. Сначала пойми замысел автора, потом советуй
2. Советы конкретные и применимые, с примерами
3. Уважай стиль автора, не навязывай свой
4. Поощряй новое, избегай шаблонов
```

### Шаг 2: создайте писательский Skill

<AdInArticle />

**Зачем**
Skill упаковывает сложные писательские инструкции в один вызов.

**Важно**: структура каталога Skill обязана быть `skill/<имя>/SKILL.md`

```bash
mkdir -p .opencode/skill/character-design
```

Создайте Skill дизайна персонажей:

```
Создай Skill дизайна персонажей и сохрани в .opencode/skill/character-design/SKILL.md:

> ⚠️ **Правила именования (рекомендуемые)**
> - Строчные латинские буквы, цифры, дефисы
> - Длина 1–64 символа
> - Не начинается и не заканчивается дефисом
> - Без двойных дефисов (`--`)
> - Обязано совпадать с именем каталога
>
> Рекомендуемый формат: `^[a-z0-9]+(-[a-z0-9]+)*$`

---
name: character-design
description: Генерация подробной карточки персонажа романа
---

# Навык дизайна персонажей

По заданному типу персонажа создай полную карточку.

## Формат вывода

### Базовые данные
- Имя, возраст, профессия, внешность

### Спектр характера
- 3 положительные черты
- 2 отрицательные черты

### Предыстория
- Ключевые события, сформировавшие характер

### Главная мотивация
- Внешняя цель
- Внутренняя потребность

### Арка персонажа
- Стартовое состояние → финальное состояние

### Фирменные черты
- Коронная фраза или жест
```

### Контроль прав Skill

Можно настроить, какие Skill доступны каким agent, в `opencode.json`:

```json
{
  "permission": {
    "skill": {
      "character-design": "allow",
      "internal-*": "deny",
      "*": "allow"
    }
  }
}
```

| Право | Поведение |
|------|------|
| `allow` | Skill загружается сразу |
| `deny` | Skill скрыт от agent, доступ запрещён |
| `ask` | Перед загрузкой спросить пользователя |

Поддерживаются wildcard-шаблоны: `internal-*` покрывает все skill на `internal-`.

## Продвинутые возможности Command

Кроме `$ARGUMENTS` поддерживаются продвинутые приёмы:

### Позиционные параметры

Доступ к отдельным параметрам:

| Параметр | Описание |
|-----|------|
| `$1` | Первый параметр |
| `$2` | Второй параметр |
| `$3` | Третий параметр |
| ... | И так далее |

Пример:

```md
---
description: Создать файл и записать содержимое
---

Создай файл с именем $1 в каталоге $2 со следующим содержимым:
$3
```

Запуск: `/создать-файл config.json src "{ \"key\": \"value\" }"`

### Режим подзадачи

Флаг `subtask: true` принудительно выполняет команду как подзадачу, не засоряя главный контекст.

```md
---
description: Глубокий анализ кода
subtask: true
---

Выполни глубокий анализ кода:
$ARGUMENTS
```

### Инжект вывода shell

Конструкцией `!command` подставляется вывод bash-команды в шаблон команды.

Пример: разбор результатов тестов

```md
---
description: Разобрать покрытие тестами
---

Текущие результаты тестов:
!`npm test`

Предложи план оптимизации по результатам.
```

Пример: ревью свежих изменений

```md
---
description: Проверить свежие изменения
---

Свежие коммиты Git:
!`git log --oneline -10`

Проверь и предложи улучшения.
```

## Приёмы продвинутой настройки

### Контроль прав

Agent тонко управляет доступом к инструментам и навыкам. Настройка во frontmatter agent:

```markdown
---
name: readonly-reviewer
description: Ревью кода только для чтения
permission:
  edit: deny
  bash:
    "*": ask
    "git diff": allow
    "git log*": allow
  webfetch: deny
---

Только анализируй код, не изменяй.
```

Варианты прав:
- `"ask"` — спрашивать подтверждение перед выполнением
- `"allow"` — разрешить всё без подтверждений
- `"deny"` — отключить инструмент

### Вложенные Agent

Agent можно раскладывать по подкаталогам, например:

```
.opencode/agent/
  ├── writing/
  │   ├── novelist.md
  │   └── copywriter.md
  └── coding/
      ├── frontend.md
      └── backend.md
```

::: tip 💡 Как вызываются
- **Без поля name**: система сама использует полный путь как имя Agent, например `writing/novelist`, вызов — `@writing/novelist`
- **С полем name**: перекрывает автоимя, например `name: novelist` вызывается как `@novelist`

**Рекомендация**: у Agent во вложенных каталогах не задавайте поле `name` во frontmatter — пусть система сама создаёт имена с путём, так несколько Agent проще организовать и вести.
:::

Так вызываются через `@writing/novelist` или `@coding/frontend` (при условии, что поле `name` во frontmatter не задано).

## Типичные проблемы

| Симптом | Причина | Решение |
|-----|-----|-----|
| Agent не работает | Файл конфигурации не там | Проверьте: `~/.config/opencode/agent/` или `.opencode/agent/`, имя файла и есть имя agent |
| Ошибка frontmatter Agent | Неверные поля | Во frontmatter используйте `mode`, а не `agent`; обязательные поля — `name` и `description` |
| Skill не находится | Неверная структура каталогов | Каталог обязан быть `skill/<имя>/SKILL.md` (строчными) |
| Имя Skill не по правилам | Ошибка именования | Строчные буквы и цифры, 1–64 символа, не начинать/заканчивать дефисом, без двойных дефисов |
| Ошибка команды | Ошибка синтаксиса параметров | Проверьте использование плейсхолдеров `$ARGUMENTS`, `$1` и т. д. |
