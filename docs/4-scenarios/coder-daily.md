# B1 Повседневная разработка

> 💡 **Коротко**: понимайте код через Plan Agent, пишите функции и чините баги через Build Agent.

<summary>📝 Текстовая версия шпаргалки</summary>

1. Поток разработки: понять код → составить план → реализовать → проверить тестами (Plan → Plan → Build → Build).
2. Три сценария: понимание кода (Plan), написание (Build), фикс багов (Plan → Build).
3. Синтаксис: `@путь` (вставить файл), `!команда` (выполнить в TUI), `/undo` (откат, нужен Git).
4. Быстрое понимание: `@explore` — структура проекта, `@файл` — конкретная логика.
5. План функции: Plan-агент → список файлов → 2–3 варианта реализации.
6. Реализация: Build-агент, дробить на мелкие шаги, проверять каждый.
7. Локализация бага: Plan-агент → 3–5 причин → приоритет проверки.
8. Фикс бага: Build-агент → сначала понять, потом чинить.
9. Навигация: Tab/Shift+Tab, `<leader>a`, `<leader>right/left/up`.
10. Ловушки: AI сразу пишет код — сначала Plan; функция сломалась — не пошагово; баг не найден — мало данных.

</details>

## Основная идея

### Рабочий процесс разработки

```
Понимание кода (Plan) → план решения (Plan) → реализация (Build) → проверка тестами (Build)
```

### Три типичных сценария

| Сценарий | Рекомендуемый Agent | Типичные действия |
|-----|---------|---------|
| Понять код | Plan | `@файл` для разбора, `@explore` для исследования |
| Новая функция | Build | Пошаговая реализация, итеративные правки |
| Баг | Plan → Build | Сначала найти причину, потом чинить |

### Шпаргалка по синтаксису (в уроке только эти 4)

- `@path`: подтянуть содержимое файла в диалог
- `!command`: выполнить команду в TUI и подтянуть вывод в диалог
- `/undo`: вернуться к предыдущему сообщению пользователя и откатить связанные файловые патчи (восстановлению файлов нужен Git-репозиторий)
- `/redo`: восстановить только что отменённое содержимое сессии и файлы

Полный синтаксис: https://opencode.ai/docs/tui

> Если в главной конфигурации `"snapshot": false`, `/undo` и `/redo` всё равно двигают границы сессии, но файлы не восстанавливают. Исходники: [`session/revert.ts:38-98`](https://github.com/anomalyco/opencode/blob/v1.18.22/packages/opencode/src/session/revert.ts#L38-L98),[`config.ts:52-55`](https://github.com/anomalyco/opencode/blob/v1.18.22/packages/core/src/v1/config/config.ts#L52-L55).

## Повторите за мной

### Шаг 1: быстро поймите код

**Зачем**
Первое дело при взятии проекта — разобраться в структуре.

Переключитесь на Plan Agent:

```
@explore разбери общую структуру этого проекта, включая:
1. Главные каталоги и модули
2. Точки входа и ключевые процессы
3. Технологический стек и фреймворки
```

Копните конкретный файл:

```
@src/services/auth.ts как устроена логика этого модуля аутентификации? Перечисли все экспортируемые функции и их назначение
```

### Шаг 2: спланируйте функцию

<AdInArticle />

**Зачем**
Прежде чем писать код — продумать решение.

Оставайтесь в Plan Agent:

```
Хочу добавить в проект функцию «уведомлений по почте»: после успешной регистрации пользователя отправлять приветственное письмо.
Проанализируй, пожалуйста:
1. Какие файлы нужно менять
2. Рекомендуемые варианты реализации (2–3)
3. Плюсы и минусы каждого
4. Какой вариант рекомендуешь и почему
```

### Шаг 3: реализуйте функцию по шагам

**Зачем**
Сложную функцию — маленькими шагами, меньше риск ошибок.

Переключитесь на Build Agent:

```
Реализуй функцию почтовых уведомлений по варианту один:

Шаг первый: создай модуль почтового сервиса src/services/email.ts
- Используй nodemailer
- Поддержка SMTP-настроек
- Экспортируй функцию sendEmail
```

Убедившись, что первый шаг готов:

```
Шаг второй: после успешной регистрации пользователя вызывай почтовый сервис
@src/controllers/auth.ts в функцию register после успеха добавь логику отправки приветственного письма
```

### Шаг 4: локализуйте баг

**Зачем**
Прежде чем чинить — понять проблему.

Переключитесь на Plan Agent:

```
Пользователи жалуются: «после входа страница бесконечно грузится». Проанализируй, пожалуйста:
1. Какие могут быть причины
2. Как искать (дай конкретные шаги)
3. В каком файле, скорее всего, проблема
```

### Шаг 5: почините баг

**Зачем**
Чинить — только после локализации.

Переключитесь на Build Agent:

```
@src/hooks/useAuth.ts проблема локализована здесь:
- после успешного входа isLoading не сбрасывается в false
- исправь, пожалуйста
```

## 📋 Волшебный промпт

### 🔍 Объяснение кода
> Ожидаемый эффект: ясное объяснение логики кода для понимания незнакомого кода

```
## Роль
Ты — опытный инженер по технической документации: объясняешь сложный код просто и понятно.

## Задача
Объяснить присланный код: помочь понять его функцию, принципы и потенциальные проблемы.

## Входные данные
### Обязательные
- Язык программирования: 【язык】
- Код: @【путь к файлу】 или [вставьте код]

### Необязательные
- Уровень читателя: 【начинающий/средний/продвинутый】 (по умолчанию: средний)
- Фокус: 【что особенно интересно?】

## Формат вывода
1. **Резюме одной фразой** (≤50 знаков)
2. **Разбор по блокам**: фрагмент кода (с номерами строк) + назначение + принцип
3. **Ключевые концепции**: затронутые паттерны, алгоритмы, возможности языка
4. **Потенциальные проблемы**: 🔴 серьёзные / 🟡 рекомендации / 🟢 подсказки
5. **Пример использования**: как вызывать этот код

## Ограничения
- ✅ Объясняй постепенно, от простого к сложному
- ✅ Для начинающих добавляй аналогии
- ✅ Термины оставляй на английском, объяснения — на русском
- ❌ Не ограничивайся «что делает», объясняй «почему»
- ❌ Не предполагай знание продвинутых концепций
```

### ⚡ Реализация функции
> Ожидаемый эффект: пошаговая реализация функции, каждый шаг проверяем

```
## Роль
Ты — fullstack-инженер: превращаешь требования в рабочий код.

## Задача
По описанию требований пошагово реализовать полную функцию.

## Входные данные
### Обязательные
- Описание требования: 【опишите нужную функцию】
- Язык программирования: 【язык】

### Необязательные
- Фреймворк: 【фреймворк?】
- Зависимости: 【что уже установлено?】
- Ограничения: 【требования к производительности/совместимости?】

## Формат вывода
Каждый шаг выводит:
1. **Цель шага**: что делаем на этом шаге
2. **Реализация**: полный рабочий код
3. **Способ проверки**: как убедиться, что шаг удался
4. **Анонс следующего шага**: что дальше

## Ограничения
- ✅ Код сразу запускаемый
- ✅ Нужная обработка ошибок включена
- ✅ Имена ясные и по конвенциям
- ✅ Каждый шаг ждёт подтверждения пользователя
- ❌ Не вываливать слишком много кода за раз
- ❌ Без овер-инжиниринга
```

### 🐛 Локализация бага
> Ожидаемый эффект: системный анализ и локализация первопричины

```
## Роль
Ты — senior-инженер по отладке: от симптомов идёшь к первопричине. Рассуждаешь чётко, гипотезы проверяешь строго.

## Задача
Разобрать описанный пользователем баг, локализовать возможные причины и дать план исправления.

## Входные данные
### Обязательные
- Описание проблемы: 【что происходит】
- Ожидаемое поведение: 【как должно быть】
- Фактическое поведение: 【как на самом деле】

### Необязательные
- Шаги воспроизведения: 【как воспроизвести?】
- Связанный код: @【путь к файлу?】
- Текст ошибки: 【лог ошибки?】
- Окружение: 【где запускается?】
- Что уже пробовали: 【что пробовали?】

## Формат вывода
1. **Резюме проблемы**: главная жалоба одной фразой
2. **Анализ первопричин**: по убыванию вероятности
   | № | Возможная причина | Вероятность | Основание |
3. **Способы проверки**: конкретные шаги проверки каждой причины
4. **План исправления**:
   - Временное решение: быстро остановить кровь
   - Капитальное решение: чинить полностью
   - Профилактика: чтобы не повторялось

## Ограничения
- ✅ Сортировать по вероятности, проверять самые вероятные первыми
- ✅ Способы проверки — конкретные и выполнимые
- ✅ Учитывать побочные эффекты исправлений
- ❌ Не менять слишком много за раз
- ❌ Не давать ответ без объяснения причин
```

## Переключение Agent и навигация сессий (шпаргалка сценарного урока)

- Главные Agent (`build` / `plan`): переключение через `Tab`; обратное — через `Shift+Tab`.
- Список Agent: `<leader>a` (по умолчанию leader — `ctrl+x`, то есть сначала `ctrl+x`, потом `a`).
- Навигация дочерних сессий: `Right` — следующая дочерняя сессия, `Left` — предыдущая, `Up` — назад к родителю. Эти три по умолчанию — прямо стрелками, без предварительного Leader.

Полный список горячих клавиш: [5.6b Горячие клавиши](../5-advanced/06b-keybinds).

## Типичные проблемы

| Симптом | Причина | Решение |
|-----|-----|-----|
| AI сразу правит код | Активен Build Agent | Сначала переключитесь на Plan Agent для анализа |
| Функция работает, но сломала соседнее | Не делили на шаги | Подтверждайте каждый шаг перед следующим |
| Локализация бага неточная | Мало информации | Давайте полный текст ошибки и шаги воспроизведения |
