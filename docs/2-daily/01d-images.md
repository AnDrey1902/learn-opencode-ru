## Основная идея

OpenCode предлагает три способа показать изображение AI:

1. **Вставить снимок экрана** (самый распространённый способ): после снимка нажать Ctrl+V
2. **Сослаться на локальный файл**: использовать `@путь_к_изображению` или вставить путь к файлу
3. **Создать изображение с помощью AI**: некоторые модели (например, Copilot) умеют рисовать по запросу

При любом способе в поле ввода изображение отображается виртуальной меткой вроде `[Image 1]` или `[Image 2]`. После отправки AI сможет увидеть и проанализировать его содержимое.

## Повторите за мной

### Шаг 0: способы сделать снимок на разных платформах

В разных системах используются разные сочетания клавиш для снимка экрана. Выберите подходящий вариант:

| Система | Область экрана | Весь экран | Окно |
|------|---------|---------|---------|
| **Windows** | `Win + Shift + S` | `PrtScn` | `Alt + PrtScn` |
| **macOS** | `Cmd + Shift + 4` | `Cmd + Shift + 3` | `Cmd + Shift + 4`, затем пробел |
| **Linux (GNOME)** | `PrtScn`, выбрать область | `PrtScn` | `Alt + PrtScn` |
| **Linux (KDE)** | `Meta + Shift + S` | `PrtScn` | `Meta + PrtScn` |

::: tip Куда попал снимок?
- **Windows**: после снимка изображение оказывается в буфере обмена, а в правом нижнем углу появляется предварительный просмотр;
- **macOS**: по умолчанию снимок сохраняется на рабочий стол, но `Ctrl + Cmd + Shift + 4` сразу копирует его в буфер обмена;
- **Linux**: зависит от окружения рабочего стола — обычно изображение копируется в буфер или появляется диалог сохранения.
:::

---

### Шаг 1: сделайте снимок и вставьте его

**Действия**
1. Сделайте снимок сочетанием из таблицы выше (рекомендуется снимок области, содержащий только нужное содержимое).
2. Вернитесь в поле ввода OpenCode.
3. Нажмите `Ctrl+V`.

**Вы должны увидеть**
- в поле ввода появилась метка `[Image 1]`;
- до и после метки можно ввести описание.

```
┌─────────────────────────────────────┐
│  Проанализируй эту ошибку [Image 1]        │
└─────────────────────────────────────┘
```

**Зачем**  
OpenCode автоматически обнаруживает изображение в буфере обмена, преобразует его в формат base64 и отправляет AI.

---

### Шаг 2: установите инструмент буфера обмена в Linux (если требуется)

**Когда это нужно**  
Если после `Ctrl+V` **не появилась** метка `[Image 1]` и вы используете Linux, установите инструмент буфера обмена.

**Зачем**  
Графическим протоколам X11/Wayland в Linux нужны дополнительные инструменты для чтения изображений из буфера обмена.

**Действия**

Сначала проверьте тип сервера отображения:
```bash
echo $XDG_SESSION_TYPE
```

Затем установите инструмент в зависимости от результата:

::: code-group

```bash [X11(дисплей x11)]
sudo apt install xclip
# или
sudo apt install xsel
```

```bash [Wayland(дисплей wayland)]
sudo apt install wl-clipboard
```

:::

::: tip xsel как запасной вариант
Если xclip недоступен в вашей системе, для X11 можно использовать xsel.
:::

После установки **перезапустите OpenCode** и снова попробуйте `Ctrl+V`.

**Вы должны увидеть**
- после установки `Ctrl+V` корректно вставляет изображение;
- в поле ввода появляется метка `[Image 1]`.

---

### Шаг 3: сошлитесь на локальный файл изображения

**Действия**
1. Введите `@` в поле ввода.
2. Выберите путь к файлу изображения или введите путь вручную.
3. Нажмите Enter для подтверждения.

Или ещё проще:
1. Скопируйте полный путь к изображению в файловом менеджере.
2. Вставьте путь в поле ввода OpenCode.

**Вы должны увидеть**
- в поле ввода появилась метка `[Image 1]`;
- результат такой же, как при вставке снимка экрана.

---

### Шаг 4: отправьте изображение и прочитайте ответ AI

**Действия**
1. Добавьте описание вопроса до или после `[Image 1]`.
2. Нажмите `Enter`, чтобы отправить сообщение.

**Вы должны увидеть**
- AI проанализирует содержимое изображения и ответит;
- для снимка ошибки AI предложит исправление;
- для макета AI предложит улучшения.

**Пример диалога**

```
Пользователь:Что значит эта ошибка? [Image 1]

AI:Ошибка означает, что модуль не найден. Судя по скриншоту, проблема в...
```

---

### Шаг 5: удалите добавленное изображение

**Действия**
- Удалите метку `[Image 1]` в поле ввода клавишей `Backspace` или `Delete`.

**Зачем**  
Удаление виртуальной метки отменяет отправку изображения. К сообщению оно не прикрепится.

## 🚑 Устранение неполадок: Ctrl+V не вставляет изображение

Проверяйте проблему последовательно:

### Проверка 1: убедитесь, что изображение действительно в буфере обмена

**Метод проверки**:
- после снимка откройте системный текстовый редактор (Блокнот/TextEdit);
- нажмите `Ctrl+V`: если вставился текст, значит инструмент снимков скопировал текстовое описание;
- **ничего вставиться не должно** — это означает, что в буфере находится изображение.

**Если вставился текст**: инструмент снимков сохранил изображение в файл и поместил в буфер только его имя. Используйте системное сочетание клавиш для снимка (см. таблицу в шаге 0).

---

### Проверка 2: проверка для Linux

**Если это Linux и вставка не работает**:

```bash
# 1. Определяем тип дисплейного сервера
echo $XDG_SESSION_TYPE
# Вывод должен быть x11 или wayland

# 2. Проверяем, стоят ли нужные инструменты
# Пользователям X11:
which xclip
# или
which xsel

# Пользователям Wayland:
which wl-paste
```

**Если команда не найдена**: установите соответствующий инструмент (см. шаг 2).

**Если инструмент установлен, но проблема остаётся**:
- попробуйте вручную прочитать буфер, чтобы проверить работу инструмента:
  ```bash
  # X11
  xclip -selection clipboard -t image/png -o > /tmp/test.png
  # Если появился файл test.png — инструменты в порядке

  # Wayland
  wl-paste -t image/png > /tmp/test.png
  ```

---

### Проверка 3: убедитесь, что дело не в модели

**Симптом**: метка `[Image 1]` вставляется, но AI говорит, что не видит изображение.

**Причина**: используемая модель не поддерживает ввод изображений.

**Модели с поддержкой изображений** (по состоянию на март 2026 года):

| Провайдер | Модели с поддержкой изображений |
|--------|---------------|
| OpenAI | GPT-5.2,GPT-5 |
| Anthropic | Claude Opus 4.6,Claude Sonnet 4.6 |
| Google | Gemini 3.1 Pro/Flash |
| Moonshot AI | **Kimi K2.5** (рекомендуемая китайская модель) |

::: warning Внимание для китайских моделей
- **Kimi K2.5**: ✅ поддерживает изображения
- **Zhipu GLM-5, MiniMax 2.5, DeepSeek, Doubao, Qwen**: ❌ изображения не поддерживают

Если вы используете китайскую модель, рекомендуется выбрать **Kimi K2.5**.
:::

---

**Особое ограничение: размер изображений в Anthropic**

Для моделей Anthropic (Claude) установлен предел размера изображения:
- **максимум 2000 пикселей** (по ширине или высоте);
- при превышении появляется ошибка: `At least one of the image dimensions exceed max allowed size`.

**Решение**: выбирайте меньшую область при создании снимка или используйте инструмент сжатия изображений.

---

**Известная проблема: Azure GPT-5.2-Codex**

У модели `gpt-5.2-codex` в Azure сейчас есть проблема со вставкой изображений:
- после вставки появляется `[Image 1]`, но при отправке показывается «File not found: Image 1»;
- это проблема интеграции модели, не связанная с OpenCode.

**Решение**: переключитесь на обычную версию `GPT-5.2` (не Codex) или другую модель с поддержкой изображений.

---

### Проверка 4: проверьте конфликты сочетаний клавиш

**Симптом**: после `Ctrl+V` в поле ввода появляется `^V` или другие странные символы.

**Причина**: эмулятор терминала или SSH-клиент перехватывает `Ctrl+V`.

**Решение**:
- **Windows Terminal**: Настройки → Действия → убедитесь, что `Ctrl+V` назначено на «Вставить»;
- **iTerm2 (macOS)**: Preferences → Keys → проверьте привязку `Cmd+V`;
- **JetBrains IDE Terminal (macOS)**: используйте `Ctrl+V`, а не `Cmd+V`;
- **некоторые раскладки macOS** (например, русская и отдельные китайские): переключитесь на английскую раскладку и повторите попытку;
- **SSH к удалённому серверу**: на сервере тоже должен быть установлен инструмент буфера обмена либо используйте протокол OSC52 (с автоматическим откатом).

---

### Проверка 5: проблема с мультиплексором терминала

**Симптом**: копирование и вставка не работают в Zellij, tmux или screen.

**Причина**: эти мультиплексоры перехватывают последовательности буфера OSC52, из-за чего невозможно взаимодействовать с системным буфером.

**Решение**:
- временно выйдите из мультиплексора и используйте OpenCode в обычном терминале;
- либо запустите OpenCode вне мультиплексора.

**Затронутые инструменты**:
- Zellij (известная проблема)
- tmux (зависит от конфигурации)
- screen (зависит от конфигурации)

---

### Проверка 6: особенность окружения WSL

**Симптом**: в WSL/WSL2 копирование и вставка работают непредсказуемо.

**Причина**: WSL — это подсистема Linux в Windows, поэтому буфер обмена должен работать через мост между Windows и Linux.

**Решение**:
- **Вставка изображений**: WSL поддерживает вставку изображений, но при сбое попробуйте запустить OpenCode непосредственно в Windows Terminal (не внутри WSL);
- **Копирование содержимого**: текст, скопированный в WSL, обычно можно вставить в Windows, но для функций вроде общих ссылок может потребоваться дополнительная настройка;
- **Рекомендация**: если основная рабочая среда — Windows, лучше установить версию OpenCode для Windows.
