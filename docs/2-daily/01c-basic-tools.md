## Основная идея

<AdInArticle />

OpenCode предоставляет AI **10 основных инструментов**. В этом уроке мы подробно рассмотрим 6 наиболее часто используемых инструментов для работы с файлами:

| Инструмент | Назначение | Аналогия |
|------|--------|------|
| **read** | Читает файл или каталог | Открыть файл и посмотреть содержимое |
| **write** | Создаёт или перезаписывает файл | Сохранить как |
| **edit** | Точно заменяет текст в файле | Найти и заменить |
| **bash** | Выполняет команды Shell | Ввести команду в терминале |
| **grep** | Ищет файлы по содержимому | Глобальный поиск |
| **glob** | Ищет файлы по имени | Поиск имени в файловом менеджере |

Вам не нужно вызывать эти инструменты вручную. Просто опишите задачу естественным языком — AI сам выберет подходящий инструмент.

::: info Есть и другие инструменты
Помимо этих 6 инструментов для работы с файлами, в OpenCode есть:

| Инструмент | Назначение | Где изучить |
|------|------|---------|
| **Task** | Создаёт дочернего Agent для сложной задачи | [Права и безопасность Agent](/5-advanced/02c-agent-permissions) |
| **WebFetch** | Получает содержимое веб-страницы | [Поиск в интернете](/5-advanced/23-web-search) |
| **TodoWrite** | Управляет списком задач (AI использует автоматически) | — |
| **Skill** | Загружает пакет специализированных знаний | [Серия об Skill](/5-advanced/03a-skills-basics) |

**Что такое TodoWrite?**

Когда вы ставите AI сложную задачу, он может автоматически составить такой план:

```
1. [ ] 分析代码结构
2. [x] 读取配置文件
3. [ ] 修改入口文件
4. [ ] 运行测试验证
```

Это работает инструмент TodoWrite. Он создаёт список задач и отмечает пункты по мере выполнения, чтобы AI не «забыл» что-либо и не «сбился с пути». Вызывать его вручную не нужно: AI использует его при необходимости。
:::

Но знание их возможностей и ограничений поможет писать более качественные промпты и быстро находить причину проблем.

::: tip Основной принцип: каждому инструменту — своё дело
Не просите AI использовать команды bash (`cat`, `sed`, `grep`) для операций с файлами. Специализированные инструменты проверяют права, умеют обрабатывать ошибки и оптимизированы по производительности, а команды bash такой защиты не дают.
:::

## Повторите за мной

### Шаг 1: попросите AI прочитать файл

**Зачем**
read — самый базовый инструмент: AI должен сначала «увидеть» содержимое файла, чтобы проанализировать или изменить его.

Введите в OpenCode:

```
帮我看看 package.json 里有什么
```

**Вы должны увидеть**: AI вызовет read, прочитает файл и проанализирует его содержимое.

::: details 📦 Возможности инструмента read
**Основные параметры**:
- `filePath`: абсолютный путь к файлу
- `offset`: с какой строки начинать чтение (по умолчанию с первой)
- `limit`: максимальное число читаемых строк (по умолчанию 2000)

**Обработка больших файлов**: если в файле больше 2000 строк, read автоматически усечёт вывод и покажет «Use offset parameter to read beyond line 2001». AI продолжит чтение следующих строк с параметром offset.

**Особые файлы**: read также умеет читать изображения (PNG, JPG, GIF) и PDF, преобразуя их в base64 для анализа моделью AI. SVG и бинарные файлы (.zip, .exe и другие) не поддерживаются.

**Исправление опечаток**: если вы ошиблись в имени файла, read предложит похожие имена. Например, для `packge.json` он предложит `package.json`.

**Чтение каталогов**: read умеет читать не только файлы, но и каталоги. Упомяните каталог в диалоге через `@имя_каталога`, и AI получит его содержимое (список подкаталогов и файлов) в удобном для чтения формате. Это полезно, когда нужно познакомить AI со структурой проекта.
:::

### Шаг 2: попросите AI создать файл

**Зачем**
Инструмент write создаёт новые файлы или полностью перезаписывает существующие.

```
帮我创建一个 hello.txt，内容写 "Hello OpenCode"
```

**Вы должны увидеть**: AI вызовет write, создаст файл и сообщит об успешной записи.

::: warning ⚠️ Правило «сначала прочитать, потом записать»
Если файл уже существует, AI обязан сначала прочитать его через read и только затем перезаписать через write. Это защищает от случайной перезаписи без знания текущего содержимого.

Если AI пропустит чтение и сразу запишет существующий файл, OpenCode сообщит об ошибке.
:::

**Автоматическая проверка после записи**: после write автоматически запускается диагностика LSP. Если в записанном коде есть синтаксическая или типовая ошибка, AI сразу увидит её и попробует исправить.

### Шаг 3: попросите AI изменить файл

**Зачем**
edit — самый интеллектуальный инструмент OpenCode. Он не просто «изменяет строку номер N», а точно находит место изменения по совпадению строк.

```
把 hello.txt 里的 "Hello OpenCode" 改成 "Hello World"
```

**Вы должны увидеть**: AI вызовет edit и выполнит замену с помощью `oldString: "Hello OpenCode"` и `newString: "Hello World"`.

::: details 📦 Интеллектуальное сопоставление в edit
У edit есть 9 стратегий сопоставления: они применяются последовательно от строгой к более свободной:

| Стратегия | Описание | Пример |
|------|------|------|
| Стратегия | Описание | Пример |
| Точное совпадение | Полное совпадение | `foo` совпадает с `foo` |
| Игнорирование пробелов в начале и конце строк | Игнорирует пробелы по краям каждой строки | `  foo  ` совпадает с `foo` |
| Якоря первой и последней строки | Находит блок кода по первой и последней строке | Совпадают начало и конец функции |
| Нормализация пробелов | Считает несколько пробелов одним | `a  b` совпадает с `a b` |
| Допуск различий в отступах | Игнорирует общий отступ | Отступ в 2 пробела совпадает с отступом в 4 |
| Обработка escape-символов | Обрабатывает `\n`, `\t` и другие | `a\nb` совпадает с реальным переносом строки |
| Обрезка границ | Убирает пробелы по краям перед сопоставлением | Совпадение работает и при пустых строках по краям |
| Учёт контекста | Использует первые/последние строки и сходство содержимого | Находит слегка изменённый блок кода |
| Несколько совпадений | Находит все точные совпадения | Используется вместе с replaceAll |

Проще говоря, фрагмент кода в запросе не обязан полностью совпадать с файлом: небольшие различия в отступах и пробелах не помешают.
:::

**Что делать при нескольких совпадениях?**

Если `oldString` встречается в файле несколько раз, edit сообщит об ошибке:

```
Found multiple matches for oldString.
Provide more surrounding lines in oldString to identify the correct match.
```

Решение:
- попросите AI добавить больше контекста (включить ещё несколько строк кода), чтобы совпадение стало уникальным;
- либо используйте параметр `replaceAll`, чтобы заменить все совпадения сразу.

### Шаг 4: попросите AI выполнить команду

**Зачем**
Инструмент bash позволяет AI выполнять команды Shell: запускать тесты, устанавливать зависимости и проверять состояние Git.

```
帮我运行一下 git status
```

**Вы должны увидеть**: AI вызовет bash, выполнит команду и вернёт сведения о состоянии Git.

::: danger 🚫 Не используйте bash для операций с файлами
Это самая частая ошибка новичков. Инструмент bash предназначен для выполнения команд, а не для работы с файлами.

| ❌ Не делайте так | ✅ Делайте так |
|------------|-----------|
| Использовать `cat` для чтения | Использовать read |
| Использовать `echo > file` для записи | Использовать write |
| Использовать `sed` для редактирования | Использовать edit |
| Использовать `find` для поиска файлов | Использовать glob |
| Использовать `grep` для поиска содержимого | Использовать grep |

Почему? Специализированные инструменты проверяют права, умеют обрабатывать ошибки и запускают диагностику LSP, а команды bash такой защиты не дают.
:::

**Механизмы безопасности bash**:
- тайм-аут по умолчанию — 2 минуты, чтобы команда не зависала;
- tree-sitter разбирает синтаксис команд, а для операций с файлами (`rm`, `cp`, `mv` и других) проверяет, находится ли путь внутри каталога проекта;
- для всех команд запрашивается подтверждение прав (можно настроить правила автоматического разрешения);
- вывод длиннее 2000 строк или 50 КБ автоматически усекается.

### Шаг 5: попросите AI найти код

**Зачем**
grep и glob — два инструмента поиска: один ищет содержимое, другой — имена файлов.

**Поиск содержимого файлов** (grep):

```
帮我找出项目里所有用到 console.log 的地方
```

**Вы должны увидеть**: AI вызовет grep и вернёт подходящие файлы и номера строк.

**Поиск имён файлов** (glob):

```
帮我找出所有的测试文件
```

**Вы должны увидеть**: AI вызовет glob и выполнит поиск по шаблону вроде `**/*.test.ts`.

| Что нужно сделать | Что использует AI | Пример промпта |
|-----------|-----------|-----------|
| Найти места вызова функции | grep | «Найди все вызовы getUserData» |
| Найти файл | glob | «Найди все файлы конфигурации» |
| Найти строку | grep | «Найди все комментарии TODO» |
| Перечислить файлы определённого типа | glob | «Перечисли все файлы .tsx в src» |

::: tip Ограничение результатов поиска
grep и glob возвращают не более 100 результатов. Если вывод обрезан:
- сузьте каталог поиска («ищи только в каталоге src»);
- используйте более точные ключевые слова;
- ограничьте тип файлов («ищи только файлы .ts»).
:::

## Совместная работа инструментов: как AI комбинирует их

В реальной работе AI редко ограничивается одним инструментом. Рассмотрим несколько типичных сценариев:

**Сценарий 1: переименование функции**

```
你：把所有 getUserData 改成 fetchUserInfo

AI 的操作流程：
1. grep 搜索 "getUserData" → 找到 20 个文件
2. 逐个文件 read 读取
3. edit + replaceAll 替换
4. bash 运行测试验证
```

**Сценарий 2: добавление функции**

```
你：给 User 组件添加 email 字段

AI 的操作流程：
1. glob 搜索 "User.tsx" → 找到文件
2. read 读取文件内容
3. edit 修改接口定义和组件代码
4. 自动 LSP 检查类型错误
```

**Сценарий 3: поиск ошибки

```
你：登录后没有跳转到首页，帮我查一下

AI 的操作流程：
1. grep 搜索 "login" 相关代码
2. read 读取登录逻辑
3. grep 搜索 "redirect" 或 "navigate"
4. 分析代码逻辑，找到问题
```

## Типичные проблемы

| Симптом | Причина | Решение |
|-----|-----|-----|
| AI сообщает «File not found» | Неверный путь или опечатка в имени файла | read предложит похожее имя, исправьте его по подсказке |
| AI сообщает «Found multiple matches» | oldString из edit встречается в файле несколько раз | Попросите AI добавить контекст или использовать replaceAll |
| AI сообщает «Output truncated» | Слишком большой файл или вывод команды | Это нормально: AI автоматически прочитает данные частями |
| AI использует `cat` для чтения | AI нарушил разделение обязанностей инструментов | Напомните: «используй инструмент read для чтения» |
| Команда bash превысила тайм-аут | Тайм-аут по умолчанию — 2 минуты | Скажите AI: «эта команда может выполняться 10 минут» |
| write сообщает «must read first» | Файл не был прочитан перед перезаписью | AI сам должен выполнить read, затем write; при ошибке напомните ему об этом |

## Итоги урока

В OpenCode есть **10 основных инструментов**; в этом уроке мы рассмотрели **6 инструментов для работы с файлами**:

| Инструмент | Назначение | Что запомнить |
|------|------|--------|
| read | Читает файл или каталог | Большие файлы читаются частями, поддерживаются изображения и PDF, каталог можно упомянуть через @ |
| write | Создаёт или перезаписывает файл | Сначала нужно прочитать, после записи запускается проверка LSP |
| edit | Точно заменяет строки | 9 интеллектуальных стратегий, различия в отступах не страшны |
| bash | Выполняет команды Shell | Есть тайм-аут и проверки безопасности; не используйте для работы с файлами |
| grep | Ищет содержимое файлов | Поддерживает регулярные выражения, возвращает до 100 результатов |
| glob | Ищет имена файлов | Шаблоны glob, до 100 результатов |

Запомните три правила:
1. Специализированные инструменты лучше команд bash
2. Сначала чтение, затем запись
3. У результатов поиска есть ограничение; при необходимости сужайте область

**Ключевые константы**:
- `DEFAULT_READ_LIMIT = 2000`: число строк, читаемых read по умолчанию
- `MAX_LINE_LENGTH = 2000`: максимальное число символов в строке
- `MAX_BYTES = 50 * 1024`: максимальный размер вывода read и общего вывода перед усечением — 50 КБ
- `DEFAULT_TIMEOUT = 2 * 60 * 1000`: тайм-аут bash по умолчанию — 2 минуты
- `MAX_METADATA_LENGTH = 30_000`: максимальная длина метаданных bash
- `limit = 100`: ограничение результатов grep/glob

**Ключевые функции**:
- `replace()`: основная логика замены edit, последовательно пробует 9 Replacer
- `isBinaryFile()`: определяет, является ли файл бинарным (по расширению и анализу байтов)
- `Ripgrep.files()`: glob использует ripgrep для поиска файлов
- `Truncate.output()`: логика усечения вывода bash; полный вывод сохраняется в файл при превышении лимита
