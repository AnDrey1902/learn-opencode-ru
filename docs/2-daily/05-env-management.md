<summary>📝 Текстовая версия шпаргалки</summary>

**3 CLI-команды**: `opencode models` (список моделей), `opencode stats` (расходы), `opencode auth` (доступы).

- `opencode models --refresh` — обновить кэш моделей; `opencode --model [ID]` — запуск с конкретной моделью.
- **Cache Read** — главный показатель экономии: попадание в кэш = бесплатно; вход дешевле выхода.
- `opencode stats --models 5` — топ-5 самых дорогих моделей.
- Auth: `auth list` (api vs oauth), `auth logout`; хранение — `~/.local/share/opencode/auth.json`.
- Соответствия CLI↔TUI: `opencode -m` ↔ `/model`, `opencode stats` ↔ `/stats`, `opencode auth login` ↔ `/connect`.
- Экономия: Cache Read + помесячные планы для рутины + оплата по факту для сложных задач.

## 1. Просмотр доступных моделей

Если вы настроили несколько провайдеров (например, одновременно используете DeepSeek и Claude) или добавили новый ключ, возникает вопрос: «Какие модели мне сейчас доступны?»

### Команда терминала: `opencode models`

Выполните в терминале:

```bash
opencode models
```

Вы увидите список примерно такого вида:

```text
opencode/glm-4.7-free
anthropic/claude-3-5-sonnet-20241022
google/gemini-2.0-flash
ollama/deepseek-r1:7b
zhipuai-coding-plan/glm-4.7
...
```

Каждая строка — это **ID модели** (формат `провайдер/имя_модели`). Этот ID можно скопировать и указать при запуске:

```bash
# Например, прямой запуск через Zhipu GLM-5
opencode --model zhipuai-coding-plan/glm-5
```

### Продвинутый приём 1: просмотр моделей конкретного провайдера

Список слишком длинный? Укажите имя провайдера:

```bash
# Только модели Anthropic
opencode models anthropic

# Только модели DeepSeek (если настроены)
opencode models deepseek
```

Так список станет короче и покажет только интересующие модели.

### Продвинутый приём 2: просмотр цен

Хотите узнать точную цену модели? Добавьте параметр `--verbose`:

```bash
opencode models --verbose
```

В выводе будут подробные метаданные, включая `inputCost` (стоимость ввода) и `outputCost` (стоимость вывода):

```json
zhipuai-coding-plan/glm-4.7
{
  "id": "zhipuai-coding-plan/glm-4.7",
  "name": "GLM 4.7",
  "provider": "zhipuai-coding-plan",
  "inputCost": 0,    // бесплатно!
  "outputCost": 0    // бесплатно!
}
```

### Продвинутый приём 3: обновление кэша

::: tip 💡 Почему после добавления ключа модель не появилась?
OpenCode кэширует список моделей. Если вы только что добавили конфигурацию в `opencode.json` или получили доступ к новой модели (например, скачали новую модель Ollama), список мог ещё не обновиться.
:::

В этом случае выполните **принудительное обновление**:

```bash
opencode models --refresh
```

После сообщения `Models cache refreshed` снова выполните `opencode models`.

### Важный шаг: назначьте предпочтительную модель по умолчанию

Вы нашли нужный ID модели (например, `zhipuai-coding-plan/glm-4.7`), но вводить его при каждом запуске неудобно.

Откройте файл конфигурации (обычно `~/.config/opencode/opencode.json`) и добавьте его:

```json
{
  "model": "zhipuai-coding-plan/glm-4.7"
}
```

Теперь команда `opencode` будет запускать вашу любимую модель.

## 2. Счета: просмотр статистики использования

«Сколько я потратил на написание кода в этом месяце?» «Какой моделью я пользовался чаще — Claude или GPT-4?»

В OpenCode есть удобная встроенная панель статистики.

### Команда терминала: `opencode stats`

Выполните:

```bash
opencode stats
```

Вы увидите подробную панель. Ниже приведён пример данных после месяца использования; для краткости в разделе инструментов параметр `--tools 7` показывает только первые 7 пунктов:

│Total Cost                                    $1232.56 │

### Как читать ключевые показатели

Новичкам достаточно обратить внимание на следующие показатели:

1. **Total Cost**: расчётная стоимость в долларах. OpenCode вычисляет её по опубликованным ценам провайдеров.
2. **Avg / Median Tokens/Session**:
    *   `Avg` (среднее): средний расход токенов во всех сессиях.
    *   `Median` (медиана): центральное значение после сортировки по расходу. Если отдельные сессии особенно «прожорливы», медиана будет намного ниже среднего и лучше покажет «обычный» уровень использования.
3. **Input vs Output**:
    *   `Input` (ввод): ваши сообщения + содержимое файлов, прочитанных AI. Объём большой, но стоимость ниже.
    *   `Output` (вывод): код и ответы, созданные AI. Объём меньше, но цена выше.
4. **Cache Read / Cache Write (кэш контекста):**
    *   **Cache Read**: число токенов чтения кэша по данным провайдера. Стоимость и цена зависят от модели и конфигурации провайдера.
    *   **Cache Write**: число токенов записи в кэш по данным провайдера. Стоимость и цена также зависят от модели и конфигурации провайдера.
5. **Tool Usage**:
    *   показывает, какие инструменты AI использует чаще всего;
    *   `read` (чтение файлов) обычно на первом месте — AI активно изучает ваш код;
    *   `bash` (выполнение команд) и `edit` (изменение кода) также относятся к основным инструментам;
    *   список слишком длинный? Используйте `--tools 5`, чтобы видеть только первые 5 (см. раздел «Сокращённый вывод» ниже).

### Продвинутый уровень: статистика отдельного проекта (нужен Git)

::: info ☕ Совет тем, кто не программирует
Если вы **не знакомы с Git** или вас устраивает «общий счёт для всех проектов», **смело пропустите этот раздел!**
Он предназначен для опытных пользователей, которым нужно чётко разделять расходы «рабочих» и «личных» проектов.
:::

По умолчанию `opencode stats` показывает **общий счёт** всех проектов.

Находясь в **Git-проекте**, можно посмотреть расходы **только этого проекта**, добавив параметр `--project ""`:

```bash
# Статистика только текущего проекта
opencode stats --project ""
```

**Сравнение на реальном примере** (команды выполняются в репозитории исходного кода `opencode`):
- `opencode stats` (общий счёт): расходы **$1232**;
- `opencode stats --project ""` (текущий Git-проект): расходы **$923**.

Это означает, что около $300 было потрачено в других проектах (или в области Global).

::: tip 💡 Основная логика: что считается «проектом»?
OpenCode определяет проект по **первому коммиту** Git-репозитория.
- **Project (отдельный счёт)**: Git-репозиторий хотя бы с одним Commit.
- **Global (общий счёт)**: все остальные случаи (обычная папка или пустой Git-репозиторий).

**⚠️ Как избежать ошибки**:
Если выполнить `opencode stats --project ""` в обычной папке, сумма будет **общей для всех операций Global на этом компьютере** (в неё войдут расходы в Downloads, Desktop и других каталогах без Git), а не только в текущей папке.

**Хотите включить отдельный счёт?**
Достаточно трёх шагов (**подключать GitHub не нужно, подойдёт локальный репозиторий**):
1. `git init`
2. `git add .`
3. `git commit -m "init"` 👈 **Этот шаг крайне важен!**
:::

### 💡 Скрытая функция: расходы автоматически «переносятся» задним числом

Возможно, вы переживаете: «Я несколько дней писал код в этой папке и потратил немало токенов, но не использовал Git. Если инициализировать репозиторий сейчас, пропадут ли прежние расходы?»

OpenCode умнее, чем кажется: **он автоматически перенесёт их!**

После создания Git-проекта (и коммита) в папке OpenCode просканирует «глобальный журнал» и перенесёт все прошлые сессии, **относящиеся к пути этой папки**, под именем нового проекта.

Поэтому пользуйтесь спокойно и не переживайте, что сначала нужно «оформить подписку», а уже потом начинать работу.

### Узнайте, какая модель «съедает» больше всего токенов

Хотите узнать, какая модель обходится дороже всего? Выполните:

```bash
# Топ-5 моделей по расходу
opencode stats --models 5

# Подробный список всех моделей
opencode stats --models
```

Будет показана подробная статистика Top 5:

```text
┌────────────────────────────────────────────────────────┐
│                      MODEL USAGE                       │
├────────────────────────────────────────────────────────┤
│ anthropic/claude-opus-4-5-20251101                     │
│  Messages                                       12,548 │
│  Input Tokens                                   241.0M │
│  Cost                                       $1232.5613 │
├────────────────────────────────────────────────────────┤
│ zhipuai-coding-plan/glm-4.7                            │
│  Messages                                        3,023 │
│  Input Tokens                                    68.9M │
│  Cost                                          $0.0000 │
├────────────────────────────────────────────────────────┤
```

**Разницу видно сразу**:
- **Claude Opus**: оплата по использованию; модель мощная, но дорогая — у меня она потратила $1232.
- **Zhipu GLM-5**: показывает $0.0000, **потому что я приобрёл месячную подписку Coding Plan**.

::: tip 💡 Как сэкономить
В этом и состоит смысл статистики OpenCode — она показывает, куда уходят деньги.
Если какая-то модель используется много и стоит дорого, можно сделать основной модель с месячной подпиской (например, Zhipu), а дорогую модель с оплатой по использованию оставить для самых сложных задач.
:::

Регулярно проверяя эту статистику, вы сможете оптимизировать набор моделей и сэкономить реальные деньги.

### Продвинутый приём: просмотр расходов за последние дни

По умолчанию `stats` показывает накопленный счёт за всю историю. Можно также учитывать только недавно активные сессии:

Количество дней задаётся параметром `--days`:

```bash
# Сессии, обновлённые после полуночи
opencode stats --days 0

# Сессии, обновлённые за последние 24 часа
opencode stats --days 1

# Сессии, обновлённые за последние 7 дней
opencode stats --days 7
```

::: warning `--days` не показывает приращение счёта
Параметр фильтрует сессии по времени последнего обновления, а затем суммирует все накопленные данные найденных сессий. `--days 0` не означает «расходы, добавленные сегодня», а `--days 1` не означает строгое приращение за последние 24 часа.
:::

**🔥 Мощная комбинация**:

Совместите «фильтр активных сессий» со «статистикой моделей», чтобы узнать, какие модели в основном использовали обновлённые сегодня сессии:

```bash
# Сессии после полуночи с полной статистикой по моделям
opencode stats --days 0 --models
```

### Сокращённый вывод: только первые инструменты

По умолчанию `stats` перечисляет все использованные инструменты. Со временем список становится длинным.

С помощью `--tools` можно показать только первые N:

```bash
# Топ-5 самых используемых инструментов
opencode stats --tools 5

# Комбо: топ-3 инструмента за 7 дней
opencode stats --days 7 --tools 3
```

## 3. Учётные данные: управление авторизацией

Со временем вы могли попробовать множество моделей и настроить много ключей. Какие учётные данные сейчас сохранены в OpenCode?

### Просмотр списка учётных данных

```bash
opencode auth list
```

Вы увидите дерево примерно такого вида:

```text
Credentials ~/.local/share/opencode/auth.json
┌
●  Zhipu AI Coding Plan  api
│
●  Google  oauth
│
●  OpenAI  oauth
│
└  3 credentials
```

Эта команда покажет:
1. **Способ авторизации**:
    *   `api`: добавлено с помощью ключа `sk-...`.
    *   `oauth`: авторизация через веб-страницу (например, Google или OpenAI).
2. **Расположение хранилища**: обычно `~/.local/share/opencode/auth.json`.
    ::: warning ⚠️ Безопасность
    В этом файле ваши ключи хранятся в **открытом формате JSON**. Защитите компьютер и файл, не загружайте его в общедоступные репозитории.
    :::

### Выход и удаление учётных данных

Если нужно удалить старый ключ (например, он раскрыт или истёк):

```bash
opencode auth logout
```

Затем клавишами <kbd>↑</kbd> и <kbd>↓</kbd> выберите провайдера для удаления и нажмите Enter.

## 4. Соответствующие операции в TUI

Всё выше выполняется в **терминале** (вне интерфейса OpenCode). Если вы уже находитесь в OpenCode, есть соответствующие команды:

| Что нужно сделать | Команда терминала | Slash-команда TUI |
| ---------- | --------------------- | ----------------------- |
| Переключить модель | `opencode -m <id>` | `/models` |
| Войти в аккаунт | `opencode auth login` | `/connect` |
| Просмотреть состояние | `opencode stats` | `/status` (краткая сводка) |
| Выйти из программы | `Ctrl+C` | `/exit` |

::: info Отличие
Команда `/models` в TUI не только показывает модели, но и позволяет **напрямую переключить** модель текущей сессии.
:::

**Разбор ключевой логики**:

1. **Создание ID проекта (`project.ts`)**:
    *   OpenCode ищет каталог `.git` в текущем и родительских каталогах.
    *   Если каталог найден, пытается получить хеш `root commit` как ID проекта.
    *   Если `.git` или commit отсутствует, ID становится равным `"global"`. Поэтому пустые папки используют один общий счёт.

2. **Механизм переноса расходов (`project.ts`):**
    *   Когда OpenCode обнаруживает, что ID текущего проекта не `global`, он запускает `migrateFromGlobal`.
    *   Он перебирает все сессии Global и проверяет, совпадает ли `session.directory` с текущей рабочей областью.
    *   При совпадении `projectID` сессии автоматически обновляется до ID нового проекта — расходы «переносятся».

3. **Фильтрация статистики (`stats.ts`):**
    *   По умолчанию (`projectFilter` не определён) учитываются все Session.
    *   Только при явной передаче `--project ""` вызывается `getCurrentProject()` для получения ID текущего каталога и фильтрации.

4. **Хранение учётных данных (`auth/index.ts`):**
    *   Учётные данные хранятся в `~/.local/share/opencode/auth.json`.
    *   Код записывает их напрямую через `JSON.stringify`, без шифрования.
    *   В качестве меры безопасности для файла устанавливаются права `0o600` (чтение и запись только текущим пользователем).

</details>
