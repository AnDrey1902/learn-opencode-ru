## Основная идея

### Что такое «файл правил»?

Файл правил — это Markdown-файл с правилами, которым должен следовать AI. OpenCode автоматически читает его и добавляет содержимое в системный промпт.

**Преимущества**:
- не нужно повторять правила в каждом диалоге;
- правила могут быть длинными и подробными;
- формат Markdown помогает удобно организовать их.

### Правила загружаются «на лету»!

::: warning ⚡ Важный момент
Изменения файла правил вступают в силу **сразу** — перезапускать OpenCode или создавать новую сессию не нужно!
:::

OpenCode перечитывает файл правил **при каждом отправленном сообщении**. Это означает:

| Действие | Требуется ли |
|------|---------|
| Перезапустить OpenCode после изменения правил | ❌ Нет |
| Создать сессию после изменения правил | ❌ Нет |
| Отправить следующее сообщение после изменения правил | ✅ Этого достаточно |

**На практике**: после того как AI обновит файл правил, просто отправьте следующее сообщение — новые правила вступят в силу.

### Три области действия

OpenCode поддерживает правила с тремя областями действия:

| Область | Расположение | Сценарий |
|-------|------|---------|
| **Глобальные правила** | `~/.config/opencode/AGENTS.md` | Общие предпочтения для всех проектов |
| **Правила проекта** | `AGENTS.md` в корне проекта | Нормы конкретного проекта |
| **Файл конфигурации** | Поле `instructions` в `opencode.json` | Ссылки на несколько файлов правил |

::: info 🤔 Почему файл называется AGENTS.md?
OpenCode поддерживает и `AGENTS.md`, и `CLAUDE.md` (для совместимости с Claude Code). Рекомендуется `AGENTS.md` — это стандартное имя OpenCode.
:::

### Порядок загрузки правил

Правила загружаются в следующем порядке; последующие **дополняют**, а не перезаписывают предыдущие:

```
1. Глобальные ~/.config/opencode/AGENTS.md
2. Глобальные ~/.claude/CLAUDE.md (режим совместимости)
3. Поиск AGENTS.md / CLAUDE.md вверх от каталога проекта
4. Файлы, указанные в поле instructions конфигурации
```

**Результат**: все правила действуют и объединяются.

## Повторите за мной

<AdInArticle />

::: tip 💡 Основная идея
**Не выходите из OpenCode**! Проще всего попросить AI создать файл правил.
:::

### Шаг 1: попросите AI создать глобальные правила

**Зачем**  
Раз уж вы используете OpenCode, удобнее всего поручить AI создать файл.

Введите в поле OpenCode:

```
Помоги создать файл глобальных правил ~/.config/opencode/AGENTS.md со следующим содержимым:

Всегда отвечай на русском
```

**Вы должны увидеть**: AI создаст каталог и файл и запишет в него правила.

::: details 📦 Что сделает AI?
AI выполнит примерно следующие действия:
1. Проверит, существует ли каталог `~/.config/opencode/`.
2. Создаст каталог, если его нет.
3. Создаст файл `AGENTS.md` и запишет ваши правила.

Вам не придётся вводить команды вручную!
:::

### Шаг 2: убедитесь, что правила действуют

**Зачем**  
Проверим, что OpenCode прочитал правила.

Введите `hello` в текущей сессии.

**Вы должны увидеть**: AI ответит по-русски.

::: tip 💡 Правила действуют сразу
Поскольку правила загружаются «на лету», после создания файла AI будет соблюдать их уже в следующем сообщении. Новая сессия не нужна!
:::

::: details 📦 Как проверить
Спросите AI: «Какие правила ты сейчас соблюдаешь?» — он перечислит правила из системного промпта.
:::

### Шаг 3: дополните правила

**Зачем**  
Одного правила мало — добавим несколько практичных.

Продолжите в OpenCode:

```
Помоги обновить файл глобальных правил ~/.config/opencode/AGENTS.md, замени содержимое на:

## Язык и стиль

- Всегда отвечай на русском
- Отвечай по делу, без лишней вежливости
- Комментарии в коде тоже пиши на русском

## Стандарты кода

- Отступ — 2 пробела
- Имена переменных — в camelCase
- Имена функций начинай с глагола (например, getUserById)

## Рабочие привычки

- Перед изменением кода сначала прочитай связанные файлы
- Если не уверен — сначала спроси, не гадай
- Каждый раз вноси только минимально необходимые изменения
```

**Вы должны увидеть**: AI обновил файл правил.

### Шаг 4: (необязательно) создайте правила проекта

**Зачем**  
Некоторые правила должны действовать только в определённом проекте.

Запустите OpenCode в каталоге проекта и скажите:

```
Помоги создать AGENTS.md в корне проекта со следующим содержимым:

# Правила проекта

## Технологический стек
- Фронтенд: React + TypeScript
- Бэкенд: NestJS
- База данных: PostgreSQL

## Стандарты кода
- Используй конфигурацию ESLint проекта
- Файлы компонентов именуй в PascalCase
- Маршруты API — в kebab-case
```

**Вы должны увидеть**: в этом проекте AI будет соблюдать и глобальные, и проектные правила.

### Шаг 5: (необязательно) создайте правила проекта через /init

**Зачем**  
Если вы не знаете, какие правила написать, попросите AI проанализировать проект и создать их автоматически.

Введите в OpenCode:

```
/init
```

**Вы должны увидеть**: AI проанализирует структуру проекта, технологический стек и стиль кода и автоматически создаст `AGENTS.md`.

::: info 🤔 Что создаёт /init
AI проанализирует:
- команды сборки и тестирования проекта;
- стиль кода (отступы, правила именования и т. д.);
- используемые фреймворки и библиотеки;
- существующие правила Cursor/Copilot (если есть).

Созданные правила занимают около 150 строк и охватывают самые важные нормы проекта.
:::

## Примеры практичных правил

Ниже приведены проверенные на практике правила, которые можно скопировать и использовать:

### Общие правила разработки

```markdown
## Рабочий настрой

- Каждую задачу выполняй тщательно, держи высокую планку качества

## Стиль общения

- Сразу выдавай код или решение, без лишней вежливости («извини», «понял» и т. п.)
- Не прикладывай описание кода, если явно не просили

## Принцип честности (не выдумывай)

- Если не уверен или не хватает данных — сначала проверь или задай уточняющий вопрос
- Выводы об окружении, конфигурации, исходниках и поведении опирай только на факты
- В ответе отделяй «факты» от «предположений»
```

### Правила качества кода

```markdown
## Принципы качества кода

- Приоритет — читаемости кода, вноси самые простые изменения
- Не обходи проблемы через `eslint-disable` или `@ts-ignore`
- Не используй тип `any`, определяй явные типы
- Не храни устаревший код ради обратной совместимости
- Удаляй неиспользуемый код, не оставляй его в комментариях

## Переиспользование прежде всего

- Прежде чем писать новый код, проверь, нет ли похожей реализации в проекте
- Переиспользуй существующие компоненты и утилиты, а не создавай новые
```

### Правила рабочего процесса

```markdown
## Регламент выполнения

- Любую нетривиальную задачу сначала планируй, потом делай
- Перед изменением кода обязательно прочитай связанные файлы
- После изменений сам запусти тесты для проверки

## Стратегия делегирования подагентам

- По возможности поручай работу подагентам
- То, что можно отдать эксперту, отдавай — не делай всё сам
```

## Продвинутое использование: ссылки из файла конфигурации

Если правила находятся в нескольких файлах, можно перечислить их в конфигурации:

```json
// opencode.json
{
  "instructions": [
    "CONTRIBUTING.md",
    "docs/coding-standards.md",
    ".cursor/rules/*.md",
    "~/my-rules/common.md"
  ]
}
```

**Поддерживаемые форматы**:
- относительный путь: `docs/rules.md`;
- абсолютный путь: `~/my-rules/common.md`;
- шаблон Glob: `.cursor/rules/*.md`;
- URL: `https://example.com/rules.md`.

::: warning ⚡ Разное время применения
**Список путей** к файлам правил, указанный через `instructions`, загружается при запуске сессии. Если вы добавили или изменили запись `instructions` в `opencode.json`, для применения изменений нужно **открыть новую сессию**.

Однако **содержимое** уже загруженных файлов обновляется «на лету»: изменения самого файла правил вступят в силу в следующем сообщении.
:::

::: tip 💡 Совместимость с другими инструментами
Если вы раньше пользовались Cursor, можно напрямую подключить `.cursor/rules/*.md` и повторно использовать эти правила.
:::

## Типичные проблемы

| Симптом | Причина | Решение |
|-----|-----|-----|
| Правила не применяются | Неверный путь к файлу | Проверьте, что это `~/.config/opencode/AGENTS.md`, а не `~/.opencode/` |
| Часть правил игнорируется | Правила слишком длинные и обрезаются | Сократите правила, оставив только важные |
| Конфликт правил | Глобальные и проектные правила противоречат друг другу | Сделайте проектные правила более конкретными |
| Нечитаемые символы (кракозябры) | Кодировка файла не UTF-8 | Сохраните файл в кодировке UTF-8 |

**Как работает загрузка «на лету»**:
- `SessionPrompt.prompt()` вызывается при каждом сообщении пользователя;
- цепочка вызовов: `prompt()` → `loop()` → `processor.process()` → `SystemPrompt.custom()`;
- `SystemPrompt.custom()` каждый раз перечитывает файл, не используя кэш.

**Поддерживаемые имена файлов** (по приоритету):
- `AGENTS.md` — стандарт OpenCode
- `CLAUDE.md` — совместимость с Claude Code
- `CONTEXT.md` — устарел, но по-прежнему поддерживается

**Порядок поиска глобальных правил**:
1. `$OPENCODE_CONFIG_DIR/AGENTS.md` (если задана переменная окружения)
2. `~/.config/opencode/AGENTS.md`
3. `~/.claude/CLAUDE.md`

**Поиск правил проекта**: поиск выполняется от текущего каталога вверх, пока файл не будет найден или не будет достигнут корневой каталог.
