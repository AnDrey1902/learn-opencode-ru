## С какими трудностями вы столкнулись

- Диалог становится всё длиннее, и AI начинает путать контекст
- AI неправильно изменил код, а вы не знаете, как отменить это действие

## Основная идея
<AdInArticle />

### Зачем нужны несколько сессий

- **Изоляция контекста**: отдельная сессия для каждой задачи не даёт AI запутаться
- **Параллельная работа**: в одной сессии AI пишет код, в другой анализирует документацию
- **Сохранение истории**: важные диалоги можно сохранить и просматривать в любое время

### Где хранятся сессии?

OpenCode использует SQLite для хранения сессий, сообщений и их фрагментов. По умолчанию база данных `opencode.db` находится в каталоге данных OpenCode:

```
~/.local/share/opencode/opencode.db
```

::: details О пути
Пример приведён для каталога данных XDG в Linux. Фактическое расположение зависит от системы и окружения; сессии в базе всё равно связаны с соответствующими проектами. Не изменяйте файл базы вручную.
:::

### Жизненный цикл сессии

От создания до завершения сессия проходит следующие этапы:

```
Создание → активный диалог → сжатие (автоматически при переполнении контекста) → архив/удаление
```

Обычно вам не нужно об этом думать — OpenCode всё обработает автоматически. Достаточно знать, что слишком длинные диалоги сжимаются автоматически (см. [5.20 Сжатие контекста](/5-advanced/20-compaction)), а ненужные сессии можно удалять.

### Краткий список команд управления сессиями

| Команда | Назначение |
|-----|------|
| `/new` | Создать сессию |
| `/sessions` | Просмотреть и переключить сессию |
| `/undo` | Отменить последнее действие |
| `/redo` | Повторить отменённое действие |
| `/compact` | Сжать контекст |
| `/export` | Экспортировать историю диалога |
| `/share` | Поделиться сессией (создать ссылку) |
| `opencode import` | Импортировать сессию из файла или URL (команда CLI) |
| `opencode export` | Экспортировать сессию в JSON (команда CLI) |

## Повторите за мной

### Шаг 1: создайте сессию

**Зачем**  
Начинайте новую задачу в новой сессии, чтобы предыдущий контекст не мешал.

Введите:

```
/new
```

Или используйте сочетание клавиш: <kbd>Ctrl</kbd>+<kbd>X</kbd> <kbd>N</kbd>.

**Вы должны увидеть**: интерфейс очистится, и откроется новая сессия.

### Шаг 2: поговорите в новой сессии

**Зачем**  
Добавим содержимое в новую сессию, чтобы позже было удобно переключаться и проверять результат.

Введите:

```
Привет, это вторая сессия
```

### Шаг 3: просмотрите и переключите сессию

**Зачем**  
Научимся переключаться между несколькими сессиями.

Введите:

```
/sessions
```

**Вы должны увидеть**: список сессий, содержащий две созданные сессии.

Выберите сессию клавишами <kbd>↑</kbd> и <kbd>↓</kbd>, затем нажмите <kbd>Enter</kbd>.

### Шаг 4: проверьте отмену действий

**Зачем**  
AI может ошибиться, а отмена поможет восстановить предыдущее состояние.

::: warning ⚠️ Предварительное условие
Для отмены **операций с файлами** (создания, изменения и удаления) через `/undo` проект должен быть **Git-репозиторием**.

| Тип проекта | Отмена операций с файлами | Отмена истории диалога |
|---------|------------|------------|
| Git-проект | ✅ Файлы будут восстановлены | ✅ |
| Не Git-проект | ❌ Файлы не изменятся | ✅ |

Проводите проверку ниже в Git-проекте. Если текущий каталог не является Git-репозиторием, сначала выполните `git init`.
:::

Сначала попросите AI выполнить действие (например, создать файл):

```
Создай файл test.txt с содержимым "hello"
```

Затем отмените его:

```
/undo
```

**Вы должны увидеть** (Git-проект):
- файл удалён, состояние восстановлено до операции;
- интерфейс показывает подтверждение отмены.

**Вы должны увидеть** (не Git-проект):
- история диалога отменена;
- ⚠️ файл **не удалён** (поскольку нет снимка Git).

### Шаг 5: сожмите слишком длинный контекст

**Зачем**  
Длинный диалог расходует токены, а сжатие помогает снизить затраты.

Введите:

```
/compact
```

**Вы должны увидеть**: AI обобщит предыдущий диалог и удалит старые сообщения.

### Шаг 6: экспортируйте историю диалога

**Зачем**  
Сохраните важный диалог, чтобы обратиться к нему позже.

Введите:

```
/export
```

**Вы должны увидеть**: диалог экспортирован в файл Markdown.

### Шаг 7: экспортируйте и импортируйте сессию через CLI

**Зачем**  
`/export` в TUI создаёт формат Markdown, удобный для чтения. Но для резервного копирования всех данных или восстановления сессии на другом компьютере нужна команда CLI, экспортирующая JSON.

**Экспорт**:

```bash
# Интерактивный выбор сессии для экспорта
opencode export

# Экспорт по ID сессии с перенаправлением в файл
opencode export session_abc123 > backup.json
```

Если не указать ID сессии, появится список для выбора:

```
Export session
◇ Select session to export
│   Fix authentication bug • 2026-02-14 10:30 • a1b2c3d4
│   Add new API endpoint • 2026-02-13 15:20 • e5f6g7h8
└   Update documentation • 2026-02-12 09:00 • i9j0k1l2
```

**Импорт**:

```bash
# Импорт из локального файла
opencode import backup.json
```

**Вы должны увидеть**: `Imported session: session_abc123`.

После импорта восстановленная сессия появится в списке `/sessions`.

### Шаг 8: импортируйте сессию по ссылке общего доступа

**Зачем**  
Коллега поделился ссылкой на сессию OpenCode, и вы хотите продолжить этот диалог локально.

```bash
opencode import https://opncd.ai/share/abc123
```

::: tip 💡 Формат URL
Ссылка общего доступа по умолчанию имеет формат `https://opncd.ai/share/<slug>`. У пользователей корпоративной версии домен может отличаться согласно настройке `enterprise.url`. При неверном формате URL появится ошибка.
:::

### Шаг 9: разветвите сессию (Fork)

**Зачем**  
Иногда нужно «ответвиться» от определённого узла диалога и попробовать другой путь, не теряя исходный диалог. Для этого и предназначен Fork.

Fork копирует всю историю текущей сессии и создаёт новую. К её заголовку добавляется суффикс `(fork #1)`, а при следующих ответвлениях номер увеличивается: `(fork #2)`, `(fork #3)`…

**Порядок действий**:

У Fork нет сочетания клавиш по умолчанию. Назначить его можно в `tui.json` или `tui.jsonc` проекта:

```jsonc
{
  "$schema": "https://opencode.ai/tui.json",
  "keybinds": {
    "session_fork": "<leader>f"
  }
}
```

Сочетания клавиш относятся к отдельной конфигурации TUI — не добавляйте эту настройку в основной `opencode.json` / `opencode.jsonc`. Исходный код см. в [схеме сочетаний клавиш TUI для v1.18.22](https://github.com/anomalyco/opencode/blob/v1.18.22/packages/tui/src/config/index.tsx#L61-L75).

После настройки нажмите <kbd>Ctrl</kbd>+<kbd>X</kbd> <kbd>f</kbd>, чтобы разветвить текущую сессию.

**Вы должны увидеть**: новую сессию с заголовком вроде `Исходный заголовок (fork #1)`.

## Типичные проблемы

| Симптом | Причина | Решение |
|-----|-----|-----|
| Файлы не восстановились после `/undo` | Текущий каталог не является Git-репозиторием | Перейдите в Git-проект или сначала выполните `git init` |
| `/undo` отменил диалог, но файл остался | В не-Git проекте отмена файлов не поддерживается | Это нормально: отменяется только история диалога |
| Не удаётся найти нужную сессию | Все сессии имеют имена по умолчанию | Называйте их через `/new имя_задачи` |
| После `/compact` пропала важная информация | Сжатие удаляет подробности диалога | Сначала сохраните важное через `/export` |
| `opencode import` завершился ошибкой | Неверный формат JSON | Можно импортировать только файл, созданный `opencode export` |
| Не удалось импортировать URL общего доступа | Неверный формат URL | Формат должен быть `https://opncd.ai/share/<slug>` |
