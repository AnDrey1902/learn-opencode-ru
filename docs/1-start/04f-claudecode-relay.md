# Сторонний шлюз (совместимый с Claude Code)

## 📝 Конспект урока

Краткий конспект основных идей урока:

<img src="/images/1-start/claudecode-relay-notes.mini.jpeg"
     alt="Сторонний прокси (совместимый с Claude Code) — шпаргалка"
     data-zoom-src="/images/1-start/claudecode-relay-notes.jpeg" />

Эта страница решает одну задачу: подключает к OpenCode сторонний шлюз, заявляющий о совместимости с Claude Code.

## Что вы сможете после урока

Вы выполните три действия:

1. Настроите отдельный provider (например, `claudecode-relay`), направив `baseURL` на `.../v1` шлюза
2. Настроите API Key (**один из двух вариантов**: записать в `opencode.json` или сохранить в `auth.json`)
3. Выберете модель в `/models` и проверите подключение одной фразой

---

## 🎒 Перед началом

- [ ] Завершить [1.2 Установка](./02-install) и уметь запускать `opencode`
- [ ] Получить у сервиса шлюза `baseURL` и `API Key`

От сервиса шлюза вам понадобятся две вещи:

1. **baseURL**: адрес интерфейса, предоставленный шлюзом
2. **API Key**: обычно имеет вид `k-...`

Правила указания baseURL (обычно встречаются два варианта):

1) Если вам дали адрес с `/v1`, укажите его как есть: например, `https://url.com/v1`
2) Если дали только домен, добавьте `/v1`: например, `https://url.com` → `https://url.com/v1`

> Подсказка: путь к интерфейсу сообщений многих шлюзов, совместимых с Claude/Anthropic, содержит `.../v1/messages`. Это поможет проверить, не забыта ли в baseURL часть `/v1`.

## Повторяйте за мной

### Шаг 1: настройте отдельный provider в opencode.json

Отредактируйте `~/.config/opencode/opencode.json` и добавьте пользовательский provider (в качестве ID provider используется `claudecode-relay`):

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "claudecode-relay": {
      "npm": "@ai-sdk/anthropic",
      "options": {
        "baseURL": "https://url.com/v1"
      },
      "models": {
        "claude-opus-4-5-20251101": {
          "name": "Opus 4.5 через прокси",
          "limit": {
            "context": 200000,
            "output": 64000
          },
          "modalities": {
            "input": ["text", "image"],
            "output": ["text"]
          },
          "options": {
            "thinking": {
              "type": "enabled",
              "budgetTokens": 16000
            }
          }
        }
      }
    }
  }
}
```

Пояснения:

- `npm` сообщает OpenCode, какой «драйвер протокола/SDK» использовать для запросов этого provider. Для шлюза, совместимого с Claude/Anthropic, обычно нужен `@ai-sdk/anthropic`; если удалить эту строку, OpenCode может интерпретировать provider как OpenAI-compatible по умолчанию, и запросы завершатся ошибкой.
- Можно также направить шлюз через `provider.anthropic`; по сути это тот же протокол Anthropic, но такой вариант не рекомендуется (причина приведена в разделе «Дополнительные сведения» в конце).
- Заданный key (например, `claude-opus-4-5-20251101`) — это **и** отображаемый в OpenCode «ID модели», **и** имя модели, передаваемое API шлюза.
- `models.<key>.name` — отображаемое имя; его можно свободно указать по-русски (например, «opus 4.5 шлюза»).
- `limit.context` и `limit.output` определяют размер контекстного окна и максимальную длину ответа модели. **Если их не настроить, значение по умолчанию будет 0 и автоматическое сжатие перестанет работать**. Рекомендуемые значения приведены ниже.

| Модель | context | output |
|-----|---------|--------|
| claude-opus-4-5 | 200000 | 64000 |
| claude-sonnet-4-5 | 200000 | 64000 |

> 💡 Хотите подробнее узнать о механизме сжатия контекста и параметре `limit`? См. [5.20 Сжатие контекста](/5-advanced/20-compaction).

### Необязательно: для работы с изображениями `modalities` нужно указать на уровне модели

Чтобы модель принимала изображения, `modalities` необходимо указать в `models.<modelID>.modalities`; его нельзя размещать на уровне provider или внутри `options`.

✅ Правильно (будет работать):

```jsonc
{
  "provider": {
    "claudecode-relay": {
      "models": {
        "claude-opus-4-5-20251101": {
          "modalities": {
            "input": ["text", "image"],
            "output": ["text"]
          },
          "options": {
            "thinking": {
              "type": "enabled",
              "budgetTokens": 16000
            }
          }
        }
      }
    }
  }
}
```

❌ Частые ошибки:

- `provider.claudecode-relay.modalities` (уровень слишком высокий, конфигурация сразу выдаёт ошибку)
- `provider.claudecode-relay.models.<modelID>.options.modalities` (уровень слишком глубокий: ошибки нет, но настройка не работает)

### Шаг 2: настройте API Key (**один из двух вариантов**)

Выберите только один из следующих способов:

#### Вариант 1: записать Key в `opencode.json` (проще всего)

##### Способ A: указать Key напрямую (быстрее всего)

```jsonc
{
  "provider": {
    "claudecode-relay": {
      "options": {
        "baseURL": "https://url.com/v1",
        "apiKey": "твой API-ключ"
      }
    }
  }
}
```

Просто вставьте Key, который предоставил шлюз.

::: warning Безопасность
В этом случае Key будет храниться в файле конфигурации в открытом виде. В целях безопасности рекомендуется способ B.
:::

#### Способ B: использовать переменную окружения (безопаснее)

Если вы не хотите хранить Key в открытом виде в файле конфигурации, используйте переменную окружения:

```jsonc
{
  "provider": {
    "claudecode-relay": {
      "options": {
        "baseURL": "https://url.com/v1",
        "apiKey": "{env:CLAUDECODE_RELAY_API_KEY}"
      }
    }
  }
}
```

Затем добавьте в файл конфигурации shell (`~/.bashrc` или `~/.zshrc`):

```bash
export CLAUDECODE_RELAY_API_KEY="твой API-ключ"
```

Сохраните файл и выполните `source ~/.bashrc` (или перезапустите терминал), чтобы переменная окружения вступила в силу.

#### Вариант 2: сохранить Key в аутентификации OpenCode (`auth.json`)

Выполните:

```bash
opencode auth login
```

В интерактивном интерфейсе:

1. Выберите `Other`
2. Введите ID provider: `claudecode-relay`
3. Вставьте свой API Key

Key будет записан в файл аутентификации OpenCode `auth.json`. Командой ниже можно узнать, «в какой именно путь он записан» (путь будет показан в выводе команды):

```bash
opencode auth list
```

::: warning Важно: не указывайте Key обоими способами
Чтобы не столкнуться с ситуацией «я заменил Key, но он не применился», рекомендуется оставить только один способ.

- Если выбран вариант 1 (в `opencode.json` есть `options.apiKey`), не выполняйте `auth login`.
- Если выбран вариант 2 (Key сохранён в `auth.json`), не добавляйте `options.apiKey` в `opencode.json`.

Причина: если в `opencode.json` есть `options.apiKey`, он используется в первую очередь.
:::

### Шаг 3: выберите модель и проверьте подключение

Запустите OpenCode:

```bash
opencode
```

Введите:

```text
/models
```

Выберите `claudecode-relay/claude-opus-4-5-20251101`, затем отправьте фразу для проверки:

```text
Привет! Коротко расскажи о себе
```

## Типичные проблемы

| Симптом | Причина | Решение |
|-----|------|------|
| 404 / Not Found | Неверный baseURL | Сначала проверьте, должен ли `baseURL` оканчиваться на `.../v1`, и убедитесь, что из него получается `.../v1/messages` |
| 401 / Unauthorized | Key недействителен или нет прав | Создайте новый Key или проверьте тариф и разрешения |
| Ошибка сразу после выбора модели | Имя модели не поддерживается | Убедитесь, что настроенный key (например, `claude-opus-4-5-20251101`) полностью совпадает с именем модели у шлюза |
| `Unrecognized key: "modalities" provider.xxx` | `modalities` указан на уровне provider | Переместите его в `provider.xxx.models.<modelID>.modalities` |
| `this model does not support image input` | `modalities` указан внутри `options` или не настроен | Используйте уровень модели: `models.<modelID>.modalities.input` должен содержать `image` |

## Настройка нескольких шлюзов одновременно

OpenCode поддерживает одновременную настройку нескольких шлюзов. В `provider` можно добавить несколько отдельных provider:

```jsonc
{
  "provider": {
    "relay-a": {
      "npm": "@ai-sdk/anthropic",
      "options": {
        "baseURL": "https://relay-a.com/v1",
        "apiKey": "твой ключ провайдера A"
      },
      "models": {
        "claude-opus-4-5-20251101": {
          "name": "Opus 4.5 через провайдера A",
          "limit": {
            "context": 200000,
            "output": 64000
          }
        }
      }
    },
    "relay-b": {
      "npm": "@ai-sdk/anthropic",
      "options": {
        "baseURL": "https://relay-b.com/v1",
        "apiKey": "твой ключ провайдера B"
      },
      "models": {
        "claude-sonnet-4-5-20250514": {
          "name": "Sonnet 4.5 через провайдера B",
          "limit": {
            "context": 200000,
            "output": 64000
          }
        }
      }
    }
  }
}
```

После настройки в `/models` будут видны:
- `relay-a/claude-opus-4-5-20251101`
- `relay-b/claude-sonnet-4-5-20250514`

**Сценарии использования**:
- разные шлюзы отличаются ценой и скоростью, можно переключаться по необходимости;
- если один шлюз перестал работать, быстро перейти на другой;
- сравнивать результаты работы разных шлюзов.

## Дополнительные сведения: почему не рекомендуется менять `provider.anthropic`

Технически можно указать шлюз в `provider.anthropic`, но это не рекомендуется:

- исходная конфигурация `anthropic` также будет «заменена шлюзом» (сложнее вернуться к официальному сервису или сравнить конфигурации);
- при выполнении `opencode auth login` проще сохранить Key не в тот providerID (например, ошибочно в `anthropic`), что усложняет диагностику.

Отдельный providerID (например, `claudecode-relay` из этого урока) изолирует «конфигурацию шлюза» от «официальной конфигурации anthropic».
