## Основные понятия

### Что такое прокси

Прокси-сервер — это «перевалочный пункт». Ваш запрос сначала отправляется прокси, затем прокси пересылает его целевому серверу, а ответ возвращается тем же путём.

Прокси нужен во многих ситуациях:
- корпоративная сеть обращается к внешним ресурсам через шлюз
- в учебной сети действуют ограничения доступа
- для доступа к отдельным сервисам требуется специальный маршрут

### Как OpenCode использует прокси

OpenCode получает настройки прокси через **переменные окружения**. Нужно задать:

- `HTTP_PROXY`: адрес прокси для HTTP-запросов
- `HTTPS_PROXY`: адрес прокси для HTTPS-запросов

Формат: `http://代理地址:端口号`

После настройки OpenCode и большинство инструментов командной строки будут автоматически использовать прокси.

## Повторяйте за мной

### Шаг 0: проверьте сведения о прокси

Вам понадобятся два значения:
1. **Адрес прокси**: обычно `127.0.0.1` (локальный прокси) или адрес, предоставленный компанией
2. **Номер порта**: число, например `7890` или `8080`

::: tip 💡 Не знаете номер порта?
Откройте приложение прокси и найдите в разделе «Настройки» или «Параметры» пункт «Порт HTTP» или «Локальный порт прослушивания».

Если прокси предоставлен компанией или учебным заведением, обратитесь в ИТ-отдел.
:::

### Шаг 1: проверьте доступность прокси

<AdInArticle />

Сначала убедимся, что сам прокси работает.

Введите в терминале (замените адрес и порт на свои):

```bash
curl -x http://127.0.0.1:7890 -I https://httpbin.org/ip
```

**При успехе:**

```
HTTP/1.1 200 Connection established

HTTP/2 200
content-type: application/json
...
```

Появление `HTTP/2 200` означает, что прокси работает нормально.

**Ошибка 1: соединение отклонено**

```
curl: (7) Failed to connect to 127.0.0.1 port 7890: Connection refused
```

Причина: прокси не запущен или указан неверный порт. Убедитесь, что приложение прокси запущено и порт указан правильно.

**Ошибка 2: превышен тайм-аут**

```
curl: (28) Operation timed out
```

Причина: прокси работает неправильно или целевой адрес недоступен. Проверьте конфигурацию прокси.

---

### Шаг 2: задайте переменные окружения (временно)

Сначала задайте их временно, а после проверки запишите в файл конфигурации.

::: code-group

```bash [macOS / Linux]
export HTTP_PROXY=http://127.0.0.1:7890
export HTTPS_PROXY=http://127.0.0.1:7890
```

```powershell [Windows (PowerShell)]
$env:HTTP_PROXY = "http://127.0.0.1:7890"
$env:HTTPS_PROXY = "http://127.0.0.1:7890"
```

:::

::: warning ⚠️ Внимание
Замените `127.0.0.1:7890` на фактические адрес и порт прокси.
:::

**Проверьте успешность настройки:**

```bash
echo $HTTP_PROXY
```

Должно отобразиться заданное значение. В Windows используйте `$env:HTTP_PROXY`.

---

### Шаг 3: проверьте действие переменных окружения

Теперь выполните проверку без параметра `-x`, чтобы убедиться, что переменные окружения применяются автоматически:

```bash
curl -I https://httpbin.org/ip
```

Если возвращается `HTTP/2 200`, переменные окружения настроены правильно, и curl автоматически использовал прокси.

---

### Шаг 4: запишите настройки в файл (постоянное действие)

Временные настройки действуют только в текущем окне терминала. После записи в файл конфигурации они будут применяться при каждом запуске терминала.

::: code-group

```bash [macOS / Linux (zsh)]
# 编辑配置文件
nano ~/.zshrc

# 在文件末尾添加：
export HTTP_PROXY=http://127.0.0.1:7890
export HTTPS_PROXY=http://127.0.0.1:7890

# 保存退出（Ctrl+X → Y → Enter）
# 重新加载配置
source ~/.zshrc
```

```bash [macOS / Linux (bash)]
nano ~/.bashrc

# 在文件末尾添加：
export HTTP_PROXY=http://127.0.0.1:7890
export HTTPS_PROXY=http://127.0.0.1:7890

# 保存退出，重新加载
source ~/.bashrc
```

```powershell [Windows (永久设置)]
# 设置用户级环境变量
[Environment]::SetEnvironmentVariable("HTTP_PROXY", "http://127.0.0.1:7890", "User")
[Environment]::SetEnvironmentVariable("HTTPS_PROXY", "http://127.0.0.1:7890", "User")

# 重启 PowerShell 生效
```

:::

::: tip 💡 Как узнать, используется zsh или bash?
```bash
echo $SHELL
```
Если вывод содержит `zsh`, используется zsh; если `bash` — bash. В новых версиях macOS по умолчанию используется zsh.
:::

## Типичные проблемы

### Проблема 1: `Connection refused`

**Полный текст ошибки:**
```
curl: (7) Failed to connect to 127.0.0.1 port 7890: Connection refused
```

**Шаги диагностики:**

1. Запущено ли приложение прокси? Проверьте значок в панели задач или строке меню.
2. Верен ли номер порта? Проверьте его в настройках приложения прокси.
3. В некоторых приложениях нужно вручную включить «Разрешить подключения из локальной сети» или «Прокси HTTP».

---

### Проблема 2: `Operation timed out`

**Полный текст ошибки:**
```
curl: (28) Operation timed out after 30001 milliseconds
```

**Шаги диагностики:**

1. Нормально ли подключено приложение прокси? Проверьте его состояние.
2. Доступен ли целевой сервис? Проверьте другой адрес (например, https://httpbin.org).
3. Если используется удалённый прокси, проверьте сетевое подключение.

---

### Проблема 3: переменные окружения не применяются

**Симптом**: переменные заданы, но curl по-прежнему завершается по тайм-ауту

**Шаги диагностики:**

1. Убедитесь, что переменная задана: `echo $HTTP_PROXY`
2. Некоторым инструментам нужны переменные в обоих регистрах:
   ```bash
   export http_proxy=http://127.0.0.1:7890
   export https_proxy=http://127.0.0.1:7890
   export HTTP_PROXY=http://127.0.0.1:7890
   export HTTPS_PROXY=http://127.0.0.1:7890
   ```
3. После записи в файл конфигурации выполните `source` или откройте новый терминал.

---

### Проблема 4: через прокси проходят только некоторые запросы

**Симптом**: одни сайты открываются, а другие — нет

**Возможные причины:**
- проблема с правилами маршрутизации прокси
- некоторые адреса исключены из прокси

**Решение**: проверьте правила в приложении прокси или обратитесь к сетевому администратору.
