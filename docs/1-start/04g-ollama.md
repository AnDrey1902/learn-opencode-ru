# Подключение Ollama (локальные модели)

Ollama позволяет запускать локальные модели на собственном компьютере: **данные не покидают устройство, что подходит для конфиденциальной информации и секретных проектов**. API Key не нужен, возможна работа офлайн.

---

## Что вы сможете после урока

> Без преувеличений — только то, что можно сделать сразу

- Использовать OpenCode для обработки чувствительных данных полностью офлайн, не отправляя их с компьютера
- Установить Ollama и проверить его работу
- Выбрать и скачать локальную модель под своё оборудование
- Настроить локальную модель Ollama в OpenCode и провести первый диалог

## С какими трудностями вы столкнулись

> Если вы сталкиваетесь с этим, этот урок для вас

- На компьютере много чувствительных файлов (финансовые данные, сведения о клиентах, личная информация), и вы не хотите загружать их сторонним моделям
- Вы разрабатываете секретный проект, и код и документы **ни в коем случае не должны** покидать рабочий компьютер
- Вам важна строгая конфиденциальность данных: даже если поставщик обещает ничего не сохранять, вы не хотите отправлять данные с устройства
- Сеть ограничена, поэтому нужен офлайн-помощник ИИ
- Вводите `/connect` в поисках локального Ollama, но видите только **Ollama Cloud** и не знаете, что делать дальше

---

## Когда это пригодится

> Главное преимущество локальных моделей: **конфиденциальность прежде всего**

- Когда нужно:
  - обрабатывать чувствительные данные (финансовые отчёты, сведения о клиентах, личную информацию);
  - разрабатывать секретные проекты (коммерческая тайна, патентованный код, системы безопасности);
  - гарантировать, что данные не покинут устройство (принцип нулевого доверия, требования соответствия).

- И при этом не хочется:
  - загружать файлы с рабочего стола и содержимое Excel сторонним сервисам;
  - отправлять код проекта за пределы компьютера;
  - зависеть от сетевого подключения для работы с ИИ.

::: tip 💡 Локальные и облачные модели
| Сценарий | Локальная модель (Ollama) | Облачная модель |
|-----|------------------|---------|
| Обработка чувствительных данных Excel | ✅ Данные не покидают устройство | ❌ Требуется загрузка |
| Разработка секретного проекта | ✅ Код обрабатывается локально | ❌ Требуется загрузка |
| Повседневные задачи разработки | ⚠️ Возможности слабее | ✅ Возможности сильнее |
| Полностью офлайн | ✅ Поддерживается | ❌ Нужен интернет |
:::

## Основная идея

> Сначала разберём подход, а не команды

- **Главные преимущества локальных моделей: конфиденциальность и секретность**
  - Все данные обрабатываются на устройстве, ничего не отправляется сторонним серверам
  - Подходит для финансовых данных, сведений о клиентах, личной информации, коммерческой тайны, патентованного кода и т. д.
- `/connect` используется только для сохранения API key (поэтому вы видите Ollama Cloud); локальному Ollama key не нужен — настройте provider в `opencode.json`, чтобы выбрать его в `/models`
- Для локального запуска важнее всего **оперативная память/видеопамять**: чем больше модель, тем больше ресурсов она требует
- Новичкам не стоит сразу стремиться к 70B: сначала пройдите процесс на 7B/8B, затем обновляйтесь
- При выборе модели учитывайте:
  - **Размер (B)**: обычно большая модель мощнее
  - **Назначение**: для кода выбирайте `*-coder`, для общего диалога — `llama`/`qwen`/`gemma`

## Повторяйте за мной

> Двигайтесь шаг за шагом — будем считать, что ошибки неизбежны

### Шаг 1: установите Ollama

**Зачем**  
Нужна среда выполнения локальных моделей: она запускает сервис на компьютере, к которому сможет подключиться OpenCode.

::: code-group

```bash [macOS]
brew install ollama
```

```bash [Linux]
curl -fsSL https://ollama.com/install.sh | sh
```

```powershell [Windows]
# Скачиваем установщик с официального сайта
# https://ollama.com/download
```

:::

Проверьте установку:

```bash
ollama --version
```

**Вы должны увидеть** вывод номера версии (например, `ollama version x.y.z`).

### Шаг 2: выберите и скачайте модель под своё оборудование

**Зачем**  
Слишком большая модель будет долго скачиваться, медленно работать или вообще не поместится в оперативную память/видеопамять.

Запомните простое правило выбора (эмпирическое, достаточное для новичков):

- **3B–8B**: начальный/лёгкий уровень, работает даже на компьютере с 16 ГБ ОЗУ
- **14B**: заметно мощнее, обычно комфортнее с 16 ГБ видеопамяти или более чем 32 ГБ ОЗУ
- **27B–32B**: качественный локальный помощник, рекомендуется 24–32 ГБ видеопамяти или более 48 ГБ ОЗУ
- **70B/72B**: локальный «потолок» возможностей, обычно требуется 48 ГБ и более видеопамяти (либо смешанная выгрузка на несколько видеокарт/CPU, что заметно снижает скорость)

::: tip Размер скачивания ≠ объём при работе
Указанные на странице Ollama гигабайты — это «размер скачиваемого файла». Во время работы дополнительно используется KV cache (чем длиннее контекст, тем больше нужно памяти).

Рекомендуется оставить запас свободной оперативной памяти/видеопамяти в размере 1,2–1,5 от «размера скачивания».
:::

**Популярные модели (по назначению):**

- Общий диалог (лёгкая): `llama3.2:3b` (около 2,0 ГБ для скачивания)
- Общий диалог (мощнее): `llama3.1:8b` (около 4,9 ГБ для скачивания)
- Китайский язык/общие задачи: `qwen2.5:7b` (около 4,7 ГБ), `qwen2.5:14b` (около 9,0 ГБ)
- Программирование: `qwen2.5-coder:7b` (около 4,7 ГБ), `qwen2.5-coder:14b` (около 9,0 ГБ), `qwen2.5-coder:32b` (около 20 ГБ)
- Другие популярные: `gemma2:9b` (около 5,4 ГБ), `mistral:7b` (около 4,4 ГБ)

**Выбор по оборудованию (эмпирическая рекомендация):**

| Ваше оборудование | Рекомендуемый размер | Рекомендуемые модели (примеры) |
|---|---|---|
| MacBook (Apple Silicon), 16 ГБ объединённой памяти (например, M4 16 ГБ) | 3B–8B | `llama3.2:3b` / `llama3.1:8b` / `qwen2.5-coder:7b` |
| Дискретная видеокарта с 16 ГБ видеопамяти (например, NVIDIA/AMD с 16 ГБ VRAM) | 7B–14B | `qwen2.5-coder:14b` / `qwen2.5:14b` / `gemma2:9b` |
| Дискретная видеокарта с 24 ГБ видеопамяти | 14B–32B | `qwen2.5-coder:32b` / `qwen2.5:32b` / `gemma2:27b` |
| Дискретная видеокарта с 32 ГБ видеопамяти (например, RTX 5090 32 ГБ) | 32B | `qwen2.5-coder:32b` / `qwen2.5:32b` |
| Дискретная видеокарта с 48 ГБ и более видеопамяти | 70B/72B | `llama3.1:70b` / `qwen2.5:72b` |

::: warning «Сколько B может запустить 5090»
Важна не модель видеокарты, а объём **видеопамяти**.

Если у вашей 5090 24–32 ГБ видеопамяти, обычно лучше начать с моделей уровня 32B; для 70B/72B часто требуется 48 ГБ и более либо смешанная выгрузка на CPU (запустится, но будет медленно).
:::

Начните скачивание (выберите любой вариант; сначала рекомендуется пройти весь процесс):

```bash
# В приоритете код (рекомендуется)
ollama pull qwen2.5-coder:7b

# Обычные диалоги
ollama pull llama3.1:8b

# Легче
ollama pull llama3.2:3b
```

**Вы должны увидеть** процесс скачивания и сообщение об успехе вроде `pulling manifest ... success`.

### Шаг 3: запустите сервис Ollama

**Зачем**  
OpenCode связывается с Ollama через локальный HTTP-сервис.

Выполните в терминале:

```bash
ollama serve
```

**Вы должны увидеть** `Listening on 127.0.0.1:11434` (не закрывайте это окно терминала).

### Шаг 4: настройте «локального поставщика Ollama» в OpenCode (можно скопировать)

**Зачем**  
То, что в `/connect` вы видите только **Ollama Cloud**, нормально: `/connect` отвечает только за сохранение API key (в `~/.local/share/opencode/auth.json`).

Локальному Ollama key не нужен. Правильный способ — настроить provider в `opencode.json` и указать совместимый с OpenAI адрес Ollama.

**Куда записать конфигурацию? (рекомендуется выбрать один вариант)**

- Глобально: `~/.config/opencode/opencode.json` (для всех проектов)
- Для проекта: положите `opencode.json` в корень текущего проекта (только для этого проекта)

Если вы не уверены, какой путь читает OpenCode, выполните:

```bash
opencode debug paths
```

**Готовая конфигурация для копирования (локальный Ollama):**

```json
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "ollama": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Ollama (local)",
      "options": {
        "baseURL": "http://localhost:11434/v1"
      },
      "models": {
        "qwen2.5-coder:7b": { "name": "Qwen2.5 Coder 7B (local)" },
        "llama3.1:8b": { "name": "Llama 3.1 8B (local)" },
        "llama3.2:3b": { "name": "Llama 3.2 3B (local)" }
      }
    }
  }
}
```

::: tip Два момента, которые легко упустить
1. Рекомендуется, чтобы key в `models` (например, `qwen2.5-coder:7b`) совпадал с именем модели в `ollama pull`.
2. Эта конфигурация только «объявляет список доступных моделей» в OpenCode и не скачивает их; для скачивания по-прежнему нужен `ollama pull ...`.
:::

**Вы должны увидеть**: после сохранения конфигурации и перезапуска OpenCode в `/models` появятся модели в разделе `Ollama (local)` (проверим на следующем шаге).

### Шаг 5: перезапустите OpenCode, выберите локальную модель и отправьте первую фразу

**Зачем**  
OpenCode читает `opencode.json` при запуске, поэтому после изменения конфигурации обычно требуется перезапуск.

Откройте новый терминал:

```bash
opencode
```

Введите:

```
/models
```

Выберите скачанную и добавленную в конфигурацию модель, затем отправьте:

```
Привет! Расскажи о себе
```

**Вы должны увидеть**: модель начнёт выводить ответ (локальная модель может быть немного медленнее облачной).

## Зачем использовать локальные модели?

> Локальные и облачные модели: важно выбрать подходящий сценарий

### Два главных преимущества локальных моделей

**1. Защита конфиденциальности: данные не покидают устройство**

При использовании локальной модели все ваши данные (содержимое файлов, код и история диалогов) обрабатываются на компьютере и не отправляются сторонним серверам.

**Типичные сценарии:**
- обработка чувствительных данных Excel (финансовые отчёты, сведения о клиентах, расчётные листки и т. д.);
- анализ файлов и папок на компьютере (с личной информацией или коммерческой тайной);
- организация личных документов (номера удостоверений личности, банковские данные, медицинские записи и т. д.).

::: warning ⚠️ Почему это важно
Даже если поставщик большой языковой модели обещает «не сохранять ваши данные», они всё равно **передаются на его серверы**. В сферах со строгими требованиями соответствия (например, финансы, медицина и государственные учреждения) это может нарушать правила.
:::

**2. Секретность проекта: код никогда не покидает устройство**

При разработке секретного проекта локальная модель гарантирует, что код и документы всегда обрабатываются на вашем компьютере.

**Типичные сценарии:**
- разработка коммерчески секретных проектов (неопубликованные продукты, патентованные технологии);
- разработка систем безопасности (инструменты безопасности, шифровальные и защитные системы);
- проекты по заказу клиентов (подписано соглашение о конфиденциальности, код нельзя передавать вовне);
- внутренние корпоративные проекты (исходный код содержит служебную тайну).

::: tip 💡 Когда локальная модель необходима
Если подходит хотя бы один пункт, **настоятельно рекомендуется использовать локальную модель**:
- ✅ Для проекта требуется соглашение о конфиденциальности или соблюдение нормативов
- ✅ Код связан с патентованной технологией или коммерческой тайной
- ✅ Данные содержат личную информацию (удостоверения личности, банковские карты, медицинские записи)
- ✅ Данные принадлежат клиенту или партнёру (их нужно защищать)
- ✅ Политика безопасности компании запрещает загрузку данных во внешние сервисы
:::

### Ограничения локальных моделей

Локальные модели хорошо защищают конфиденциальность, но у них есть ограничения:

| Параметр | Локальная модель | Облачная модель |
|-----|---------|---------|
| **Конфиденциальность** | ⭐⭐⭐⭐⭐ Данные не покидают устройство | ⭐⭐ Данные нужно загружать |
| **Возможности модели** | ⭐⭐⭐ Относительно слабее | ⭐⭐⭐⭐⭐ Мощнее |
| **Скорость ответа** | ⭐⭐ Зависит от оборудования | ⭐⭐⭐⭐⭐ Выше |
| **Стоимость** | ⭐⭐⭐⭐⭐ Бесплатно (нужно оборудование) | ⭐⭐ Платно |
| **Требования к сети** | ⭐⭐⭐⭐⭐ Работает офлайн | ⭐ Нужен интернет |

::: tip 💡 Рекомендуемая стратегия
**Для большинства пользователей:**
- чувствительные данные и секретные проекты → локальная модель;
- повседневная разработка и обычные задачи → облачная модель (она мощнее).

**Гибридная стратегия:**
1. Сначала обработайте чувствительную часть локальной моделью
2. Затем при необходимости обработайте обычную часть облачной моделью
:::

## Типичные проблемы

> Здесь застревают 80% пользователей

| Симптом | Причина | Решение |
|-----|-----|-----|
| Симптом | Причина | Решение |
| В `/connect` есть только Ollama Cloud | `/connect` используется только для сохранения API key | Настройте `opencode.json` по шагу 4, затем выберите локальную модель через `/models` |
| В `/models` нет `Ollama (local)` | Неверный путь к конфигурации / ошибка в JSON / OpenCode не перезапущен | Выполните `opencode debug paths`, найдите каталог конфигурации, проверьте JSON и перезапустите OpenCode |
| `connection refused` | Сервис Ollama не запущен | Выполните `ollama serve`, затем снова откройте `/models` в OpenCode |
| Скачивание идёт медленно | Проблемы с сетью или медленное зеркало | Повторите попытку позже; сначала скачайте небольшую модель (3B/7B) |
| Сразу зависает/не хватает памяти | Модель слишком большая | Выберите модель уровнем меньше (например, 14B → 7B/8B; 32B → 14B) |
| Ответы очень медленные | Задействован CPU / не хватает ресурсов / первая загрузка | Закройте ресурсоёмкие приложения; попробуйте меньшую модель; медленная первая загрузка нормальна |
| Порт занят | Уже работает `ollama serve` | Не запускайте сервис повторно, достаточно одного процесса |

::: warning Важные замечания об Ollama
1. Перед каждым использованием OpenCode сначала запускайте `ollama serve`
2. Локальные модели слабее Claude и DeepSeek, поэтому могут плохо справляться со сложными задачами
3. Нагрев компьютера и сильный шум вентилятора — нормальное явление
:::
